# 连续任务控制器协议原型

**本目录只做模拟单测，不是游戏实测或云模型并发性能实测。** 不调用模型、不访问网络、不产生 API 费用、不读取或控制游戏。

## 原则
- 每角色最多一个未完成规划任务；全局 PlannerPool 默认最多 4 个执行线程、20 个已接纳任务。满额立即返回，不阻塞游戏 tick。未来需对云服务加入 token 限流、重试预算、超时和费用上限。
- tick 不等待 Future，旧计划在有效期内继续刷新短命令租约。模型返回、语义校验后才替换计划。
- 状态机：planning、executing、executing+planning、unsafe。
- 动作仅 move/stop，x/z∈[-1,1]，不允许模型决定接口、玩家身份或外部访问。
- 默认每 0.1 秒最多刷新一次 0.4 游戏秒租约；计划最长 5 现实秒，过期自动 stop。等待规划不意味着无限继续走。
- 状态陈旧 >2现实秒、死亡、健康下降 >=0.05、错误玩家或非法状态触发 stop 并锁存。恢复需调用方明确 resume，迟到旧规划因 generation 不匹配被丢弃。
- 请求超过5秒的规划结果不再采用，异常/无效结果不会变成动作。

## 对接真实游戏前必须处理
1. observed_at 必须是本地 monotonic 的“新状态到达时间”。不能每次读取同一旧文件就更新时间；需以 tickSeconds/文件变化确认新观察。
2. playerAlias/processId 只用于可信路由与可读记录，实际命令目标需来自确认的文件标识，不能由模型指定。
3. 游戏更新线程执行租约，卡帧时0.4游戏秒可超过0.4现实秒。它不是硬实时急停保证。生产需要进程独立看门狗、桥侧超时与帧率监控。
4. stop 命令需确认，控制循环/进程退出时应 finally 发送 stop。本文纯接口未写文件适配器，不可直接宣称真实安全闭环。
5. 当前健康检查不是完整碰撞/悬崖/敌人安全判断，连续移动仅限已验证平坦无害场景。
6. 20角色单测仅证明20个控制器不重复提交规划；不证明游戏能同时运行20角色，亦不证明4线程满足20角色的推理吞吐。

`cd qwen-lab/continuous && python -m unittest -v`

覆盖旧计划跨模拟延迟继续、计划到期、陈旧状态、受伤、迟到响应、非法动作、过旧规划、20角色各一请求、租约限制和全局队列非阻塞满额拒绝。延迟由未完成 Future 模拟，无真实模型推理。

## 追加：真实四角色世界中的单角色执行器验证（已完成）
在资源基准结束后，仅操作 LabBot1；其他三角色保持原地。没有运行 Qwen 或云模型，planner 使用本地 sleep 模拟延迟。读取实际文件 API，新 tick 才更新 freshness；有2格全局范围/0.75格垂直变化护栏，结束 stop 并确认。详见 live_test.py / live-results.json。

| 模拟规划延迟 | 实际总时长 | 正向续租次数 | 反向续租次数 | 控制器 stop 时点 | 新状态 tick 数 | 结束 stop 确认 |
|---|---:|---:|---:|---:|---:|---|
| 2秒 | 3.34秒 | 10 | 4 | 2.73秒 | 15 | 成功 |
| 5秒 | 6.37秒 | 15 | 0 | 3.03秒 | 29 | 成功 |
| 10秒 | 11.31秒 | 15 | 0 | 3.03秒 | 52 | 成功 |

2秒规划等待期间，角色已产生真实位移，新反向计划在2.02秒开始续租，实现“不因等待推理立即停车”。5/10秒等待超过旧计划3秒有效期时，控制器按设计停止，过迟结果未采用。此方案是“有效计划继续+超期安全停”，不是任何长度模型等待都无限前进。

三轮中 health 始终1，最大累计离起点1.26格。命令确认及新 tick 实际读取；未逐条强制等待每个续租确认，否则会阻塞实时控制。stop 后仍有微小物理位移，不能把确认等同于瞬间速度归零。没有故意制造真实受伤/死亡/陈旧状态，相关急停仍仅单测覆盖。

本测试只证明同一四角色世界中的一个真实角色可用连续执行器与模拟延迟planner工作，**不代表四个模型同时控制，更不代表16–20个模型玩家性能**。在本窗口没有模型调用费用。

## 追加：真实本地 Qwen + 双角色连续执行（可见画面）
local_two.py 启动一个 Qwen3.5-2B Q4_K_M CPU 服务（2线程，1 slot），两个角色各最多一个在途规划，统一单worker串行推理。使用真实位置/health精简观察，模型选forward/backward，代码映射z=±0.1，不改地形。没有云API。保留四角色可见画面，没有隐藏视图。

30秒控制窗口，总计33.61秒含加载/收尾。24次实际模型请求，LabBot1/2各12次，前后目标均输出对应枚举。单次服务请求推理耗时1.13–1.49秒，中位1.32秒（不含排队）；每角色决策开始间隔约2.6秒。模型RSS峰值2,077,468 KiB（1.98GiB）；本次未记录模型CPU秒，2线程配置不等于实际恒定占用2核。

两个角色均读到真实新tick、收到本控制器命令的状态确认，最终stop命令分别精确确认，health保持1。最大实际位移分别0.0832/0.0823格。没有触发安全锁存。

重要限制：可见软件渲染游戏只有0.113倍实时，30现实秒只推进约3.4游戏秒；新状态最大间隔年龄1.881秒，接近2秒陈旧阈值。每角色前后反转较频繁，且速度仅0.1，实际位移很小。此次证明“两角色共享本地模型→异步执行器→真实游戏确认和微小位移”的链路，不证明两个角色已完成有价值的生存任务，更不是实时流畅或16–20角色扩展证明。

续租总共发送143/135次，文件邮箱会覆盖旧命令；样本 ack_ours 仅说明当前确认来自本控制器，不能把发送次数视为逐条成功次数。未来应以游戏时间/动作完成条件保持高层任务，明确续租与新计划的版本确认，避免模型频率快于游戏更新时反复覆盖尚未执行的动作。

证据：local-two-results.json，local_two.py，local-two-server.log。所有请求完成后模型服务已退出，角色最终stop已确认。

## 追加：保持技能直到实际完成，再切换模型目标
离线16项测试通过后，运行 local_skills.py，保持四角色可见画面，仍只控制 LabBot1/2。异步准备下一目标，但当前技能保持到位移≥0.2格或1游戏秒预算或18现实秒期限；完成后stop确认才启动下一技能。速度0.25，短lease0.4游戏秒；health/新tick/2格/垂直边界守护。没有隐藏画面或热部署模组。

|---|---|---:|---|---:|
| LabBot1 | forward | 0.233格 | distance_complete | 6.55秒 |
| LabBot2 | forward | 0.242格 | distance_complete | 6.90秒 |

记录：local-skills-results.json（包含方向、前后位置、完整轨迹与所有续租）、local_skills.py、skill.py。

实测后根据静态审阅增加NaN/非法数值、负状态年龄、tick/墙钟回退拒绝，19/19离线测试通过；这部分增强仅离线测试，未重复真实游戏试验。请勿将安全单测覆盖说成实际故障注入验证。

## 追加：50角色世界、隐藏视角，仅2角色本地模型技能复测
无模型8/16/32/50基线结束后，在现有50角色进程中重跑相同 Qwen/2线程与技能阈值，仅给 LabBot1/2 发动作，其他48角色不控制。脚本 local_skills_50world.py，证据 local-skills-50world-results.json；前轮文件保留。

本实验仍只有2个角色接受本地Qwen规划，**不代表50个AI同时推理**。不从4次请求或单模型短测推算50角色稳定决策吞吐。

## 追加：50角色世界中8角色无模型独立活动
8个非Walter角色 LabBot1–8，前4先前后、后4先后前，各最多两技能。速度≤0.2，距离目标0.15格或0.7游戏秒预算，1格全局范围、health/air下降或陈旧即停。其他42角色只读对照。没有调用模型，也没有同时控制50人。

测试实际2.44秒完成，8个最终stop命令全部精确确认。每角色发9–12条命令，实际观察到7–10个独立命令确认；不把发送数等同执行数。

16个技能中14个末次观察距离≥0.15格；LabBot1/2后退仅0.135/0.130格，game_budget_complete，不是距离完成。八人前后z方向均反转，可见独立定向动作。最大离起点0.334格，health/air全程为1，无unsafe事件。

42对照角色未发任何命令，最大实际位移0.103格，health未变化。可见无指令时也会有物理漂移/碰撞，因此不把活动者的全部位移当作纯命令贡献；本短测不估计长期生存成功率。距离完成判断仍有状态离散采样的超时/距离同刻边界。

证据：eight_active.py、eight-active-results.json（每角色方向、轨迹、健康、空气、实际确认计数和42个对照结果）。
