# 食物情况与候选契约

只处理宿主提供的真实观察快照，不读取地形、实体集合或模型。`FoodSituationPlanner.Create` 校验角色/会话/观察/库存版本，输出确定候选 ID、证据引用、缺料、前提、风险与可执行标志。

默认执行器注册仅包含已有 EatInventory/GatherPlant/Search；能力 flags 不能把尚未集成的狩猎、拾取、制作、烹饪标为可执行。未来执行器真正接入后由宿主显式提供 `FoodExecutorRegistry`，不是由模型注册。静态配方不代表拥有材料，动物位置来自宿主视野快照而非全知扫描。输入是真实传感器可信边界，本纯层不能认证观察真实性。

`FoodSituationPrompt` 分别提供可执行候选与不可执行诊断事实（后者没有可选择 ID），包含实际健康和饥饿状态；Search 与已有食物路线并列提供，宿主不代替模型做方向选择。模型，返回严格 `{"candidate_id":"<本次ID或wait>"}`。schema和解析器均拒绝任意字段/诊断候选/无效ID；执行前仍必须原生重验证库存、目标和能力。解析允许慢推理完成后的原计划成员选择，但不刷新旧证据。超过三秒的执行输入需宿主以新观察重新规划或进行明确的重新绑定流程，不能直接执行旧候选。

测试使用合成可信快照，不证明原生狩猎、烹饪或制作已运行。

宿主不按饱食值 0.8 禁用动作：饥饿状态是模型决策信息，储粮/探索或等待由模型选择。保留真实生命、能力、证据和原生执行前置校验。提示最多展示16项执行候选、8项诊断，按动作种类轮询保留替代路线；最大5600字符并明确遗漏数量，schema和独立解析器均只接受本次展示的候选。字符预算不是实际token数保证，真实4B上下文仍需实测。
