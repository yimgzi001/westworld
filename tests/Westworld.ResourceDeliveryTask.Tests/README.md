# P4 任务领取、交付与恢复契约（未接原生宿主）

运行：`./work/dotnet/dotnet run --project tests/Westworld.ResourceDeliveryTask.Tests/ResourceDeliveryTask.Tests.csproj`。只链接独立纯文件，不构建/启动游戏。当前35项通过。

## 复用范围

- `ToolCallLedger`继续负责工具session/actor/sequence幂等，本模块不发工具。
- `ActorRegistry.Restore`继续要求原生身份重新绑定。
- `CognitionRunLedger`与`WorldCognitionScheduler.Checkpoint`已有独占运行锁、写盘及配对世界快照，不在本模块重造持久化服务。
- `LocalObservationMemory`继续存角色局部认识，任务账不得把隐藏全局事实自动广播给成员。

现有模块未提供多角色资源交付的认领/部分完成凭据账，因此新增`ResourceDeliveryTask`，不修改既有运行循环。

## 生命周期

1. 建立一个指定世界、任务、收件人、完整物品值、数量的任务。原生身份须由宿主验证。
2. Claim具有请求ID，相同请求重放返回同结果，冲突领取拒绝。目前不支持转让/租约超时，以免默认重新分配仍在执行的任务。
3. Prepare登记唯一交付ID和真实已获得来源批次ID、来源证据ID。宿主必须先把登记持久化，再尝试原生交付。
4. Accept只处理宿主验证过的原生回执，核对来源减少、发送者减少、接收者增加一致。实际量可以小于请求上限，形成部分交付，不擅自重发差额。重复回执不增加计数；来源批次连续计量，不能换ID凭空补满同一来源。
5. Capture搭配确切世界检查点身份。Restore仅恢复逻辑状态，默认禁止新写，不执行任何动作。
6. 宿主加载且验证配对世界/角色/原生回执后调用Reconcile。未决交付缺回执就保持阻塞；空列表不能抹掉未知效果。已确认的部分恢复可重复核对，不重复计量。

## 宿主集成义务和未证明范围

`ResourceDeliveryProof`是可信宿主输入，不是密码学证明，不能接受LLM自报。现有`NativeAcquisitionFact`只覆盖世界掉落物到角色，**尚没有双方库存转移的原生审计钩子**，不能把该拾取事件直接当本契约的交付凭据。必须先在真实容器/角色转移路径获得双方变更事实，再接入。

来源ID必须跨存档稳定，不能直接用重载后新对象重新生成的临时Guid；保存时需持久化映射。单任务只防自己重复计量，多个任务共享同一库存时，宿主还须在统一世界账上保留批次与原生事件的唯一分配，避免跨任务重复认领同一次转移。本模块没有原生锁、物品移动、全局库存预留或联网功能。

Capture只是JSON，不能保证和世界写盘原子。应复用原有checkpoint，并核对文件哈希/角色绑定；只把一个字符串传给Reconcile并不能证明磁盘与世界匹配。真实世界恢复、进程崩溃、双角色交付、交付失败/退回均待后续原生验证。

用例覆盖领取重复与冲突、实际部分交付、守恒失败、重复原生事件、来源批次断裂、未知交付禁止重试、恢复后证据对账、重复恢复/重复回执、错误世界/检查点、重复JSON键及无效数量。
