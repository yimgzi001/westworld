# ADR-001：SCAPI 单世界多智能体架构

状态：架构基线提案，2026-11-09。不是完成情况声明。实现前按下列门槛验证；每个完整开发/测试里程碑审查后推送cjh，所有后续测试在dot云电脑，禁止操作用户电脑上的Minecraft。

## 1. 产品目标与既有设计
运行一个持续的生存战争世界，让10–20个、进一步40–50个具有独立人格与记忆的AI自然活动、生存和交流；用户可进入观察互动；资源和模型费用可量化。当前仅证明原生单/双角色及部分动作接口，未证明50人。

以 docs/design 的14份目标设计为约束来源，不照搬Minecraft。继承：世界事实由引擎结算、角色认知隔离、人格/愿望/记忆连续性、动作不等于结果、来源审计、版本化实验与可恢复。球面世界、自由物理发明、复杂繁衍/遗传/跨代文明不是SCAPI当前已实现能力，本阶段只保留可扩展领域接口，先用原生身体与生存机制。

### 重要取舍：实时，而非锁步
旧《AI时间推进与调度设计》要求必要模型批次未齐便冻结整个世界；总览又要求启动后纯观察、不预置领导。不能悄悄称其与当前自然实时互动完全兼容。
- **当前实时生存模式**：游戏时钟继续，模型请求异步；有效既有技能继续执行。API延迟可能影响角色反应，必须记录，不能声称消除了公平差异。
- **未来研究锁步模式**：在一致边界冻结世界，等待必要决定，保持模拟时间公平；单独设计、测试和版本标识，不在首版同时实现两套时钟。
- 用户进入、授意任务或队长配置均记录为实验干预。纯观察研究可禁用干预；不将人为组织的成果称为自发社会演化。

## 2. 模块边界

| 模块 | 权限与职责 | 明确禁止 |
|---|---|---|
| GameHost + SCAPI adapter | 唯一世界权威；游戏线程快照、技能输入、物理/库存结算 | 模型线程直接改Entity/地形/背包 |
| Actor registry | 稳定actor_id、身体实体、生命周期、存档绑定 | 将actor等同本地分屏槽位 |
| Observation service | 眼睛/视距/遮挡、声音、本人身体/背包、已知地点 | 角色获取全图/别人记忆/未来事件 |
| Cognition runtime | 每人档案、情绪愿望、工作区、私有记忆检索 | 模型叙述直接变世界事实 |
| Decision scheduler | 公平轮转、每人一个在途主要决定、合并唤醒、供应商并发/退避 | 每条聊天都触发全员推理 |
| Skill executor | 有状态本地动作、有限计划、中断、进度与验收 | 一格一LLM，或无期限移动掩饰等待 |
| Social events | 真实发出/接收、承诺/任务状态、独立回应 | 默认强制服从、全知公共黑板 |
| Persistence + telemetry | 一致检查点、行动去重、费用/性能/证据记录 | 读日志等于获得角色知识 |

模型适配与网络I/O可放独立进程，使用共享连接/工作池，不需要每角色启动一份游戏或一份模型。具体部署边界先以故障隔离和测量为依据，不先引入复杂分布式服务。

## 3. 第一架构风险：角色与渲染解耦
当前 SubsystemPlayers.MaxPlayers=4；GamesWidget、TerrainChunk.HazeEnds及ComponentPlayer对GameWidget/Gui/Input的依赖，使“改成50”不成立。还需审计按玩家枚举的区块激活、天气、睡眠、实体生成、存档与死亡重生。

首个技术决策验证是：**一个世界、五个拥有正常生存组件的真实AI身体、最多一个人类视口，独立控制并存读档**。五个是跨越既有四人限制的判别点，不是性能目标。不能以简化动物实体冒充等价玩家。

优先设计actor控制/呈现接口，将GUI/相机与身体状态分离，保留上游原生生存结算。AI位置仍需激活必要区块；节省视口不等于免除地形/物理成本。Linux无窗口启动也不等于已有无GPU依赖：GLFW/OpenGL初始化需独立验证与解耦。

## 4. 决策与行动契约
服务器绑定 experiment/session/actor/decision/action/observation_version；模型只选有限动作与已知对象引用，不自行指定别人的身份。
流程：观察快照→私人上下文→异步模型→结构化候选→版本/时间/占用检查→游戏线程接收→技能执行→实际世界差量→个人可感知结果。
- accepted仅代表受理，completed也需区分成功、部分完成、失败、中断、取消。
- 重连先查询原action结果，不盲重发。每角色单身体主动作，辅助兼容性显式声明。
- 开始时及过程中复查实际条件。旧观察不保证目标仍在、库存仍有。
- 计划有步数、时长和可表达的中断条件。已有计划无法继续时停到合理状态并请求重规划，不由执行器偷偷发明新生活策略。
- 技能目录覆盖导航/转向、采集、拾取、库存/容器、制作、放置、进食/休息及交流，先核对SCAPI可实现范围。
- 本轮已证明挖完不等于拾取；Place的false可能是pending；所有物品产出、转移和消耗看原生变化，不看模型说“成功”。
- 生成脚本扩展单独设计权限、生命周期、资源与故障隔离，不作为首版核心循环，也不把解释器任意执行隐式接进游戏线程。

## 5. 自然动作与异步
本地技能按游戏tick持续运动、转向、等待原生挖掘挥动及处理路径。LLM决定“去已知位置取得材料”等有限意图，不决定每帧按键。
事件合并触发下一次思考：计划完成/受阻、局部危险、重要消息、角色主动回顾、最长思考间隔。推理期间继续仍有效计划；紧急反应只能依本人可感知信号和预声明的本地行为，不用全知信息。
衡量连续性是动作空闲/阻塞时间和进展，不是强迫角色永不停下；等待、休息和观察可以合理。

## 6. 人格、记忆与协作
每人拥有稳定人格倾向、短期工作区、目标与主观关系、长期记忆。记忆保留经历/听闻/推测/意图区分、来源、时间、置信和版本；世界审计日志不直接成为角色可检索记忆。变化可追溯，摘要不覆盖事实。

群体性格作为初始化分布/共享文化线索与以后交流形成的理解，不是强制统一意志。领导、三人小组或分工只能是可替换策略或明确初始设定；不得写死为社会规律。

可选合作机制是**有证据的任务/承诺账**：提出者、接收者、目标、认领、依赖、预期交付、实际验收、期限/阻塞、版本。账不是全体全知共享：成员只读本人实际收到/参与的条目，队长也只能从报告和观察得知进展。允许拒绝、误解和合作失败。

收件箱合并、任务完成/阻塞/危险才汇报、避免无信息增量回复。通信策略和调用预算是实验配置，不把减少聊天偷换成禁止自主交流。效率验证同时看token与实际交付，不只看消息数。

## 7. 状态、恢复与费用
检查点需协调原生世界、actor绑定、技能游标、个人记忆/目标、通信与行动去重状态。无法原子保存时采用可核对的检查点ID与恢复日志，恢复前校验；未知执行结果进入对账，不再发一次物品。
模型失败、游戏故障、主动暂停、正常重启分别记录。SCAPI吞异常的路径不能当成功。
逐请求记录供应商/模型版本、时延、普通输入/缓存输入/输出token、重试、费用及估算/实账标识；密钥只经私有配置，不进Git。预算策略需显式配置；本阶段不继承Minecraft凭据为另一项目的默认调用授权。

## 8. 整体验收路线
A. 架构契约+actor/视口解耦可行性：5个真实身体、一个视口、存读档、独立背包/生存/控制；不改人数常量冒充完成。
B. 一个完整个人闭环：局部发现资源→导航→采集→拾取→制作或生存用途→后续记忆影响下一决定；慢模型期间动作连续且能中断。固定响应回归与真实模型结果分别报告。
C. 2–4人实际协作：交流送达、独立接受/拒绝、材料交付与共享目标产物证据；多人竞争/重复消息/重启不复制物品。
D. 10/20/50活跃角色分阶段：聚集与分散区块两种负载，人类加入观察；每一级达到预先冻结窗口再升级，不拿空闲角色在线数充当活跃容量。
E. 长时生存及故障恢复：模型限流/离线、断连、世界重载、角色死亡等；保留失败和实际存活/物资/合作数据，不承诺文明必然出现。

每阶段产物：代码+配置模板+自动回归+原生验收脚本/证据摘要+运行说明+已知限制。开发/测试完成一阶段即审查并推cjh；原始存档、密钥、依赖二进制和私人数据不提交。当前独立smoke是回归资产，不是产品完成比例。

## 9. 性能指标与不确定性
测游戏tick p50/p95/p99、最忙CPU线程、RSS/托管堆及增长、激活区块并集、导航/感知时间、动作成功率/无进展时长、模型在途/排队/时延、每角色及每游戏小时token费用。
云模型+无AI视口预期主要压力转向CPU、区块与内存，但没有50人实测前不承诺硬件规格。一个人类视口仍有GPU成本。区块分散通常比人数本身更能放大负载，必须单列。

## 10. 当前交接边界
已核验历史：原生短移动/停止/重载、双角色隔离/局部第一命中、挖掘拾取放置的一次完整脚本链。未完成：正式actor层、五人无视口、模型自主闭环、长期人格记忆/合作、大规模压测。
最新动作证据见[交接报告](../research/2026-11-09-interaction-handoff.md)。架构后的下一次开发应从A的关键可行性判别开始，不继续无规划添加独立演示。
