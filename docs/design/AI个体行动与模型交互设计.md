# AI 个体行动与模型交互设计 v0.2

> 基于 Survivalcraft 的目标设计，尚不表示已实现。游戏复用范围、根本驱动力和运行额度以[设计总览](./AI部落文明模拟-设计草案.md)为准；专题中的新增机制按能力清单逐项接入，不要求先重建一套世界。

## 1. 目的与边界

本方案承接《AI 部落文明模拟：设计草案》和《AI 个体状态设计》。50 人各自持有独立的档案、记忆和短期工作区，共享一个由引擎计算事实的世界；模型按需调用。角色不联网，不单独移除预训练知识。用户设置初始条件后只观察，具体实现范围按游戏接入与验收结果界定。

核心契约：模型收到个人视角的信息，输出意图与候选心理变化；运行器依据固定机制安排行动并结算；世界变化经过个人感知后，才成为其后续思考材料。

本方案定义通用行动能力，不预设职业、每日生活脚本、合作义务或发展文明的任务。初始动作范围、数值与时限是实验条件，不能声称已经支持无限开放的现实世界。

## 2. 一次决策、一次请求、一次行动的区别

一次 API 请求产生一次模型响应。一次个人决策通常只需要一个请求，可以同时返回行动、记忆选择、目标调整与后续思考安排。显式回想或格式修复可能需要额外请求，均单独计费并限制轮次。

一次决策可以安排跨越一段模拟时间的行动或有限计划。走路、搬运、采集进度、身体消耗等由引擎推进，不为每个时间子步骤调用模型。计划的每一步仍需单独满足前提，不能把一段文字直接当成已经完成的行动。

## 3. 调用时具体传什么

游戏版首轮使用结构化的个人观察，在需要思考时发送 JSON 文本。感知适配器以人物眼睛位置与朝向为基准，在附近查询人物、掉落物和地形，再按感知范围、视野和遮挡过滤。结合已启用的照明、听觉与身体条件，输出人物能辨认的方向、距离和物品特征。转身或靠近可以取得新观察。人类的自由摄像头独立读取场景，模型的视角始终属于人物本人。

可从游戏的[人物视点](../../game/Survivalcraft/Component/ComponentCreatureModel.cs)、[附近实体查询](../../game/Survivalcraft/Subsystem/SubsystemBodies.cs)和[地形射线检测](../../game/Survivalcraft/Subsystem/SubsystemTerrain.cs)起步。查询结果先进入感知过滤，只有角色实际可辨认的内容进入输入。首轮以文字和对象引用表达可感知场景，是否增加第一人称图像留待需要视觉判断的能力另行验证。

| 输入部分 | 内容 | 不包含什么 |
| --- | --- | --- |
| 稳定规则与行动协议 | 个人视角、输出结构、允许的行动与参数、记忆和行动的权限边界 | 不要求建设文明，不规定具体价值选择 |
| 个人档案摘要 | 当前有效的性格倾向、偏好和认知约束 | 不直接暴露所有隐藏参数或他人档案 |
| 当前心理状态 | 情绪、愿望、关注、关系判断、未完成目标 | 不把本人判断当成客观事实 |
| 身体感受与可知能力 | 饥渴、疲劳、疼痛、可感知的动作限制、自己知道的操作经验 | 不直接告知潜伏疾病、精确病因或未感知的生理数值 |
| 当前观察 | 当前位置的可见环境、可辨识的人物和物品、可听消息、天气感受等 | 不给全地图、隐藏资源、他人内心与尚未结算的行动 |
| 可访问记忆 | 与当前线索有关的本人记述、可信程度与记忆标识 | 不给世界全量日志或已遗忘细节 |
| 近期过程 | 本人上次计划、最近行动反馈、已经收到的交流和当前行动进度 | 不把行动意图当成实际结果 |
| 可用表达与当前注意安排 | 稳定的动作目录、已知对象引用、本人设置的回顾条件 | 不根据隐藏事实生成会泄漏答案的“必定成功动作菜单” |

输入按认知预算控制长度。档案、感知、记忆、他人话语使用明确的不同部分，听到的一句话不具有修改系统协议的权限。传入日期、距离与物品数值时，要区分角色实际能够判断的量和观察者才知道的精确量。

实验标识、调用标识、个体身份、观察版本和真实模拟时刻由运行器绑定，不交给模型选择。模型使用的对象引用是已有个人观察或记忆中的引用，不赋予探测任意数据库编号的能力。

记得某地有某人，不代表现在仍能看见或远程定位他。移动可指向记得的地点或探索方向；接触与操作要在实际到达和重新感知后成立。

### 一份个人观察示例

下面是简化示例，字段名和引用用于说明信息来源。运行器保存实际输入与观察版本。

```json
{
  "body": ["有点饿", "还能走动"],
  "seen": [{"ref": "person_07", "description": "阿禾在前方几步，手里拿着一份食物"}],
  "heard": [{"from": "person_07", "text": "帮我找些木材，我可以分你一点吃的。"}],
  "remembered": ["昨天在溪边见过几棵树，不知道现在还有没有"],
  "current_task": "回营地"
}
```

对象引用用于校验人物可以指向谁或什么，执行时仍要确认接触条件。看见手中物品、听见愿意分食、实际收到食物分别来自可见观察、交流记录和交接结果。人物可见范围外的背包内容不在输入中，记忆中的地点也不会自动更新成现状。话语的送达过程见[交流与社会关系](./AI交流与社会关系设计.md#3-一句话怎样真正被别人收到)。

## 4. 模型具体返回什么

| 返回部分 | 必要内容 | 引擎如何使用 |
| --- | --- | --- |
| 意图摘要 | 当前想实现什么，简短理由，可关联已有目标 | 用于个人连续性与观察，不代表结果 |
| 当前行动 | 行动类别、目标引用、材料/工具、数量或努力程度、希望持续的时长或完成条件 | 进入动作验证与执行流程 |
| 后续计划 | 有限的后续步骤、依赖与停止条件，可为空 | 只有动作和条件均可执行时才形成计划；普通文字只作打算 |
| 交流内容 | 对谁、说什么、以何种可支持方式表达 | 转成有传播范围、时间和接收条件的世界事件 |
| 个人状态更新提案 | 愿望、关注、情绪或关系判断变化及本人依据 | 按《AI 个体状态设计》校验并版本化提交 |
| 记忆提案 | 选择保留或概括哪些可访问经历，类型、描述与来源 | 更新个人主观记忆，不改世界事实 |
| 下次思考安排 | 回顾时间、本人选择的可检测唤醒条件 | 由调度器检查范围后执行 |

通常只接受一个主要身体行动；允许哪些辅助行为同时发生，由事先声明的动作兼容性规则决定。例如慢走与短句交谈可以兼容，睡眠与主动制作工具不能兼容。不能一次提交多个互斥行动，获得多倍时间或体力。

模型提出的时间和数量是意图或上限，实际耗时、产出和消耗由世界决定。候选记忆可记录“我打算造工具”，不能把尚未发生的制造成功写成经历事实。

不要求完整内部推理；仅保存模型输出的意图、计划和简短解释。模型不能通过返回新属性直接修改体力、技能、物品数量、他人情绪或外部物理规则。

## 5. 有限计划如何减少调用

执行器可以维护有限的、参数明确的动作序列，例如前往已知水源、饮水、返回已知营地。每步包含目标、完成条件、可检测的中断条件及其使用的身体资源。

每个后续步骤先登记为待启动动作，与同刻准备完成的模型决定及动物动作一起进入[统一启动阶段](./AI时间推进与调度设计.md)，再检查实际条件；完成事件处理器不直接启动下一步或抢占资源。只能执行已经声明的动作；程序不会为了“完成大目标”临时替角色发明新策略。条件失效时停止、登记其明确给出的有限分支，或唤醒本人思考。前往未知区域可以表达为探索方向与持续时间，不暗中取得全图最优路径。

自然语言“直到安全”“有危险就换办法”只有在被转换为已支持的个人感知条件后才可自动执行。复杂新情况需要再次调用模型。计划长度、同一时刻可进行的回想与反思轮次有边界，防止零时间无限循环。

### 分层执行与向上反馈

游戏版首轮建议用三块 C# 职责实现。认知层先冻结个人观察、记忆与当前任务，再由 `IActorDecisionSource` 返回候选决定。固定测试决定与真实模型使用同一个认知校验入口，网络协议和宿主配置见[大模型适配层](../development/开发与验证.md#大模型适配层)。任务执行器接收已校验的计划，按步骤发出动作请求。游戏动作适配器调用游戏组件，返回动作状态、实际完成量与可感知反馈。世界调度器统一推进这三块所用的模拟时钟和事件，具体批次与结算见[时间与调度](./AI时间推进与调度设计.md)。

首轮任务执行器用步骤列表和状态机。每个人保存计划版本、当前步骤、正在运行的动作标识、已取得的进展、最后一次取得进展的模拟时刻和剩余重试次数。状态区分等待、执行中、受阻、成功、失败与取消。一个步骤在获准开始时发出一次，后续更新检查真实进展。成功后登记下一步，受阻时可以尝试计划许可的局部恢复，耗尽后把实际情况交回本人。取消后保留已发生的效果，迟到反馈按动作标识归档。恢复时用已保存的游标、进度和效果记录续跑。

当前 [ActorTaskExecutor](../../game/Survivalcraft/Westworld/Upper/ActorTaskExecutor.cs) 已在游戏模拟步中执行有限序列，每步等待原子动作结算，下一步最早在后续模拟步启动。`submit_plan` 接受最多 12 个已声明动作，步骤可指定实际效果的最低数量和有限重试。只在原生动作即时返回 `Busy` 且没有产生效果时重试；部分效果低于要求时保留已发生的效果并停止。`plan_craft` 将已知配方和现有材料展开为摆放与制造步骤，配方仍由游戏规则确认。取材、路由和重新规划由上层明确提出。[配方编排](../../game/Survivalcraft/Westworld/Upper/RecipeTaskComposer.cs)

分层职责由[设计总览第 4 节](./AI部落文明模拟-设计草案.md#4-每个人的分层自主执行)维护。层间任务包含所属人、来源目标/决定、方法版本、目标引用、数量、资源和搜索范围、前置条件、完成/停止条件、允许的局部分支、进度与取消关系。结果返回实际完成量、消耗、可感知失败、剩余任务及需要哪一层重新处理。

共享执行器可以绕开已感知障碍、重试有限次接近目标、展开本人已有的操作方法；不得为达标读取全图资源、临时改变交易或攻击策略。没有授权分支时报告受阻，由本人思考。无模型的规划器只在本人已知信息和已选目标内展开、排序与检查依赖；HTN、GOAP 或行为树是候选实现，不要求同时引入。

高层计划不能预占未来全部资源。技能步骤仍进入统一启动入口，由游戏真实的寻路、挖掘、掉落、拾取、配方和放置过程反馈完成。长任务保存步骤游标、工具与材料状态、已发生效果和方法版本；恢复后接着做，不再领一次产物。层间不是五套持续请求模型的循环。

## 6. 首版通用行动目录

| 能力组 | 例子 | 主要结算依据 |
| --- | --- | --- |
| 感知与寻找 | 观察、倾听、检查、沿方向搜索、追踪可见线索 | 位置、视野/遮挡、光照、噪声、注意与时间 |
| 移动与姿态 | 行走、奔跑、接近、离开、躲避、改变姿态 | 距离、地形、身体、负重和途中变化 |
| 取得与放置 | 采集、拿取、携带、放下、交出、伸手接取 | 可触及对象、实际存量、持有状态、容量与同时竞争 |
| 摄入与恢复 | 进食、饮水、休息、睡眠、寻找遮蔽 | 实际摄入、食物与水性质、耗时、代谢和环境 |
| 材料操作 | 敲击、切削、连接、加热、拆解、修补、搭建 | 材料、结构、工具、技能、能量和加工时间 |
| 交流与社会接触 | 讲话、提问、邀请、请求、提议、拒绝、警告、承诺、教学 | 可接收的表达与对方自己的回应；无自动服从结果 |
| 照料与共同活动 | 搬运或照料他人、提供食物、共同搬动物体 | 各人实际贡献、接触、资源、身体条件与过程 |
| 动物与对抗互动 | 接近动物、狩猎、威吓、推挤、阻挡、防卫 | 各方实际行动、身体、位置、工具、地形及动物行为 |
| 练习与尝试 | 重复已支持操作、尝试材料组合、比较结果 | 实际操作与反馈，不能直接声明掌握技能或发现定律 |
| 留下可见记录 | 刻划、摆放记号、在已支持载体上留下符号 | 材料、动作、时间与观看者自己能够理解的内容 |
| 生命延续相关互动 | 表达结伴意愿、回应、共同照料后代 | 已定义的双方意愿与身体条件；后续生育由人口与生理过程推进 |

这些是目标能力目录。游戏版先开放已适配、验证的观察、移动、挖掘、拾取、进食、休息、制作、放置与交流；饮水、照料、开放加工及繁衍等新增能力按版本启用。它们不是角色职业或每日任务。实际可执行范围受身体阶段和既有技能约束，但不能依据隐藏毒性等事实提前给出泄密的成功菜单。所有人的身体性别本身不规定职业或社会分工。

写字与个人记忆保存是两回事。记录进入世界必须有可观察载体，阅读者获得符号感知后根据自己的经验解释，不能通过旁白自动读懂全部含义。

“制造石斧”“建立部落”是可能由角色提出的目标，必须经实际动作完成；“直接获得石斧”“令他人归顺”“直接生出孩子”不是可执行的事实修改命令。

## 7. 行动的通用结构

原子动作是执行器可单独下达、检查进展和确认结果的操作。一个 `MoveTo` 可以经过许多物理帧，转身、走路和碰撞由游戏组件持续处理。目录按生存世界中人物可主动发起的操作划分，包含 28 项游戏动作和 3 项社会动作。观察摄像头、菜单以及创意模式的天气、时间和飞行开关由各自入口处理。

| 分组 | 动作 | 游戏行为如何归并 |
| --- | --- | --- |
| 移动与载具（8） | `MoveTo`、`FaceTowards`、`SetPosture`、`Jump`、`ClimbTo`、`Mount`、`Dismount`、`Steer` | 走路、游泳可用移动目标表达。姿态明确指定站立或蹲伏。骑乘和划船的持续控制归入 `Steer`。 |
| 生存（4） | `Wait`、`Eat`、`Sleep`、`WakeUp` | 等待按游戏时间计算。进食包括原生允许饮用的物品，由物品和身体规则处理。 |
| 物品与装备（6） | `PickUp`、`Drop`、`SelectItem`、`TransferItems`、`Equip`、`Unequip` | 选手持栏位与穿戴分别表达，箱子、炉子和制造格通过库存转移放取。 |
| 地形与工具（6） | `Dig`、`Place`、`Interact`、`UseItem`、`ConfigureBlock`、`ConfigureItem` | 门、开关、容器入口属于交互，取水、耕地、点火由持有物的规则处理。可编辑方块及物品按各自规则解释设置。 |
| 战斗与投掷（2） | `MeleeAttack`、`UseAimedItem` | 近战命中、远程瞄准、发射和投掷由游戏规则结算。 |
| 制造（2） | `Craft`、`BuildFurniture` | 按实际配方取产物并消耗材料。烧炼由装料、世界时间推进和取出产物组成。家具由锤子扫描连通的实际材料，可指定名称、分辨率、镜像、旋转和位移，然后按游戏规则消耗材料及耐久并产出家具。 |
| 交流与交接（3） | `Speak`、`OfferItem`、`RespondToOffer` | 发声按可听条件送达，提出交接与对方回应分别记录，由现场状态决定能否完成转移。 |

`AtomicActionCatalog.Definitions` 给执行器提供全部动作名、类别和 C# 参数类型。每个受控角色绑定一个 `AtomicActions`，用 `GetCapabilities()` 查询其组件能执行的动作类型。游戏更新线程调用 `Start` 或 `Cancel`，持续动作由游戏模拟步推进。调用时再次检查身体、目标、距离和资源。`AtomicActionRun.Result` 提供状态、失败原因和实际影响数量，发起交接时还返回提议标识。模型侧只应收到个人获准的目标引用及可选动作，游戏实体和库存引用由可信代码解析。见 [C# 目录](../../game/Survivalcraft/Westworld/Actions/AtomicActionCatalog.cs)和[当前状态](../development/当前状态.md)。

`MoveTo` 接收个人已知且获准的坐标，用原生寻路组件的直接移动或角色自身的步行、游泳控制，以实际进入目标范围确认成功。`PickUp` 检查接触距离、目标余量和容量，并报告实际转移量。`Eat` 复用原生营养、容器转换和身体规则。睡眠、穿戴和进食仍要求相应的游戏组件，后续独立人物模板需要提供这些组件或兼容实现。交流方式和交接前提见[交流与社会关系](./AI交流与社会关系设计.md#3-一句话怎样真正被别人收到)。

`ClimbTo.Height` 使用脚底的世界 Y 坐标，目标梯段需连续。`Steer` 的转向和油门在 −1 至 1 之间，按游戏时间控制当前载具。配置支持告示牌文字、颜色和链接，开关、按钮、电池、活塞、延迟门、真值表、存储器，以及弓、弩、火枪的装填和弩上弦。方块或物品的类型决定可用字段。`ConfigureBlock` 和 `ConfigureItem` 都能重命名已有家具设计，原版规则下，同设计的放置副本和物品副本共用名称。

### 只读能力

查配方、看库存或读取环境由独立查询返回数据快照，无需占用原子动作槽。查询以游戏线程当前状态为准。执行器用查询结果准备动作，实际执行时重新校验库存、位置和目标版本。

| 查询面 | 接口 | 返回 |
| --- | --- | --- |
| 原版图鉴 | `FindItems`、`ReadItem`、`FindCreatures` | 物品类型、名称、公开属性与生物模板摘要。分页搜索使用原版登记的条目。 |
| 原版配方簿 | `FindRecipes` | 可按产物或原料查找。返回格子摆法、每批产量、副产物、个人制造格／工作台／炉子分类，以及原版登记的等级和热量要求。现场才生成的动态配方由制造格预览匹配。 |
| 自身与装备 | `ReadSelf`、`ReadInventory`、`ReadEquipment` | 自身位置、朝向、身体状态、手持栏位、背包堆叠与穿戴层。 |
| 容器与制造设施 | `ReadStorage` | 可达容器的库存、当前角色的工作台配方预览，或炉子的进度、燃料时间和热量。 |
| 局部观察 | `LookAhead`、`FindVisibleObjects`、`ReadSign`、`ReadEnvironment` | 视线命中、前方视野内的实体与掉落物、可读告示牌及所在处的光照、降水和身体环境。范围和遮挡在游戏中校验。 |
| 物品和电路设置 | `ReadBlockSettings`、`ReadItemSettings` | 可接触方块与本人持有物的当前配置，包括电路数据和武器装填状态。 |

### 向上调用

[ActorTools](../../game/Survivalcraft/Westworld/Upper/ActorTools.cs) 是按角色绑定的 JSON 工具入口。`DescribeToolsJson()` 提供该角色支持的原子动作与查询、任务工具的参数结构，`InvokeJson(name, arguments)` 在游戏更新线程调用。一个具备全部原生组件的角色可发现 31 个动作工具与 21 个上层工具。`observe` 合并视线和可见对象查询，现场返回值只含可序列化快照与个人引用。工具接入模型传输前，由宿主将模型调用排入正确的模拟阶段。

个人知识默认只开放已获准的条目。宿主可授予图鉴和配方，也可按实验配置启用公开原版图鉴；读到实际可访问的库存会记录其中的物品。已知配方以个人引用传给 `plan_craft`。配方预览来自当前实际制造格，和人物已学知识分别处理。[个人知识](../../game/Survivalcraft/Westworld/Upper/ActorKnowledge.cs)

`observe` 为当前角色能看到的物体和可访问的设施发出不透明引用。连续观察的同一对象沿用引用，失去观察或目标变化后重新校验。地形沿用原生格坐标、方块值和面标识，同一格在两次观察间换回同值时沿用原标识。地图最多记住 128 个已到达位置或实际看到的地标，保留最后观察时间；历史地点可用于移动。探索时可以按当前朝向给相对角度，再前进 1 至 4 格。人物的现有知识、地图与现场引用存于运行内存。数据任务支持动作之间的宿主检查点，范围见[存档恢复](./AI存档恢复与历史回放设计.md#1-要保存的是一段可继续的过程)。弱光、注意和认错等更完整的感知规则按对应专题推进。[观察与地图记忆](../../game/Survivalcraft/Westworld/Upper/ActorWorldMemory.cs)

#### 数据计划与局部恢复

`submit_plan` 仍接收 1–12 个步骤。每步有 `tool`、`arguments`，可给出 `minimum_affected`、`retries`（0–2）、`item_from_step`、`next` 和 `fallback`。成功默认前进一格；`next` 可跳到后面的零基步骤，也可用步骤数结束。预先声明的 `fallback` 用 `step` 和 `failure` 指定下一步，失败码匹配且该次没有记录到数量效果时才采用；已经发生的移动和其他可见效果保留。可恢复的组合限于 `MoveTo` 的 `blocked`、`timed_out`、`movement_interrupted`，`PickUp` 的 `target_changed`、`out_of_reach`、`blocked`、`inventory_full`，以及 `Eat` 的 `target_changed`、`insufficient_items`、`inventory_full`。所有跳转向前，普通成功路径可用 `next` 越过仅供恢复的步骤。即时 `Busy` 可按预算重试；移动受阻或超时可向同一目标重新尝试。数量不足会结束任务并保留真实完成量。

例如「走近已知食物 → 拾取 → 吃一份」。如果拾取在步骤 1，进食用 `{"tool":"act_Eat","arguments":{"count":1},"item_from_step":1,"minimum_affected":1}`。执行器在进食时从拾取的入库记录中选出当前仍匹配且数量足够的单个栏位。每个拾取输出最多绑定一次，期间只能执行移动、等待等不会由计划修改背包的步骤。原生同值物品按堆叠处理；没有可用记录时向本人报告物品不足。原版身体规则继续负责进食效果。任务状态提供任务 ID、版本、当前步骤、尝试次数和实际结果。

[任务启动器](../../game/Survivalcraft/Westworld/Upper/ActorTaskScheduler.cs)先观察上一轮动作结果，再轮转同一游戏更新步内的可启动任务。新的步骤开始时重新核验前提。这个启动入口覆盖已绑定的角色任务，完整的思考批次、动物行动及资源竞争契约由[时间与调度](./AI时间推进与调度设计.md)维护。配方编排也经过同一执行器。

每个动作定义：需要哪些输入；目标怎样寻址；开始前提；身体/工具占用；启动与持续成本；过程更新；完成或部分完成条件；中断条件；可能形成的观察；涉及资源的竞争与转移规则。

资源采用明确单位并记录去向。工具耐久、疲劳、伤势、资源余量等在实际过程中更新。达到目标数量、达到时间上限、目标失去接触或本人选择停止，都可以结束动作。

同一时刻的状态、随机过程和竞争规则使用固定版本。物品保管与现实中是否能拿到属于物理状态；所有权、礼物和债务属于角色可能形成的社会理解，不能偷偷写成强制共享或强制交换的世界定律。

## 8. 程序怎样判断结果

1. **协议检查**：能否解析、动作是否支持、参数是否完整、对象引用是否来自允许范围、决策是否重复或过期。
2. **开始检查**：到了实际开始时刻，再检查身体、位置、工具、目标状态和互斥行动。模型思考之后环境仍可能变化，不能只看旧观察保证成功。
3. **接受并安排**：符合协议的意图进入行动生命周期；只登记已开始或待开始事项，不提前发放产物。
4. **过程结算**：时间推进时计算移动、消耗、加工、竞争、天气和身体变化；到中断点停止，已付出的成本保留。
5. **完成结算**：决定全部完成、部分完成、无收获、失败、被打断或主动取消，记录真实状态差量。
6. **事务提交**：把状态、资源收支、事件和行动消费标记一起保存，避免响应重放或重启导致重复采集。
7. **个人反馈**：通过感知机制生成每个人可知的后果，进入其短期工作区和后续思考。

判断遵循因果与资源约束，不统一使用一个“成功率”骰子。确定性的条件直接计算；不确定的搜寻、操作失误或动物行动等才使用已声明的随机模型，记录种子状态与实际随机结果。

引擎不能先决定剧情“需要一次失败”再倒推原因。随机模型、操作熟练度和身体更新仍是简化假设，需要通过独立场景核查一致性。

## 9. 区分技术错误、实际失败与模型边界

| 情形 | 处理 | 是否消耗模拟中的行动时间 |
| --- | --- | --- |
| 无法解析、缺字段、未知协议动作、越过角色数据权限、重复/错误版本 | 不进入世界；有限格式修复或暂停，计入 API 用量 | 不因接口故障惩罚角色 |
| 明确的有效尝试，但目标不在当前位置、材料不足、超过搬运能力等 | 依据尝试怎样发生及本人可感知的条件，产生合理的行动反馈 | 按实际移动、检查、伸手或用力的过程计算，不统一收取虚构惩罚 |
| 动作合法开始，执行中目标移动、资源耗尽、天气或伤势改变条件 | 部分完成、被打断或失败；只保留实际发生的收支 | 已发生的时间和体力消耗保留 |
| 当前待执行步骤或正在推进的过程依赖未建模的关键作用，后果无法表达 | 在越过能力边界前的最后一致提交边界保存并暂停整个世界；扩充机制属于新版本实验 | 已结算的准备和尝试成本保留；未表达部分不编造耗时、成功或失败 |

普通失败的内部原因不一定全部告诉角色。盲目操作不能变成零成本探测隐藏状态的工具：反馈只包含实际接触与可感知后果，不通过即时错误消息泄露资源、毒性或他人的隐秘状态。

单纯提出假设、谈论新技术或保留未来目标，不触发能力边界暂停；它们仍须遵守表达、记忆与交流协议。可以表达的独立准备步骤照常执行，未知的后续步骤只作未编译打算，待本人将它选为实际行动时再按协议和能力检查。不得偷偷删掉关键作用，再把剩余动作标成整个目标完成；也不能为了避免暂停循环要求模型改选另一种生活策略。

边界记录包含触发动作/过程、缺失作用、模拟时刻与阶段、最后一致版本、已完成部分和未覆盖范围。地图越界按世界专题处理。边界暂停不同于预算暂停，单纯补额度或点击继续不能越过；保留原实验，新增机制只在有来源的新版本分支中验证。未知协议动作仍按技术错误作有限修复或暂停；通用动作与属性扩大组合空间，但不能保证任意自然语言发明都可执行。

## 10. 多人如何互动

**讲话**：输出说什么及对象/方式；引擎计算是否在范围内、何时送达、能听到什么。讲话内容可以包括请求、谎言或承诺，但不能直接改写对方判断。对方在自己的后续思考中选择回应。睡眠、距离和噪声等影响接收。

**交接物品**：表达赠予不代表对方已经接下。明确区分提出交接、物品仍由谁持有、另一人伸手接取、最终转移或放在地面。放在地面后是否被他人拿走，由实际行动决定。接收意愿不是所有物理转移的强制前提；争夺作为对抗过程结算，不把默认产权制度写入物理。

**共同劳动**：共同目标和口头承诺不自动产生贡献。每个人提交具体动作，只有实际重叠的出力、工具和时间参与结算。未合作、退出或违约可以发生，社会后果由其他人解释。

**争夺与伤害**：只依据当时各方已提交动作、实际接触、工具与身体条件结算。若本人感知到新的威胁且需要反应，安排新的思考或执行先前明确设定的有限反应，不让引擎临时替其决定性格与策略。

**结伴与繁衍**：双方意愿由各自决定；出生由独立的抽象生理与人口过程计算，经历所需模拟时间，不因一段对话立即生成后代。后代拥有独立档案与经历，不继承父母的整份记忆。

## 11. 时间与版本

调度的进一步阶段约定及认知准备完成机制见 [AI 时间推进与调度设计](./AI时间推进与调度设计.md)。默认使用正的模拟思考耗时，网络延迟不替代认知耗时。

同一决策时点使用冻结状态生成各人的局部观察，模型请求可以有限并发。API 在现实中的等待不消耗模拟时间。全部对应意图返回后，登记它们在模拟中的开始条件与时点，而不是让先返回者先采集。

若认知模型规定思考需要模拟时间，则根据预先声明的认知参数安排准备完成时点；其他过程在模拟时间中照常推进。到实际行动开始时重新检查前提。未采用思考耗时的简化实验必须明确标记，但交流与动作仍需有正的时间成本，不能无限零时间交谈。

动作生命周期区分提议、已接受、等待开始、进行中、完成/部分完成/失败/中断/取消。决策提交、动作开始、阶段进度和完成可各有事务，使用行动标识及阶段序号保证每个效果只发生一次。长动作不能被误当成一个跨数小时保持打开的数据库事务。

世界快照版本、个人状态版本与决策序号分别保存。观察之后发生正常时间推进，不自动令整个响应失效；行动在实际开始时检查新条件。已经被取消或取代的决策、重复提交，以及基于旧个人状态而不能合并的更新，才按明确规则拒绝或重新安排思考。不同个人的独立决策不能因另一个人的无关状态提交而一律失效。

本人在睡眠、失能或死亡后的可行动能力由世界决定。死亡或失能发生在原计划执行前，不能继续提交已经失效的身体行动。过期响应和迟到结果保存到审计，不自动应用到新版本个人状态。

## 12. 返回给角色与观察者的两种结果

角色反馈包括：动作当前状态、自己的可感知身体变化、实际知道的获得物或失去物、眼前变化、听到的话、可以察觉的中断原因及可引用的观察编号。不显示未暴露的病因、其他人私有心理、隐藏存量或随机数。

观察者记录更完整：世界版本、行动阶段、参与者、前提检查、状态与资源差量、随机结果、实际耗时、技术错误和模型能力边界。角色不能通过记忆检索或动作错误消息读取这份全局结果。

记忆中可以留下“我没找到果实”，不应由引擎自动告诉本人“另一个人在你来之前全部采走了”，除非他实际看见或听说。行动结束也不自动要求全部经历永久记住；后续按本人记忆选择处理。

## 13. 完整示例：两个人采集同一处果实

这是虚构设计示例。观察者知道某处有 8 个可采果实；阿木与阿禾只能看到各自位置所能辨认的情况，不一定知道精确数量。

阿木本次输入包含：本人有些饿、手边空间足够、正在果丛旁、看见一些果实、记得此前来过、阿禾也在附近。模型选择：在此采集，最多拿 5 个，持续不超过约定时限；可见果实耗尽或接触不到时停止。没有输出“我已获得 5 个”。阿禾同时独立决定采集最多 5 个。

引擎在实际开始和每段采集进度检查两人的位置、能力、果实和存放条件，按固定的时间与竞争模型扣减同一份资源。相同条件的同时竞争不得用 API 返回顺序或固定个体编号分配；必要时使用带种子的平局处理，不把平均分享规定为社会制度。

某次运行可以得到阿木 5 个、阿禾 3 个的结果；这是示例结果，不是固定分配策略。世界资源减少 8 个，两人实际持有物总共增加 8 个，各自承担真实时间和体力消耗。

阿禾的反馈可以是“你采到了 3 个，眼前已找不到可采果实；阿木刚才也在采集”，不能直接加入“阿木抢走了属于你的 2 个”。是否不满、是否认为不公、是否提议轮流，是阿禾之后自己的解释与选择。

只有实际吃下果实才影响相应摄入。提案、取得物品与摄入是不同动作和状态变化，不能重复计算收益。

## 14. 设计验收重点

首先验证：同一份资源不会被重复取得；各动作消耗模拟时间并占用相容的身体能力；局部反馈不泄露全知信息；自然语言不能直接改世界；对方必须自己回应；部分完成与中断保留真实收支；计划失效不由执行器临时代作重大选择；身体/技能与心理更新分离；重启与重复响应不重复产生效果；未实现的物理过程被明确标出。

此设计能够约束执行的一致性，但行动目录、过程近似、调度和竞争规则仍会影响实验结果。首个世界支持哪些作用、每种动作的时间/资源模型和并行动作兼容性，要在正式启动前冻结并保存为规则版本。数值与具体单位由后续实现计划给出，不要求用户逐个编写生活事件。
