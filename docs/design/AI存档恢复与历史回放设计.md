# AI 存档、恢复与历史回放设计 v0.2

> 基于 Survivalcraft 的目标设计，尚不表示已实现。游戏复用范围、根本驱动力和运行额度以[设计总览](./AI部落文明模拟-设计草案.md)为准；专题中的新增机制按能力清单逐项接入，不要求先重建一套世界。

## 1. 要保存的是一段可继续的过程

游戏版复用原生世界保存，新增 AI 状态、计划与请求账必须与游戏状态恢复到同一边界。原生 `Project.xml`、地形文件与新增存储各自写入。完整模拟应以暂停推进后的共同检查点、完成清单和原子发布入口组织；若采用提交日志，则验证其能恢复对应方块、实体和 AI 状态。下文的“同事务”是共同效果不可拆开的目标，不能仅因新增数据库用了事务就宣称游戏文件也满足。


当前西部世界的普通存档会在同一帧保存模拟时钟、人物认知、任务游标、已结算步骤和宿主手动暂停标记，并恢复首版人物可用的持续动作。地形区域文件和请求账本沿用各自的持久化入口。宿主另有在动作之间发布的 `.scworld` 检查点，用于独立的归档恢复流程。具体操作和适用边界见[普通存档恢复](../development/开发与验证.md#西部世界普通存档恢复)及[异步检查点](../development/开发与验证.md#异步检查点与跨进程恢复)。

新模式的运动锚点、本人体感守卫基线、触发后的向前分支，以及移动恢复等待的剩余时间和本人眩晕状态也随保存恢复。保存不能把已触发条件改回未触发，不能因重载让身体提前恢复，不能重放已完成移动或伤害；旧网络回包不得用触发前的授权覆盖后续分支。当前接口和专门验证入口见[通用感知与运动执行](../development/开发与验证.md#通用感知与运动执行)。

存档不只包含“现在有多少食物、谁在什么位置”。它必须同时保留世界、个人心理、短期观察、正在发生的过程、未来事件、随机过程、待处理的个人回合和技术调用状态。

每个安全结算阶段均持久化，内存用于缓存和计算。重启复用已提交的待处理进度与响应。历史模式可另存快照以加快历史查询。

## 2. 保存内容清单

| 范围 | 必须保存的内容 |
| --- | --- |
| 实验身份 | 实验/分支标识、初始状态、规则/参数/单位/模型配置版本、数据模式与运行器版本、来源实验与锚点 |
| 世界状态 | 地形、环境、天气、资源、动植物、物品组成/位置/容器关系、真实库存及实体版本 |
| 身体与生命周期 | 消化与储备、体水、睡眠、伤病、成长、孕程、泌乳、生命/意识、已积分时刻与危险量阈值 |
| 个人状态 | 档案、愿望、情绪、关系、技能、承诺/规范/认同、所有修订与当前可访问状态 |
| 记忆和短期工作区 | 长期条目、遗忘/概括状态、短期缓冲、最近接收、已读/待回顾情况、检索所需实际数据 |
| 行动和自然过程 | 真实开始时间、最后结算时刻、材料已投入量、部分成果、剩余步骤、进度、兼容状态与取消原因 |
| 交流 | 已实际发出片段、尚未发出进度、各人真实接收、待送达事项和已处理标识 |
| 调度 | 模拟时间、同刻阶段游标、待处理事件、待启动动作及来源/去重键/最早开始时点、计划步骤游标、有效序号、注意订阅、回顾时点、取消与版本标记 |
| 随机过程 | 流标识、算法/版本、内部状态、事件稳定采样键、已抽取阈值、累计危险量和过程驱动 |
| 认知 | 各人精确输入、观察版本、决策序号、已返回候选及与原任务的交接关系 |
| 认知循环 | 个人认识与局部 revision、关切、目标/意图状态、方法签名、预期/实际进展窗口、事件消费游标、待重评原因、认知提交组采用结果及任务依赖 |
| API 和预算 | 逻辑调用及各尝试状态、发送意图、原始完整响应、校验结果、最终候选、用量、预留/估算/未知负债 |
| 观察与恢复辅助 | 提交序号、效果去重记录和备份清单。观察流、历史事件、结构化变化和日报快照按启用的模式保存 |

“完整输入”包含实际送入模型的系统/角色约束、个人上下文、记忆检索结果、工具协议、模型参数和有限工具回合，不只保存可在未来重新渲染的提示模板。API 密钥、认证头及与实验无关的宿主信息不进入存档；恢复调用时从外部私有配置取得认证。

[认知循环设计](AI认知循环与目标调整设计.md#6-输出校验与认知行动分别提交)允许合法认识提交而动作被拒。各认知组、动作请求和实际效果有独立去重身份及显式依赖，其采用状态必须与共同检查点一致恢复。恢复后不重新判断已经采用过的回包，不重复追加记忆、方法失败次数或费用。旧认知格式保留原实验配置；切换框架从保留锚点建新分支并显式迁移，不能用“升级”悄悄改变同一实验的行为机制。

已使用的向量、索引配置及稳定排序条件若影响检索，也应保留。可重建的索引与缓存可以重建，但只从该时点个人可访问的资料重建；不为恢复偷偷补一次模型摘要或让已遗忘细节回流。既有待完成决定直接使用保存的精确输入，不因索引重建换上下文。

## 3. 用什么标识确定“同一件事”

模拟时间不足以唯一标识状态：同一秒内可能先结算物理，再安装决定，API 技术记录也能变化。建议至少区分：

| 标识 | 作用 |
| --- | --- |
| experiment_id | 区分实验与分支，不混入别的世界 |
| world_version、sim_time、phase_cursor | 定位模拟中的已提交状态及同刻处理阶段 |
| storage_revision | 所有持久提交的递增序号，技术状态变化也递增 |
| decision_id | 标识一次个人逻辑决定 |
| call_id | 标识决定中的一次模型/工具服务回合，或独立的摘要、报告等服务请求 |
| attempt_id | 标识对外的一次实际请求尝试，重试另记 |
| action_id、process_id、effect_key | 标识实际动作、持续过程及一次性效果 |
| runner_epoch | 标识当前运行器所有权，拒绝旧任务的越权提交 |

角色只看见其可感知的世界，不因 API 状态改动看到一次新世界事件。界面同时使用世界版本和技术游标；随机数、日期或响应内容的哈希不能单独代替业务标识。不同人同样说一句话、同一人两次真实取水，都是不同事件，不能按文字内容去重。

## 4. 一次结算怎样原子保存

在最近已持久化版本上计算候选变化，随后通过统一持久化入口，在一个短事务内完成：

1. 检查当前运行器 epoch、预期世界/个人版本、阶段游标及该阶段是否已提交。
2. 联合校验本阶段的资源竞争、库存、身体约束和对象关联。
3. 写入本阶段全部状态差量、资源账、个人更新、事件队列和随机过程新状态。
4. 同时写入结构化历史、效果标识、阶段完成记录、新版本及待推送观察记录。
5. 提交成功后才替换运行内存、发布结果并进入下一阶段。

同一资源竞争和相互依赖的身体/行动变化必须联合提交，不把 50 人随意拆成先来先写的交易。阶段内约束不能只靠事后日志补救。计算可以在事务外进行，但提交时必须重新检查预期版本，过期计算不得覆盖新状态。

资源申报、候选分配和未提交效果是可重算的计算区，不是三次独立事实提交。按[世界联合结算契约](./AI世界状态与自然演化设计.md)得到一致结果后，将实际分配依据、实际消耗及全部依赖效果一起持久化。缩短区间重算不遗留资源预占或随机抽样副作用。待启动项在来源阶段与计划游标一并登记；启动阶段再原子保存其采用/取消/拒绝状态、真实 action_id、能力占用、启动投入与后续事件，恢复不能重复推进计划或再次扣启动成本。

事务失败，相关变化整体不生效。若进程恰在提交成功、尚未收到确认时退出，恢复必须重新查询阶段记录；不能仅凭上一进程“报告失败”就重做。效果已存在则读取原结果，未提交则从之前的持久状态重新计算。

一次结算的相关变化应作为整体提交，保存机制必须覆盖该动作的全部效果。

## 5. 怎样保证世界内部不重复结算

去重记录必须与效果同事务保存；先记“做过”后扣资源、或先扣资源再另写完成标记，都不符合本设计。

| 过程 | 去重与连续性约束 |
| --- | --- |
| 连续积分 | 当前 last_integrated 必须等于区间起点，阶段游标与版本匹配；提交后一起推进，不能重叠积分同一段时间 |
| 取水/采集/交接 | 动作阶段效果键唯一；扣来源、加去向及实际位置变化同事务 |
| 加工与练习 | 按实际阶段/区间记录投入、半成品、学习增量；完成事件不再额外发一次相同产物 |
| 出生与死亡 | 孕程/个体生命周期事件只可完成一次，新身份与遗体及资源账同事务创建 |
| 交流接收 | 实际片段及接收者组合标识，保存已发/已收进度，重连不是再讲一遍 |
| 记忆与关系 | 按决策内更新操作标识、字段版本和安装阶段处理，记录已应用/拒绝，不靠记忆文本去重 |
| 决定准备完成 | 候选、准备事件、取消和安装状态关联；排队/返回不自动等于已安装 |
| 观察推送 | 提交内产生待推送记录，提交后可重发；前端按游标去重，推送确认不影响世界事实 |

效果标识来自已确定的事件或过程阶段，不能每次网络回调随机生成新标识。仅用“起止时间不同”也不够：积分还必须检查连续游标，避免两个不同区间实际覆盖同一段时间。

相同输入未提交前重新计算，可以消耗 CPU 多次；已持久化效果只允许出现一次。所有模型回调、面板与后台任务都不能绕过统一入口直接执行动作。

## 6. API 请求怎样保存和恢复

一次逻辑决定通常包含主要请求，也可能包含有限的回想/工具回合；每个服务回合使用独立 call_id，重试则在该 call_id 下另记 attempt_id。已完成回合及其实际输入输出保存后复用，恢复不重走全部工具链，也不从恢复后的新资料替换原观察下的工具结果。候选完整且可用时，才安排安装。流程为：

**捕获个人观察与精确输入 → 检查预算 → 持久化发送意图与预留 → 实际发送 → 持久化回包和用量 → 游戏线程校验并按任务进展安装。**

模型请求期间世界继续推进。输入只包含当时该人物可获得的内容。恢复时用检查点中的个人回合和请求 ID 匹配账本，再复核现场。当前游戏版保存边界和复现步骤见[开发与验证](../development/开发与验证.md#异步检查点与跨进程恢复)。

| 中断时持久状态 | 恢复行为 |
| --- | --- |
| 待派发、未登记发送意图 | 按原输入及预算条件继续派发 |
| 有发送意图、没有完整终态响应 | 标为结果不明；不能推断请求肯定未发送、肯定失败或免费 |
| 完整响应已保存、尚未校验 | 直接校验保存内容，无需重发 |
| 响应无效且已确定 | 保留原文与用量，按冻结的有限修复/重试策略处理 |
| 有有效候选、原任务还未完成 | 保留候选，在原任务成功后重新校验交接 |
| 可安装候选已保存 | 按原回合及当前现场恢复交接，避免重复登记 |
| 决定已安装或被取消 | 不再执行其候选效果；迟到响应只作审计/费用记录 |

流式返回中的部分内容可以保存为技术审计，但不能当成完整决定或已说出口的话。完整性、终态和格式校验未通过，就不安装部分动作或记忆。原始响应先持久化，后续解析中断只重做本地解析。

对于结果不明的请求，优先使用供应商明确支持的请求状态查询、结果找回或幂等机制。供应商未提供这些能力时，按启动前冻结的有限策略处理：保留旧尝试及其未知费用，退役其候选资格，检查新预留额度，再登记新 attempt_id 发送原观察下的重试；次数或额度不足则技术暂停。不能无限重试或把旧费用退回预算。

同一 call_id 同一时刻只有一个可接纳结果的尝试。退役和新尝试登记由统一入口协调；已有完整响应待校验时先完成校验，不急着重发。旧尝试退役后迟到的响应仍记录用量，但不能再替换已接纳的回合结果。最终决定候选以 decision_id 只选定一次，不能比较几份答案后选“更有利”的那份。

客户端/SDK 的自动重试也必须可识别、可计数、可预留；无法追踪的隐式重试不作为首版配置。重复回调按 attempt_id 和终态记录去重，不重复增加同一份 usage；不同真实尝试即使输入相同也分别计入费用。供应商若能证明同属同一个计费请求，再通过明确对账引用消重，不能凭猜测合并。

内部效果一次性与外部只收费一次是不同保证。外部响应在进程内到达但尚未持久化就断电，可能无法找回；有限重试也可能得到不同文字。此时保留“结果不明、发生重试”的审计，不声称恢复了原本未保存的思想。

## 7. 预算不会因读档恢复额度

预算账保存已知用量估算、尚未发出预留、在途预留、未知结果负债、已对账金额及其来源。每次实际尝试先登记并预留，接收完整 usage 后按同一尝试对账。取消或超时不自动代表免费，也不释放结果不明负债。

恢复时重新汇总所有非终结尝试，保留整批未完成所需余量；不能只加载“角色决定数”估计费用。费用修订追加记录，不覆盖当时已知数。历史查看同时允许“当时已知账目”和“最终已知账目”，并标明现实记录时间。

阶段额度续接写入独立运行记录。核对既有消费、预留与未知费用后，从一致检查点续接原运行，保留已持久化的有效响应。调度资格和世界规则沿用当前版本。 [长期演进与人口扩展](./AI长期演进与人口扩展设计.md)

从旧存档另开实验不返还真实已发生费用。新分支建立独立的新运行预算，同时关联祖先的真实调用记录；共享的历史费用不再次计费，也不从账户总额中抹去。若仅存较老备份而丢失之后的请求记录，必须标明账目缺口并保守停留，待核对或按已声明最坏额度计入后才能继续派发，不能假装缺失尾部零消费。

## 8. 快照与独立备份的区别

| 名称 | 用途 |
| --- | --- |
| 阶段持久提交 | 每次安全结算保存当前权威状态及去重标记，支持进程中断恢复 |
| 应用完整快照 | 历史模式按世界版本、阶段和提交号固定可还原状态 |
| 08:00 观察快照 | 冻结某个模拟日的观察资料，用于日报取材 |
| 独立备份/导出包 | 保存数据库的一致副本及校验信息，用于文件丢失、损坏和迁移 |

应用快照必须来自同一个一致读视图，不能先存 08:00 的世界、再接上 08:05 的个人记忆。快照清单包含覆盖的提交游标、配置与模式版本、对象/记忆/队列计数、内容校验值及完成状态。采用临时构建、完成校验后发布；不完整快照不进入可恢复列表，旧有效快照继续保留。

快照载荷包含对应边界的可继续状态及必要不可变内容引用，不递归复制全部旧快照与全历史；其引用目标必须保留并纳入独立备份。完整快照不等于完整历史导出包，单独导出快照时必须标明是否附齐依赖和历史，缺少依赖的包不能宣称可独立恢复。

历史模式的完整快照可按提交量与模拟进度触发，间隔由实施方案固定。基础阶段提交独立运行，请求返回、记忆更新和自然过程仍在各自结算边界保存。08:00 观察快照与该时点的结算同事务提交，日报正文后续单独写入。

独立备份从一致状态生成，记录实际涵盖的游标、配套清单和哈希。不能在复制活动数据时猜测它对应的模拟时刻。

存档目录在进程重启和应用替换后保持可用。独立备份写入另一存储位置，并定期在隔离目录演练恢复；保留和容量纳入运行预算。

## 9. 程序重启后的恢复顺序

默认先进入恢复检查状态，不立即发 API 或推进模拟时间。通过检查且此前是正常运行状态的实验，可以按已有运行意图自动继续；此前明确暂停、结束、预算不足或机制边界暂停的实验仍保持对应状态。

1. 取得当前世界的单运行器所有权，增加 runner_epoch。通过运行实例所有权与存档预期版本检查，新实例取得所有权后才开放运行。
2. 处理正常崩溃遗留状态，校验数据库、清单、模式/规则/运行器与数值配置兼容性。
3. 查找最新持久提交头，验证当前状态与结构化历史、队列、效果记录一致。内存此前的显示不作为已提交证据。
4. 恢复世界、个人、短期缓冲、过程、随机驱动、当前阶段与事件队列；重建只读索引和缓存，禁止初始化器重新生成角色或资源。
5. 核对动作进度与 last_integrated，检查库存非负、物品位置唯一、生命状态与待安装动作相容、队列事件未重建两遍。
6. 恢复待处理回合、候选、发送/结果不明状态和预算负债；先处理已保存原始响应，再按原策略补必要缺项。
7. 从最后未完成的阶段继续。发出一次技术“已恢复”状态，界面刷新一致视图；不让角色获得重启提示或突然遗忘。

同一模拟秒内断电也要按阶段游标继续，不能退回这一秒开头重扣资源。随机驱动、危险量阈值与累计进度直接恢复；不重新抽天气、孕程结果或操作误差。

程序关闭几小时不增加任何模拟年龄、饥饿或遗忘。现实请求超时与限流期限按实际时间重新评估；它们只影响技术等待和费用，不转换为世界经历。旧 epoch 的异步任务不能推进世界，合法迟到响应只进入受控审计/对账路径。

若提交失败、磁盘满或无法保存新响应，立即停止派发并保持最后一致状态；未持久化响应可能丢失，重启后按结果不明处理。不能为了继续运行改成“先执行，稍后补存”。

## 10. 数据损坏、旧备份和版本变化

普通崩溃且最新持久提交完整，可在同一实验标识下继续。可验证的备份加完整后续结构化提交链，也可以还原到同一最新头，再按原回合恢复。

若只能回到更早备份、后续历史不可恢复，不得无声覆盖原实验并重跑不同未来。保留故障原件与已知尾部证据，从可验证锚点建立新的恢复分支，标明丢失范围、原实验来源与费用缺口；旧实验保持故障结束/不可完整恢复。首版不提供为了改变结局而反复挑旧存档重试的运行按钮。

单纯表示格式的无损迁移可以在备份副本上验证后登记迁移记录，不改世界语义。改变物理、生物、认知规则、模型、随机算法或会影响结果的数值行为，属于新实验版本。缺少兼容运行器时允许只读历史；不能用新代码猜测完成旧动作。

运行器、规则和模式版本应有可核对的归档引用。结构化历史回放依赖版本化数据解释器，未必需要旧物理引擎；真正继续计算则需要经过兼容性检查的运行时。哈希可发现某些损坏或不一致，不等于能够修复任意坏盘或证明记录未被恶意修改。

## 11. 历史回放怎样工作

已启用历史模式时，可从已存目标快照直接读状态，或用较早快照与结构化提交重建只读视图。50 人当前状态模式用最新状态和观察资料展示可用记录。日报快照是取材记录，恢复从独立备份或当前检查点继续。

结构化历史必须覆盖所有影响还原的状态，包括连续数值差量、实体创建/删除或墓碑、位置/容器、个人字段、记忆可访问性、短期缓冲、队列、过程进度和随机状态。仅有“阿木采了果子”这样的自然语言事件不够。变化记录带前置版本、序号、模式版本与校验信息，应用顺序与快照覆盖范围明确。

默认只精确展示已提交边界。用户选择两个提交之间的时间，定位到不晚于该时刻的最近可还原边界，并显示实际展示的时刻/阶段；不能用直线插值编造中间记忆、动作成果或生死。未来若提供连续轨迹插值，只能作为明确标注的视觉近似，不作为新事实。

同一历史页面的世界、人物、关系、记忆、物品与行动都固定到同一个版本。默认展示当时已经安装的决定和可回忆内容；后来才形成的记忆摘要、关系判断或返回的候选不能回填过去。观察者审计可以展开遗忘前版本，但标明当时/当前可访问性，不能把这些内容送回角色。

API 原始响应、迟到账单与技术状态另按 storage_revision 和现实记录时间关联。默认历史事实视图不把未来才知道的技术信息冒充当时已知；可以明确切换查看最终审计结果。只有相同模拟时刻、不同技术修订的记录也必须区分。

回放读隔离的只读视图，可使用临时本地派生库重建，不连接模型网关、不消费运行预算、不触发消息送达、出生、资源转移或社会分析反馈。界面断线重连只补观察记录，不重新运行世界动作。

查看历史不暂停当前正在运行的世界；全局栏仍显示真实最新状态和调用情况。只有运行控制中的“暂停模拟”才停止推进。继续运行只针对可恢复的当前头；从过去另开属于显式新实验，不能把播放器拖动当作修改历史。

另外可以在独立验证环境中，用保存的模型决定、随机驱动和兼容规则重新计算，比较结果。这是后续一致性验证，不是默认历史播放；不重新请求模型，跨平台浮点误差与规则差异须单独报告，不能预设仅同种子就逐位相同。

## 12. 一个中断示例

在模拟 08:00，阿木已经采到部分食物，阿禾有未说完的话。世界和两人的过程进度、个人记忆及待处理输入已经保存。

阿木的 API 完整响应已存为候选，阿禾只有发送意图、没有完整响应；此时断电。

恢复从 08:00 的检查点推进。已采到的食物和已送达的讲话不重复结算。阿木的回包与已保存回合匹配后复用，等到前置任务完成再复核。阿禾的未知费用保留，按已登记的恢复规则处理。

假设此前恰好已提交一次采集阶段但尚未显示给面板，恢复读取已提交效果，向界面补发同一观察记录；不把“用户没看到”当成“世界没发生”。同理，没提交的计算不会因为内存曾算出结果就作为历史。

## 13. 容量、保留与保证边界

本轮总容量、费用和累计范围以[设计总览第 6 节](./AI部落文明模拟-设计草案.md#6-本轮运行额度与暂停)为唯一配置依据。容量不能只统计主数据库，原生地形、请求账、日志、备份、导出临时文件和数据库临时增长都需计入；可选观察视频不默认开启。

当前 Windows 本机实验的共享费用账、管理目录、暂停保存和追加入口见[跨实验额度与自动暂停](../development/开发与验证.md#跨实验额度与自动暂停)。供应商最终账单对账和独立备份恢复仍按本专题验收。

| 数据 | 当前状态模式 | 历史模式与清理条件 |
| --- | --- | --- |
| 原生世界、AI 当前状态与在途任务 | 保留可共同恢复的最新状态、方法版本、队列和效果去重标记 | 历史模式另存覆盖范围内的结构化变化；不能为省空间删除已修改区块、人物或建筑 |
| 个人记忆与关系 | 保留认知机制要求的可访问资料和必要来源；关系按实际需要稀疏保存 | 人物遗忘不自动授权清理恢复或历史证据；物理清理不得改变未来可读取内容 |
| 模型输入、原文及技术尝试 | 待处理、结果不明、尚可被恢复引用的调用必须保留；完成记录可无损压缩 | 旧原文只有在完成对账、脱离所有恢复依赖且过了预先声明的审计保留范围后，才可按当前状态模式的策略整理；保存用量、身份、关联和清理范围。历史模式保留登记取证范围内原文 |
| 观察事件、日报和历史 | [实时面板](./AI监控面板信息与交互设计.md#14-刷新断线与一致性)只使用有限内存窗口。日报和选定重要事实按实验的记录设置保存 | 历史模式的已登记范围保留原始记录。摘要用于阅读，恢复和精确回放使用对应证据 |
| 普通诊断日志与缓存 | 按大小轮转；已封存日志可压缩，可重建缓存可清理 | 调用负债、效果标记和恢复清单不归类为可随日志轮转删除的内容 |
| 共同检查点与独立备份 | 仅轮换已校验、无依赖的旧副本；生成新副本前先预留峰值空间 | 删除前确认仍有可恢复版本及必要独立备份；完整快照的引用依赖不可被轮换破坏 |

运行前由实现者给出日志大小、观察窗口、原文审计保留范围、检查点间隔与备份数量的默认配置并记录，不要求用户逐条设计。保留策略在同一实验内固定；尚未确定是否可删的数据按保留处理。当前没有执行任何清理，也没有创建实验数据。

容量控制采用提前预留：统计当前占用、在途持久化与下一阶段预计写入，另留安全暂停和检查点需要的空间。若峰值无法容纳，先停止新模型请求及模拟推进，在最后一致边界保存并容量暂停；不等写满后才尝试保存。宿主实际可用空间更少、写入失败或估算偏差时同样暂停。无损压缩和已声明轮换后仍不足，就保持暂停，不牺牲世界与恢复保证延长运行。

费用达到预检边界时沿用同一暂停流程；已在途与未知请求负债继续记账。追加额度、调整保存位置或扩大容量后核对旧账与原队列再继续，不能因恢复旧副本清零费用。

连续运行按现实时间记录进程内存、CPU、区块与寻路负载、各类数据字节数及增长率、每模拟日费用和检查点/恢复耗时。先短时测量，再延长稳定性窗口；窗口长度在测试前登记，不把“能启动”视为长期运行已通过。

后续实现应进行故障注入，当前尚未测试：

| 中断点或场景 | 必须检查 |
| --- | --- |
| 状态写到一半、提交前退出 | 世界、记忆、库存、随机与队列整体未生效 |
| 提交完成、确认或推送前退出 | 恢复识别已完成，不重复效果，界面可补发去重 |
| 部分行动、发声、消化、学习或孕程 | 从真实进度继续，不重新起步、不免费完成 |
| 完整响应已存、校验或安装前退出 | 不重发有效请求；匹配的候选遵守原任务交接与取消条件 |
| 发送前后不确定窗口与迟到响应 | 未知费用不清零；旧尝试不替换已选候选；重试有限 |
| 记忆遗忘、修订、摘要与历史查询 | 历史可还原，个人不能绕回隐藏细节 |
| 身体失能、死亡或出生前后 | 身份和物质只变一次，旧决定不能让死者继续行动 |
| 重复回调、重复启动、面板断线 | 单运行器推进；技术重复不产生第二次世界效果 |
| 快照/备份写到一半或哈希不符 | 不发布损坏存档，旧有效备份可用，错误明确 |
| 从旧副本恢复、账目尾部缺失 | 新分支与缺口清楚，真实消费不回滚或重算 |
| 磁盘满、主库损坏、不兼容运行时 | 停止派发与结算，不临时跳过人或重建一个假世界 |
| 历史回放与一致性重算 | 默认回放不产生调用和副作用；重算另行检查差异 |

在存储与运行时正常、数据完整的前提下，本设计目标是：最后成功持久化的内部状态可恢复；每个世界效果至多提交一次，必要的未完成过程可继续；历史读取不改变实验。供应商请求是否只执行/收费一次、未保存外部响应能否找回、任意硬件故障是否无损，不能由本地存档机制单独保证。
