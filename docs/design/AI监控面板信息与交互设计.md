# AI 监控面板信息与交互设计 v0.2

> 基于 Survivalcraft 的目标设计，尚不表示已实现。游戏复用范围、根本驱动力和运行额度以[设计总览](./AI部落文明模拟-设计草案.md)为准；专题中的新增机制按能力清单逐项接入，不要求先重建一套世界。

Windows 已接入只读实时面板。实际启用方式见[开发与验证](../development/开发与验证.md#实时世界面板)，实现和验证范围见[当前状态](../development/当前状态.md#实现范围)。

## 1. 面板的用途与边界

面板帮助观察者回答：世界现在发生什么；某个人知道什么、记得什么、正在做什么；一次决定在何时生效，实际结果怎样；模拟为何停住；请求与费用花在哪里。

观察者可以查看全局事实与个人主观资料，但这些查询不向角色反馈，也不改变感知、关注、行动或自然过程。面板是观察与实验运行控制入口，不提供运行中编辑人物、修改记忆、投放资源或指派任务的功能。

本稿确定内容、视图关系和交互语义，像素、配色与动画表现待定。总览、列表、详情与证据逐层展开，方便观察者从 50 人中找到想看的成员。

## 2. 页面骨架与导航

首页采用全局运行栏、世界状态摘要、人物名册和可展开的人物详情。首版提供人物、世界、对话、事件、API 与费用入口，实验记录后续接入。对象和事件之间可以跳转，保留所属实验、查看时点、版本与筛选条件。

全局运行栏始终显示：实验名称与规则版本、实际最新模拟时间、运行状态、现实运行耗时、实际推进倍率、连接状态，以及开始/暂停模拟/继续/速度/导出入口。技术等待时显示原因和相关请求状态；暂停请求尚未完成时不立即标成已暂停。

开始仅对已经初始化且预算已设置的实验可用。页面刷新不创建新世界，关闭页面不暂停。速度调节改变运行节奏，不改变认知频率或物理参数。

## 3. 四种信息必须分清

| 类型 | 展示例子 | 含义 |
| --- | --- | --- |
| 世界事实 | 某人持有 3 个果实；某处水量减少 | 来自引擎已提交状态和事件 |
| 个人主观状态 | 他相信对方不可靠；他记得昨天有人帮助 | 来自个人记述、判断、愿望或参数模型，可能不准确 |
| 尚未生效的候选 | API 已返回“去河边”，准备在未来时点完成思考 | 技术候选，不等于本人已完成决定或开始移动 |
| 观察统计或解释 | 冲突次数增加；某种习惯可能正在形成 | 可计算指标或研究者解释，必须给出来源与限制 |

这些类型同时使用文字标签和样式区分，不能只靠颜色。空值区分未记录、未计算、接口未提供、模型尚不支持和本人已遗忘，不用 0 或“正常”替代未知。

当前面板只展示有值的字段。例如觅食者显示生命和饱食度，省略体力、睡眠、体温和湿润度。原生玩家有这些数据时照常显示。零值、空背包和清醒状态按实际状态显示。

面板的“思考”指已输出的意图、计划、简短理由、自述和状态提案，不声称读取模型完整内部推理。关系、情绪与认知参数也不作为经验证的人类心理测量值。

## 4. 总览：先知道现在该看哪里

总览展示少量摘要，均可点进原始事件或对象：

- 人口：存活、出生、死亡，身体或行动处境需要关注的成员。
- 当前生活：多少人在移动、采集、休息等；身体行动与认知状态分别统计，可重叠，不能相加当作人口总数。
- 环境：天气、光照、水资源和食物库存趋势，区分已采食物、仍附着的可采资源与潜在猎物，避免重复累计。
- 最近事实：交谈、行动完成/中断、资源变化、伤病、出生死亡等。
- 运行健康：最新模拟时刻、请求状态、并发和排队、暂停原因、预算与存储状态。

人物、资源、动物和住处的位置使用已提交的坐标和已知区域，在列表和详情中查看。

不默认显示“文明等级”“群体幸福度”等缺乏明确测量定义的总分。“食物还能吃多少天”若以后加入，必须解释口径与假设；首版先显示实际库存、消耗和趋势，不承诺预测。

## 5. 人物列表

列表显示 50 名初始成员及后来成员，支持按姓名/标识、生命阶段、身体状况、当前行动、认知/请求状态和地点筛选。可收藏关注成员，收藏仅影响观察界面。

建议列：姓名与标识、年龄/生命阶段、位置、身体概况、当前身体行动、当前认知阶段、最近一次已生效决定、下一次已安排回顾及是否有新事件。查看历史时所有这些列属于同一历史版本。

行动与认知必须分两列：一个人可能在行走，同时有未完成思考。排队或服务器重试显示为运行技术状态，不当作他懒惰、发呆、疲劳或认知低下。列表不需要为每人持续生成自然语言简介。

死亡成员保留可检索的档案和人生历史，不与仍可行动成员混淆；观察存档不令其恢复活动。

## 6. 人物详情

| 分区 | 内容 | 主要操作 |
| --- | --- | --- |
| 状态 | 世界中的身体事实；个人倾向、偏好、情绪、愿望、目标和认知参数 | 看当前/历史值，展开来源与变更 |
| 记忆 | 当前可回忆的经历、听闻、推测、反思与意图 | 搜索、按时间/人物/类型筛选、查看修订与调用时是否被取用 |
| 决定 | 已生效的决策时间线、当时感知、提供的记忆、输出计划与简短理由 | 比较调用前后，跳到后续行动 |
| 行动与交流 | 动作阶段、实际耗时、获得/失去、身体成本、中断，以及发出/收到的话 | 查看对象变化、接收情况与后续回应 |
| 关系与亲缘 | 本人对他人的方向性判断，以及世界记录的亲缘 | 分开看“他如何看对方”和“对方如何看他”；区分已知关系与事实 |
| 变化历史 | 愿望、判断、性格、技能等修订 | 看旧值、新值、有效时点、来源、接受或拒绝原因 |

同一页先给概要，完整上下文、输出、数值和事件依据按需展开，不默认堆满所有原始内容。

人物详情的「当前身体状态」读取与页首分钟和修订号对应的已提交检查点。存活成员可查看可用能量储备、体内水量、饥饿和口渴等级、疲劳和睡意的等级与点数，以及引擎判定的全部虚弱原因。旧存档按所支持的身体机制展示可用项目。「当时的感知」单独展示该次决定实际收到的内容。

## 7. 记忆的观察方式

默认只展示这个人在所选时点能够回忆的个人记述，包括内容、类型、经历/记录时间、对象、个人确信与重要程度、可访问程度和修订关系。个人确信与重要性不是正确率或科学测量。

可切到观察者审计模式查看已遗忘、被概括或修订的旧版本与原始依据，并持续标注“角色当前不可读取”。保留结论却忘记理由的情况应显示为这种状态，不自动把原始细节重新放进角色上下文。

从一条记忆可以查看哪些调用曾把它提供给模型、模型是否在输出中引用它，以及关联的行动。这个关系证明数据曾被提供或引用，不证明该记忆一定是内部决策的真实原因。

世界中的文字/记号是另一类对象：它需要被实际观察和理解，不能因为观察者打开其内容就进入某人的长期记忆。

## 8. 思考、候选与模型原文

一个决策的详情显示：唤醒原因、观察的模拟时点、个人版本、上下文中实际提供的信息、来源记忆、模型输出、准备完成时点、实际安装时点、被接受/拒绝的字段以及后续动作。

普通视图默认显示已经生效或已取消的决定。尚未准备完成的 API 响应放在明确的候选区并默认折叠，不出现在“他现在已经决定”或过去历史的事实摘要里。被紧急中断取消的候选只留审计，不冒充本人记得的想法。

同时显示两条不同状态线：

- 认知：取得观察、模拟中的思考区间、准备完成、决定安装或取消。
- 请求：未发、排队、请求中、收到响应、格式检查、修复/重试、有效结果已缓存。

API 已返回不等于模拟中的思考结束；等待同批他人也不等于本人多思考了几十秒。不能用网络进度条显示“思想完成百分比”。

原始输入输出供观察者按需检查；展示的是保存的内容，不重新调用模型解释它“真正想了什么”。界面不显示 API 密钥或认证头。

## 9. 行动、交流与结果追踪

动作时间线包括提议、接受、实际开始、阶段进度、完成/部分完成/失败/中断/取消。显示实际耗时、关联物品、数量与单位、身体消耗和可感知结果；尚未发生的完成时间或产量只标为估计/上限。

可以从决定一路查看：当时输入 → 输出意图 → 准备完成 → 实际行动 → 世界差量 → 本人反馈 → 后续记忆。这里的箭头代表系统记录的数据流，不等于心理学上的因果证明。

技术格式错误不放进“阿木采集失败”；模拟器能力边界单独标识，不能被描述成人物能力差或一次真实物理失败。

### 实时对话记录

对话页按模拟时间显示已说出的内容，可按说话人、实际听众或原话筛选。从人物详情可查看这个人说过的话和实际收到的片段，并跳到对应记录。发出承诺、实际贡献和未履行是不同记录。

对话和事件各用竖排信息流。左侧是带编号的圆角人物名牌，右侧是内容和模拟时间，行间用留白分隔。新记录从底部进入。向上滚动时保留正在阅读的画面，滚回底部或点「回到实时」时跳到当前内存窗口的最新记录。对话正文合并同一次发言已经送达的片段，展开后可逐段核对实际听众。

游戏在每段讲话完成送达判定时生成一条观察记录。记录包含实验标识、发言 ID、片段序号、模拟时间、说话人、发声方式、原话、实际听众和结束状态。无人听见的片段也记录。同一次发言按 ID 归组，听众变化时按段展示。中断只保留已说出的片段并标记中断。未执行的台词与尚未说出的片段留在候选资料中。

观察端从送达结算复制事件，独立于角色收件箱。面板打开后读取当前内存窗口并接收新增片段。对话与其他实时事件各有内存窗口，见第 14 节。恢复存档后，面板从恢复后的世界重新获取快照和事件流。

## 10. 世界页与对象检查

世界页用列表展示已接入的环境和对象信息，包括天气、活动区块、动物、食物、物品与结构。地表水、土壤水等随相应机制接入。列表标明数据覆盖范围。

点选任一对象查看：稳定标识、类型、位置/容器/持有/附着关系、组成与实际库存、温度/含水/损伤/生命阶段、进行中的过程、最近更新时间、相关行动和变化历史。父对象与部件视图说明派生总量，避免把组合质量或同一库存重复相加。

资源变化可追踪来源、去向、时间和规则，例如果实从树转到背包、喝水从水源转到身体、燃料转成已定义产物与损耗。未追踪过程和外部输入输出明确标识，不用一条“全世界守恒”图表掩盖近似边界。

明确标注区域之外、未建模的作用和未知数据。世界筛选不影响未被显示区域的更新。

### 场景视图

目标是在当前游戏场景内使用可移动的观察摄像头，后续可提供自由移动、跟随人物、选人和只读详情。具体按键、镜头约束、界面和回放细节待设计；当前没有本项目已完成的观察摄像头或 AI 轨迹回放实现。

摄像头不创建可交互人物，不碰撞、拾取、占用资源、发光或制造声音，不进入人物的感知输入。镜头移动和人物详情查询不触发角色决策，不改变消息接收、资源或活动资格。允许渲染和查询改变现实处理速度，不能改变模拟时点的事实结果。

活动区块由人物、动作和自然过程的模拟需要决定，不由观察摄像头独自决定。跨区加载可以为展示准备只读资源，但不得重新生成已变动地形、激活额外事件或使远处人物停工。无观察窗口时仍推进世界；无界面运行需要单独实现与验证。

球体总览和最近轨迹曾属于旧实现的展示方式，不作为本版已有功能。历史场景只展示实际保留的记录，视觉插值须标注；摄像头观察与历史回放不混为同一功能。

## 11. 事件页

世界事实、个人状态修订、技术运行记录保持类别可辨。默认世界事件按模拟时点、结算阶段和稳定事件序列排列；请求状态按现实记录时点排列，二者通过关联标识连接。

支持按时间范围、人物、对象、地点和事件类型筛选，并显示筛选口径。隐藏事件不等于删除事件；大量记录分页或分段加载，趋势降采样也不改变原始数据。

事实摘要由已提交数据或记录模板生成。AI 日报标明所用取材时点、角色记忆或记录来源，以及资料空白和分歧。刷新直接读取已保存结果，调用用量计入观察任务。

告警区分模拟处境与技术故障，例如某人伤势变化、资源趋近耗尽，与限流、预算暂停或磁盘不足分开。观察告警只帮助用户定位；是否自动停机由已有运行器规则决定，不因面板筛选或阅读习惯改变。

## 12. API 与费用页

### 请求与排队

展示待派发、在途、待交接和已提交的个人回合，附限流等待、并发上限和最近保存时点。可按角色查看等待原因，世界推进状态单独显示。

区分个人主要决策数、实际请求尝试数、显式回想、格式修复、重试、记忆整理与观察分析。一次个人决策可产生多个请求，不能把这两个计数混为一谈。

运行性能展示实际在途数、排队时长、提前派发和交接成功次数和模型等待/内核计算/持久化耗时；统计口径沿用[调度专题](./AI时间推进与调度设计.md)。区分并发上限与真正可并发的请求数量，不把提高上限显示成已经获得相同比例提速。实验记录区分预算、技术故障、能力与地图边界暂停，并显示最后一致版本及窗口未覆盖范围。

每个请求显示所属人/服务类别、输入对应模拟时点、现实排队与发送/返回时间、供应商/模型、状态、输入输出用量、延迟、是否被采用以及关联决策/行动。被取消或未采用的响应仍可能产生费用。

### 费用口径

费用首页建议分开显示：按已知用量计算的费用估算；尚未完成请求的预算预留；用量不明的请求数量及保留额度；本次实验预算与当前可用估算余额。供应商若提供可核对账单，另显示账单金额与对账差异；没有账单时不把本地计算叫作最终实付。

保留币种、价格版本、计费单位和来源。输入、缓存命中/写入、输出、推理与工具等项目按供应商支持情况归一化，标清哪些已包含在总量中，避免重复计费。未收到的字段省略；结算状态为用量未知时保留该状态。

超时、取消或断线不能填成零费用。未知用量单列，估算误差与预留不确定性显著展示；额度不足按运行器规则暂停，不靠用户开着面板守着。

支持按实验、个人、服务类别、模型和模拟日查看费用。模拟区间按决策观察时点归属；现实消费曲线按请求实际发生时间。图表明确横轴，不能把两种时间混在一条无说明的曲线上，也不将已知最终用量冒充历史时刻已经知道的金额。

不默认据少量样本承诺未来能运行多少代。若以后加入预测，应明确样本、固定调用频率等假设；角色调用量排名也不作为智力或人格评价。

## 13. 实时、固定查看时刻与回放

默认跟随最新已提交世界。启用日报的当前状态档可查看已保存的 08:00 快照与日报。历史模式可选择已保存的历史时点，场景与人物视图固定在同一实验、时点、阶段和世界版本。资料缺失时提示可查范围。

固定历史查看不会暂停正在运行的实验。全局运行栏继续显示真实最新运行状态，并明确提示“场景查看历史，实验仍在运行/产生调用”。“暂停模拟”才是运行控制；不使用一个含糊的“暂停”按钮混淆两者。

历史查看默认展示当时已经安装的决定与可访问记忆，未来才返回或生效的候选不穿越进历史。API 原文和后续费用可以作为关联审计展开，但标明各自现实记录时间、模拟准备完成时间及查看的是最终已知账目。

历史查看与回放读取实验已有的存档和记录。可查范围由实验实际保存的数据决定。实验记录页可读取已有的配置、规则和模型版本、检查点、暂停与结束原因，并导出一致范围的记录。继续针对可恢复的已暂停运行，重开或更改规则时使用新的实验标识。

## 14. 刷新、断线与一致性

面板先读取带世界版本与观察流游标的快照，再订阅增量。世界结果与请求/费用技术状态可以共用带类型的观察流，但观察流序号不等于世界版本：API 等待时可能只有技术状态在更新。

实时面板只读取世界数据与请求状态。运行端和页面都只暂存最新快照及最近一段事件，按条数和字节设内存上限，满后淘汰最早记录。实时展示额外写盘量为零。游戏存档、角色记忆和请求账本按[存档设计](./AI存档恢复与历史回放设计.md#13-容量保留与保证边界)保存。

Windows 首版每 500 毫秒至多发布一次游戏线程快照，网页每秒获取一次当前快照和事件窗口。普通事件和对话各最多 200 条、128 KiB，合计不超过 256 KiB。单次快照上限 8 MiB，人物详情最多 64 位并标出名册总数。动作结果沿任务 ID 关联，物品交接沿提议 ID 关联。对话展示实际送达片段。身体变化由相邻快照计算，当前不推断原因。

观察入口应验证快照、增量更新、断线续读与运行控制的端到端一致性。

每条更新绑定实验标识、类型、模拟时点、实际记录时间、关联世界版本和稳定编号。按已提交的世界版本整体应用世界差量，避免一张卡显示新库存、另一张还用旧位置。技术状态更新可以保持世界版本不变。

断线后显示最后确认的版本和数据时间。重连时按游标补读仍在内存窗口内的事件，去除重复记录。超过窗口或运行端已重启时重新取一致快照，并标出无法补读的区间。按实验标识隔离数据。查询、筛选、回放、切换人物和刷新均读取现有数据。

## 15. 允许的控制

允许开始已配置实验、暂停模拟、继续当前暂停、调整处理节奏、查询和导出。暂停后停止发出新请求，但已经在途的请求可能仍计费；暂停请求未到安全边界时给出准确进度。无需反复确认每一次普通暂停或查看。

不提供“替他想”“让他去做”“重新生成这个决定”“跳过这个人”“给资源”“修改记忆”等按钮。发送不明和预算暂停按既定恢复规则处理。观察行为不成为世界中一次神谕或干预。

导出固定实验、范围、数据版本与费用口径，记录规则及来源；不包含认证信息。若导出耗时，导出读取固定视图，不能把多个时点拼成一个伪快照。

## 16. 三个常见观察路径

**看一个人的生活**：人物列表 → 阿木 → 当前状态 → 最近已生效决定 → 当时观察与记忆 → 实际行动 → 收获/失败 → 后来保留的记忆。无需先读 API 原文。

**看一段误解**：某人对阿禾的判断 → 支持它的个人记述 → 当时他实际感知到的内容 → 观察者可查的真实事件。界面可以并排比较两种信息，但不会替角色纠正记忆。

**查人物为何在等待及费用变化**：全局运行状态 → 人物任务与决策状态 → 请求队列、在途或未知用量 → 预留与已知费用。分别显示模拟是否推进、人物是否在执行以及请求是否仍在后台进行。

## 17. 面板验收重点

验证事实/主观/候选/解释的标识；候选不提前生效；遗忘审计不混入本人当前记忆；历史视图不混入未来数据；暂停查看与暂停运行分清；同一世界版本一致呈现；断线可恢复；人物行动与认知计数不双算人口；库存与组成不双计；请求数与决策数分开；未知费用不显示零；用量与价格口径可追溯；观察与刷新不消耗角色 API 或改变世界。

对话另测无人听见、听众中途离开和发言中断。验证内存达到上限后淘汰旧事件，持续观察的额外写盘量为零。验证窗口内重连补读、超窗时标注缺口、恢复后读取新快照，以及角色收件箱无重复送达。
