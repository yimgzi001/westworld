# AI 游戏扩展：分阶段实施路线

> 在 Survivalcraft 上扩展，目标与运行额度见[设计总览](./AI部落文明模拟-设计草案.md)。阶段说明不是已实现或交付工期承诺。

## 1. 实施顺序与共同门槛

**核对游戏能力 → 一人受控闭环 → 一人真实模型 → 少人数交互 → 50 人压力与恢复 → 50 人短段和持续观察 → 按证据增加长期机制。** 各阶段使用同一游戏、人物身份、观察与动作接口，不先重建物理、生态或完整生理。

正确性、个人信息隔离、动作真实执行、摄像头无干预、费用/容量保护和一致恢复是已启用路径的必需门槛。各版本登记能力清单：复用且已验证、适配中、新增未实现、未启用。扩展目标未启用可不阻断该版本观察，但必须限制结论，不把未启用标成通过。

50 人是创始规模目标。第一版可以先观察游戏机制下的生存、分工、合作、冲突和方法积累；成长、生育、衰老和开放制造的后续目标保留。缺少生命周期的运行不能冒充跨代实验。

当前所有阶段先面向 Windows 本机。Linux 服务器适配与无界面运行是后续范围，不在一人或 50 人本机版本之前新增 Linux 放行关卡。已有服务器信息先查[开发与验证](../development/开发与验证.md#运行位置与已有服务器记录)。

## 2. 阶段 0：核对游戏适配入口

| 内容 | 必须形成的具体结果 |
| --- | --- |
| 人物实体 | 明确 AI 人物模板、复用组件、背包/制作/装备/生存能力，区分同屏玩家槽位与 AI 人口 |
| 执行控制 | 定位移动、寻路、挖掘、掉落拾取、进食、制作和放置；定义开始、进行、失败与完成反馈 |
| 驱动力 | 用游戏的身体后果、少量个人偏好、局部信息、经历与关系生成目标，不预设职业和日程 |
| 时钟 | 映射逐帧游戏时间与 AI 事件，明确模型等待时冻结什么、渲染与摄像头如何继续 |
| 活动范围 | 模拟所需区块由人物与过程维护，摄像头移动和关闭视图不能决定人物是否活动 |
| 保存 | 选定原生世界文件与新增 AI 状态的共同检查点及恢复入口，明确尚未具备的原子保证 |

优先沿现有组件和扩展接口接入，必要时再改源码。技术栈未确定部分由实现者提出最小可验证方案，不把 Python、Web 管理端或独立无界面服务列为第一步必需依赖。已有游戏运行记录不替代 AI 接入证据。

## 3. 阶段 1：一人受控闭环

使用游戏生成的小场景和一个具有必要生存组件的 AI 人物。先用固定测试决定串起结构化观察、`MoveTo`、`PickUp` 与 `Eat`，核对实际位置、掉落物、背包和身体反馈。把恢复点设在拾取之后、进食之前，检查重开后从当前步骤继续。闭环稳定后再覆盖休息和其余已启用物品操作。具体接口见[行动与模型交互](./AI个体行动与模型交互设计.md)。

完整链条：个人感知 → 目标/有限计划 → 技能与具体动作 → 游戏状态真实变化 → 本人反馈 → 记忆 → 后续输入。固定决定仅验证执行和连续性，不证明自主性。

同时检查分层执行：局部障碍在既定目标内绕行；没有材料、工具或既有分支时报告受阻；步骤进度和部分结果可保存。用不中断基线对照强制退出与恢复，资源不复制、游戏与 AI 状态不分叉。

先用假用量通过统一费用与容量预检、暂停和续接路径。出口是已启用动作、身体、输入和恢复通过；不是完整世界模型完成。

## 4. 阶段 2：一人及少人数真实模型

一人受控闭环通过后，从独立测试初态接入真实模型，使用本轮额度内登记的小窗口，不增加每日或个人调用配额。先落实用量预留、未知费用、有限重试、完整响应保存和容量余量，再实际派发请求。

记录实际经历是否进入后续输入、目标与方法能否跨步骤持续、低层能否少调用模型完成任务，以及实际成本。角色可以拒绝、犯错、休闲或改变打算，不要求固定生存日程或预期台词。

多人先用固定决定验证讲话送达、独立回应、实际交换和同刻竞争。加入一名在可听范围外且未目击交接的人，检查转述前后其实际模型输入。随后运行 2—5 人真实模型短试，观察分工、休闲与利益差异如何影响合作，记录未出现及反例。场景见[交流与社会关系](./AI交流与社会关系设计.md#11-一段具体演化示例)。

出口对应验收 P8 的个人连续性与独立互动证据，相关信息、费用和恢复契约仍有效。若需改变模型或认知机制，用新实验配置重测。

## 5. 阶段 3：50 人压力与候选版复核

使用同一调度器与保存路径，以替代响应器验证全员同刻、长期错峰、交流连锁、乱序、超时、限流、费用/容量不足和进程中断。验证个体最终能获得机会，响应顺序不成为资源优势，恢复复用已有结果。

验证游戏专有问题：多人物寻路、活动区块、跨区地形变动、世界与 AI 共同恢复；移动摄像头、跟随不同人物、关闭观察视图，固定决定与随机驱动下模拟结果保持一致。模型与网络异步运行，世界和既有任务在等回复时继续推进。

按[验收设计](./AI测试验收与演化证据设计.md)通过能力清单中的 W/P/T/R 必需路径及游戏接入检查。未启用扩展单列，不因缺少球面地表、独立口渴或孕程而把游戏版标成不能观察，也不宣称这些能力已具备。

最终候选版再做一人和少人数有限真实模型复核，旧简化版本证据不直接冒充新版本通过。

## 6. 阶段 4：50 人短段与持续观察

从冻结的初态运行 50 人短段，建议先约一个模拟日；测试前登记终点与口径。观察身体后果、分层行动、实际交流、记忆使用、费用与容量增长、暂停恢复和摄像头无干预。按本轮累计额度运行，不因进入新阶段清零旧消费。

通过后可以持续运行，约 30 个模拟日作为首个测量窗口的建议值，不是世界寿命上限。到费用、容量或技术边界先保存暂停；经授权续接额度后继续原时点。自然灭绝、合作失败或长期变化很少都可作为实际结果，不通过自动补资源或改人格维持剧情。

现实连续运行窗口逐步延长，记录内存/CPU、区块与寻路压力、请求等待、费用、分项磁盘增长和恢复耗时；何时延长由测量与额度决定。保持观察视图关闭和摄像头跨区两种场景。报告实际覆盖范围与停止原因。

## 7. 后续机制按观察缺项扩展

| 长期目标 | 加入条件与证据 |
| --- | --- |
| 成长、繁衍、衰老与代际传承 | 实现并验证相应身体与人口机制，出生身份独立、照料有成本、知识通过实际接触传播 |
| 更多生产、开放工具和可编程装置 | 原生配方和方块表达不足时再增加可组合作用，检验实际投入、结果与可复现性 |
| 更丰富偏好、社会方法与组织 | 依据行为缺项增加通用表达与学习能力，避免按某个预期结局补脚本 |
| 更大范围与模拟优化 | 测量瓶颈后优化，分级精度由实验规则与模拟需要决定，镜头不能触发世界语义变化 |
| 独立后台与更丰富观察界面 | 验证游戏模拟与渲染依赖后逐步解耦，不把已有客户端认定为已支持无界面服务器 |
| 球面世界、细致生态与生理 | 保留专题候选，只有研究确实需要时进入独立版本，不作为当前游戏改造前置条件 |

每项改变结果的扩展固定新规则并建立有来源的实验分支；个人学会新方法属于世界内演化，与开发者给引擎增加新能力分开。用户负责方向与资源边界，开发者提出默认实现并验证，不把全部机制细节交回用户设计。
