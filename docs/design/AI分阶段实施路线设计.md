# AI 部落文明模拟：分阶段实施路线 v0.2

> 迁移保留的目标设计。适用性需按 Survivalcraft 游戏机制重新核对，其中的设计要求不表示当前游戏或 AI 接入已经实现。

本路线沿用主草案和《AI 测试、验收与演化证据设计》的契约与放行门槛。人口规模、试验窗口和优先级中的建议值是便于推进的默认选择，不代表已经测得性能、费用或交付工期。

50 人验收验证创始规模，随后可继续验证增长后的动态人口、代际技术积累和更复杂的世界内生产与计算。阶段预算是现实运行边界，可在保留原世界和队列的情况下续接。详见 [长期演进与人口扩展](./AI长期演进与人口扩展设计.md)。

## 1. 区分第一个可运行版本与首个正式版本

| 交付边界 | 目标 | 可观察的证据 |
| --- | --- | --- |
| 第一个可运行版本 | 1 人、极小场景、固定测试决定，完成一个持久的行动闭环 | 观察、意图、实际行动、世界和身体变化、反馈、个人记忆、恢复 |
| 早期真实模型探索 | 最小离线闭环通过后，先 1 人，再在多人路径离线通过后试 2—5 人 | 提前验证动作协议、个人记忆、独立回应和实际成本；明确未实现机制 |
| 首个正式 50 人版本 | 已冻结的原始部落与基础生命周期，按预算运行并只观察 | 真实的个人及群体过程、资源与人口账、运行恢复、历史证据 |

固定决定是可控的验证输入，不作为自主决策证据。第一个版本可以没有动物、繁衍和复杂生态；这些缺项在开发测试范围里明确标出，在正式 50 人运行前补齐并测试。

总顺序：**冻结最小契约 → 一人离线闭环 → 一人真实模型探索 → 少人数离线交互与真实模型探索 → 补齐正式机制 → 50 人模拟接口压力与故障检查 → 集成模型复核 → 50 人短段 → 首个正式观察窗口。** 离线用 50 人压测不等于先建立 50 个复杂角色，更不消耗角色 API。

## 2. 先固定哪些契约

在最早的可运行版本中就采用同一套世界、时钟、行动、认知和存储边界。小场景使用较少状态与动作，接口可支持多人；不要先写一个只有一个人的对话脚本，再改造成世界。

| 契约 | 最早必须定义的内容 |
| --- | --- |
| 世界与行动 | 资源单位、实体身份与唯一位置、动作前提、正耗时、统一启动入口、需求/分配/效果的联合结算、过程进度与失败分类 |
| 时间 | 整数模拟时钟、同刻阶段、动作与身体更新、T+D 安装决定、模拟与现实时间分开 |
| 个人 | 角色所有者、实际身体、个人可感知输入、短期缓冲、私人档案/记忆和版本修订 |
| 调用 | 可替换的决定来源、精确输入和候选输出、决定与尝试分别编号；离线响应器先实现同一接口 |
| 持久化 | 单写入口、阶段原子提交、效果去重、检查点、结构化变化与状态恢复 |
| 观察 | 只读已提交状态，事实/个人解释/候选分开；测试操控只在隔离副本 |

这个阶段的产物是后续实现所需的规格与验收场景。离线阶段用假价格、固定响应和可控故障验证接入流程。单人小试的选型、接口探测和估算见[设计总览第 9 节](./AI部落文明模拟-设计草案.md)。真实小试前配置服务端凭证，核对接口能力、账户限额、试验预算和计费口径。

## 3. 阶段 1：先让一个人离线走完一天

建议场景：一个小营地、可到达的水源和有限食物，具有几个可步行的位置和可休息地点。初始身体有不同程度的饥渴、体力疲劳、睡眠压力；最早只实现这几个状态及已用动作相关收支。先做观察、移动、拿取或采集、喝水、进食、休息与睡眠。使用有正耗时的固定测试意图，不预设正式角色的生活日程。

要跑通一条完整链：从该人当前状态生成个人观察 → 接收固定决定 → 等到模拟思考完成 → 执行动作 → 实际扣除水或食物并推进身体 → 产生本人可感知反馈 → 保存有来源的个人记忆 → 下次组装输入时能读到对应内容。

先把基本存档与可观察性放进去：按阶段提交，持久化动作进度、时钟、输入和决定，能在半途停下并继续；用简单时间线查看事实、记忆提案、已生效决定和结果。在一段已提交取水之后模拟进程退出，恢复后不会再扣一次水。前后结果与固定决定的不中断基线对照。

第一阶段也接上最小预算控制：固定响应器使用假请求额度，通过统一预检和暂停入口；额度耗尽时保留未完成决定与一致状态，不再派发。进入阶段 2 前补齐所启用批次的预留、未知用量、有限重试和对账路径；扩大人口时再验证对应并发与批次规模，不能把这些保护推迟到真实调用之后。

**出口**：一人受控日程在小场景中形成可复查闭环；资源账正确，身体按实际时间变化，记忆有来源，强制中断可恢复且不重复结算，假额度到边界能保存暂停。暂未覆盖的自然和生命周期机制明确标注。此阶段未使用真实模型，不进入 P8 真实行为验收。

## 4. 阶段 2：早期真实模型探索

在阶段 1 的同一内核上，使用独立测试快照和明确的小额预算探索模型可用性，不等待复杂生态、制造和繁衍全部完成。只开放已实现并经离线验证的动作与状态；未覆盖能力列入清单，不作为完整人工社会或正式 50 人证据。供应商、模型、协议、计费口径、请求/token/金额上限和有限重试策略必须先落实。

调用前的最低门槛由[验收专题第 8 节](./AI测试验收与演化证据设计.md)维护：所启用路径的资源、身份隔离、意图/事实、时间、恢复、调用记录和预算保护全部通过；单人场景也用隐藏对象/他人资料测试夹具验证不会越权。简化的是世界范围，不能简化权限、费用和恢复保证。早期使用受控入口与可读时间线，后续验证运行与观察的完整路径。

### 2a 一人约一个模拟日

用同一内核，把决定来源切换为[已选模型的适配层](./AI部落文明模拟-设计草案.md)。从新测试开局开始，保存精确上下文、候选、有效输出和技术重试，分项记录普通输入、缓存命中、缓存写入、输出及实际扣费。观察角色在不同身体状态下能否持续给出有效行动，实际经历能否作为后来思考的输入，暂停与恢复是否复用已有回应。用这一阶段的实际用量和账单修订后续预算。

**出口**：至少一条可核查的个人闭环：实际经历进入后续个人输入，并产出有效、可执行的决定。另有真实接口的成功调用、可对账用量或明确估算限制，以及已验证的故障/预算控制路径。把“引擎没提供经历”“检索漏掉经历”“模型得到但没有使用”分开定位。不要求角色按规定时间吃饭睡觉，也不以花多少请求才碰巧说出预期答案为通过条件。

### 2b 少人数离线交互，再做两人到五人短试

先用固定决定通过两人上下文隔离、讲话实际送达、独立回应、交接、统一启动竞争以及多人批次预算/故障恢复，再换独立多人测试快照，使用同一适配器、时钟与数据权限。两人先看独立问答；三人可看旁听和信息隔离；后续少量成员观察共同出力、竞争及关系分歧。重点检查新信息实际送达后是否进入接收者自己的决策机会，交流频率和反复重试会怎样影响成本。拒绝、忽略和失败合作都可能是有效行为。

**出口**：至少一条独立互动链通过 P8：实际交流已送达，接收者通过自己的决定处理，可以回应、忽略或拒绝。单人和多人阶段的记忆/行动连续性、响应协议、调用记录与费用可解释，没有泄漏、代答、假成功或恢复问题。这些结果只放行后续机制集成；实际驱动 50 人仍须阶段 3 的完整技术门槛与阶段 4 的集成复核。记录每模拟日的动作协议有效率、修复次数、实际记忆输入及行为样例、请求量、等待和费用，保留失败与边界中断。质量阈值和观察终点在小试前登记，未达到窗口不冒充完成；修改协议或认知配置后从独立新版本场景重测。

## 5. 阶段 3：补齐正式机制并完成离线扩展

### 3a 正式版机制集成

复用早期探索前已通过的多人基础场景，随正式机制增加，用固定决定扩展联合劳动、退出、身体约束和同刻冲突的有效/无效尝试。检查新增字段和动作仍不读取他人私有记忆、不替他人同意，也不因一个人的表达就写入全体关系。

在同一引擎上按依赖补充以下能力。它们不是为每个人逐条编生活，而是供所有成员共同使用的机制：

| 优先顺序 | 新增机制 | 核查方式 |
| --- | --- | --- |
| 3a-1 多人感知与动作 | 局部声音、有限传播、交接、共同劳动、争夺；个人信任/承诺/群体认同的独立字段 | 可听与不可听、不同理解、实际贡献和资源竞争；观察解释不写回 |
| 3a-2 世界与加工 | 有限流域、昼夜/季节和局部天气、水、少量植物动物、腐败分解、基本材料与物品、简单加工 | 开放生态收支、来源和去向、结构决定工具效果、材料不复制 |
| 3a-3 身体与代际 | 局部伤病、体温、成长衰老、失能死亡、抽象繁衍、妊娠出生、泌乳与幼儿依赖 | 用隔离快照从临近阈值的状态触发，不靠等几十年或缩短正式生理周期 |
| 3a-4 学习与传播 | 实践熟练度、私人方法记忆、试制反馈、教学、可见记录和读取 | 失败可提供反馈；听讲不复制技能；载体与个人可访问性限制传播 |
| 3a-5 开局与运维 | 固定版本的初始生成器、亲缘与照料检查、快照/备份、只读回放、完整调用与预算台账 | 测试预设不冒充正式历史；整批预留、恢复与重试对账、未知用量保留、坏备份不发布 |

可在独立副本同时完善个别模块，但正式接入仍按依赖验收。简化的关系与规范用角色实际交流和个人判断表示，首版不需要单独编写社会制度引擎。罕见病程或活产只需相关机制通过专用场景，不要求多人短段自然碰到。

**出口**：按验收矩阵逐项关闭离线缺项。可证实世界与角色行为相互作用，且权限、收支、持续过程和恢复符合规格。缺失的关键能力不能用模型生成的文本顶替。

### 3b 用模拟接口验证 50 人的运行压力

从独立测试快照放入 50 个合法成员，使用同一真实调度器、持久化与预算路径。分别使用全员同刻唤醒、长期错峰唤醒和交流连锁唤醒轨迹，替代响应器制造串行、有限并发、迟到、无效响应、限流、超时、预算不足和进程中断。只模拟对外服务，不用一个绕开正式逻辑的专用简化调度器。

必须看到：批次成员各有自己的输入；排队不会增加模拟时间；返回次序不改变竞争结果；已保存结果可复用；未知尝试不清零；预算不足或状态异常在安全边界暂停。固定决定和相同随机驱动下，比较事实与恢复状态，不要求技术日志中的现实时间一致。

### 3c 游戏世界与活动范围验证

核对游戏的世界生成、区块加载、人物移动、资源可达性与存档恢复。角色离开观察范围后是否持续活动需要单独测试，不能把已有游戏画面当作多人自主运行的证明。

**阶段 3 技术放行**要求 W1—W11、P1—P7、T1—T8、R1—R7 的必要路径通过，覆盖跨区移动、50 人批次、观察入口、持久存档和故障恢复。真实运行前重新核对供应商、模型与预算。 [测试与验收](./AI测试验收与演化证据设计.md)

## 6. 阶段 4：集成后的真实模型复核

阶段 3 补齐机制后，核对早期探索证据对应的引擎、动作协议、认知和模型版本。以最终候选版本从独立快照运行一人和 2—5 人有限短试，重点复核新增状态是否挤掉必要记忆、动作是否仍可执行，以及独立接收、统一启动、预算和恢复是否保持成立；不把简化世界的旧结果直接标成完整版本已通过。

**出口**：最终候选版本具有 P8 的单人和多人可核查闭环，实际用量与成本可解释，阶段 3 的完整技术门槛仍有效。未受影响的离线证据可按版本与范围复用，改变行为接口的部分必须重验。若发现对话密度或费用问题，可安排有明确预算的 10—20 人诊断；这是针对问题的可选步骤，不是必经规模。

## 7. 阶段 5：50 人短段，再正式观测

使用经过检查的 50 人初始快照和独立实验标识，沿用同一运行器、同一模型服务和每人私有上下文。建议以 10 并发起步，账户额度允许时对照测试 20，并以批次完成耗时、限流和重试情况确定实际值。 [时间推进与调度](./AI时间推进与调度设计.md)

短段建议先安排一个有明确模拟终点的小窗口，例如一个模拟日。开跑前冻结窗口、预算和观察证据口径。检查 50 人的启动、可感知交流、压力下的结算顺序、人物与资源账、内存与存储增长、调用费用、受控暂停恢复，以及所选存档模式支持的观察路径。观察者依据角色留下的记忆和记录回顾，日报与角色行动独立。

**短段出口**要求到达登记的短段终点或按预定自然终点如实结束，运行、恢复、观察和费用达到验收口径，关键能力均有独立证据。预算暂停按暂停功能记录。若异常需改规则、模型或世界设定，保存原记录，进入新版本与新实验。

短段通过后，开启首个正式 50 人观察窗口，从创始流域开始研究冻结规则下的生存、合作、冲突与经验传播。建议约 30 个模拟日，实际以请求数、token、费用、存储和模拟终点为限。首段技术验证记录与正式实验结论分开。若事先登记短段为同一窗口的前缀且规则、预算契约和初态一致，可以续跑该实验，否则从新的冻结初态起跑。独立调试副本中的动作、观察和构造事件不带回正式初态。

**正式验收**要求世界可恢复、观察资料可核查、费用可追溯。按实际留存的个人经历、记录和行动证据报告族群、规范或传承，资料缺失时标明证据范围。需要逐事件对照的研究单独登记取证范围和存储预算。30 日以内的窗口用于观察基本运行，跨代结论需要多年窗口和重复实验。

## 8. 首个正式版本保留什么，什么往后做

| 首个正式 50 人版本需要 | 后续根据观察与数据再增加 |
| --- | --- |
| 有界无边的球面地表、创始流域和可结算的邻区移动。创始流域有基本地形、天气、水、植物动物与资源收支 | 更多区域的精细生态、远洋航行、更多物种、长气候循环和细粒度流体 |
| 局部身体、疾病与简化生命周期、可实际照料后代 | 更细器官、遗传、流行病和经数据校准的长期人口模型 |
| 每人状态、有限记忆、按需思考、常用行动与计划 | 更丰富的认知差异、经验证的语义检索、复杂长期规划 |
| 可表达的社会交流、合作冲突、主张与规范；基础加工、学习和记录传播 | 更复杂的制度表达、材料体系和工序；多文化/长期传播研究 |
| 运行控制、观察访问、预算控制、一致保存、备份与恢复 | 持续大规模运行与大容量归档优化 |
| 观察面板显示总览、人物、可用的事实与记忆、费用和 08:00 日报。地图可用位置表 | 三维画面、复杂地图动画、自动叙事、高级群体图和跨实验统计 |

不推迟决定、事实与记忆的隔离，不推迟正确时间、可恢复性和预算保护。可以延后画面精度、叙述美观和规模扩展。更大地图、更多模型请求或更细物理不会自动提高实验可信度，优先修复已经观察到的信息、行动或资源问题。

## 9. 如何避免每扩一次规模就推倒重来

- 各阶段复用相同的角色身份、动作协议、调度、持久化和观察数据。通过场景规模、允许的动作与冻结参数定义调试范围，不让不同规模走一套偷省资源或权限检查的捷径。
- 新机制先有明确的规则与可复查场景，再加入正式版本。某种想法若尚无足够物理表达，保存能力边界；不让模型填补结果，也不为了让试验顺滑而临时跳过相关人。
- 先测瓶颈。若慢在真实请求等待，优先检查唤醒与上下文开销；若慢在状态更新或查询，先定位过程和索引。改变认知节奏、规则精度或模型会影响历史，需要新实验，而不作为同一世界的隐形提速。
