# AI 时间推进与调度设计 v0.2

> 基于 Survivalcraft 的目标设计，尚不表示已实现。游戏复用范围、根本驱动力和运行额度以[设计总览](./AI部落文明模拟-设计草案.md)为准；专题中的新增机制按能力清单逐项接入，不要求先重建一套世界。

## 1. 本次确定的调度方案

使用同一个模拟时钟统筹世界、50 人、动物和物品。结合事件队列与有界的连续过程推进；只有需要思考的个人进入模型请求队列。某个模拟时点的必要请求尚未齐备时，整个世界的模拟时间保持不变，监控和网络任务仍可运行。

这是优先保证一致性和可追溯性的首版方案。它会让一个慢请求拖慢现实中的运行速度，但不会让请求较慢的人在模拟世界里多挨饿、少行动或比他人更迟看见同一时点的信息。

本方案细化《AI 个体状态设计》《AI 个体行动与模型交互设计》和《AI 世界状态与自然演化设计》。数值、认知时长和更新步长是待验证的实验参数，不宣称复现真实人脑。

## 2. 两种时间与一种速度

| 概念 | 用途 | 禁止混用 |
| --- | --- | --- |
| 模拟时间 | 世界中的日期、移动、代谢、天气、记忆与成长 | 不按 API 排队或响应耗时直接增加 |
| 现实时间 | 请求超时、限流等待、重试间隔、运行器耗时和界面刷新 | 不作为角色年龄、思考速度或生理消耗 |
| 运行速度 | 实际推进的模拟时长与现实耗时之比 | 不保证总能达到指定倍率 |

AI 事件时间使用整数刻度，初始候选精度为秒；游戏的逐帧浮点时间、睡眠倍速和暂停需映射到同一推进边界，不能直接舍入后丢掉物理帧或另造一套身体时间。具体精度待适配验证。角色思考所占模拟时间，由实验配置和认知参数预先确定；不是服务器用了多久，也不按输出 token 数临时决定。每次主要思考的模拟耗时为正；首版采用简单、可记录的时长模型，具体值由后续方案确定。

面板同时显示模拟时间、现实运行耗时、等待原因和实际倍率。调快速度只减少人为节奏等待、加快处理相同事件；不缩短世界中的路程、饥饿过程或个人思考时长。

## 3. 首版只有一个世界推进者

单个运行器拥有推进时钟、结算状态和提交事件的权限。模型请求可以有限并发，结果只进入候选区；模型工作任务、监控查询和数据库返回都不能自行推动世界或执行角色动作。

运行器状态区分：初始化、推进世界、在某时点准备决策、等待模型、安装待完成决定、用户暂停、故障/预算暂停、结束。监控可以在等待或暂停时继续读取已提交状态；关闭面板不改变运行器状态。

首版不使用预测未来再回滚的运行方式，也不按服务器请求各自的现实返回时间直接安排行动。

## 4. 事件队列里有什么

| 事件 | 谁安排 | 发生时怎样处理 |
| --- | --- | --- |
| 行动阶段检查或完成 | 行动执行器 | 检查真实进度、资源和中断，结算已经发生的后果 |
| 身体或环境检查 | 相应过程模型 | 推进到当前时刻，检测阈值和状态变化 |
| 天气阶段改变、发芽等 | 固定自然过程 | 更新当前及后续区间的条件，不能自动生成剧情 |
| 消息到达 | 空间与交流过程 | 只把已经发出的可接收内容送入对应个人感知 |
| 个体计划回顾、基础唤醒 | 本人的既有安排或认知机制 | 检查本人是否有能力思考，合并为待思考请求 |
| 思考准备完成 | 决策调度器 | 尝试安装之前快照产生的决定并开始其可行动作 |
| 生命周期事件 | 生理与人口过程 | 更新真实身体或人口，按个人感知生成后果 |

每项保存发生时点、类别/结算阶段、关联对象、有效序号、来源、取消状态和恢复所需数据。队列排序用于确定处理批次，不直接决定资源归谁；同一时刻涉及同一资源的意图必须集中结算，不能简单按个体编号依次兑现。

未来事件队列属于运行器，不作为角色可查询的预言。一个人知道自己的打算，不代表他知道尚未发生的天气或别人的决定。

## 5. 从一个模拟时刻推进到下一个

运行器选择最近事件、过程最大允许步长或已知阈值中最早的边界。对到达该边界前的区间，联合推进正在进行的动作、身体、动物与自然过程。

如果积分途中发现资源更早耗尽、行动更早中断、出现新的接触或身体阈值，应停在最早可表达的时点，重新划分后续区间。不得先发布未来状态再声称早先已经反应。整数时间精度和误差容限在版本内固定。

慢过程可以在满足误差与事件约束时累计更新，但参与交互前必须更新到同一模拟时刻。天气暴露、容器环境改变等中间历史不能被结束时的单一状态替代。

人或动物暂时不思考时，既定动作和身体继续参与这些计算。不存在“只有获得 API 的人才开始代谢”的情况。

## 6. 同一模拟时刻的固定处理次序

以下为首版阶段契约，数值求解和各动作的内部细节仍须在实现计划中确定：

1. **把上一段过程推进到当前时刻。** 对持续动作、身体、生态等使用共同的时间区间与资源约束，提交已发生的状态差量。
2. **结算当前到期的事实事件。** 包括行动完成、自然阶段变化、消息到达、失能或死亡等。一个时间区间的消耗和产出只记一次；事件完成标记不能再次发放同样资源。事件在同刻有冲突时使用声明的阶段和联合规则。
3. **生成必要的感知并处理失效。** 更新短期缓冲、检测已有注意条件和身体约束。取消不能再完成的旧动作与决定，合并需回顾的理由。
4. **收集并统一处理本时点的待启动动作。** 来源包括以前思考在此刻准备完成的决定、既有计划的下一步或已声明分支，以及到期的动物控制器输出。先按决定身份和字段版本安装允许的心理更新与注意安排，再基于共同状态检查身体能力、接触、资源和互斥占用，联合结算启动。动作开始不等于完成；物理后果在实际过程时点产生，需要反应时安排后续事件。心理更新的生效不以身体动作必定成功为前提。
5. **固定本时点需思考的成员与各自观察。** 对真正仍需思考、且具备能力的成员，每人最多建立一个新的主要决策。取消已被完成决定覆盖的普通重复回顾，但保留尚未处理的新情况。保存一致的世界状态、个人版本与输入包。
6. **若存在必要模型请求，进入等待点。** 模拟时钟停在这里；结果齐备后只登记未来的思考完成事件，再选择下一个模拟边界。

行动完成处理器只登记可继续计划的待启动项，动物控制器也只提出动作，二者均不得直接扣资源或占用工具。待启动项保存来源决定/计划步骤/控制器事件、主体、最早开始时点、版本、所需能力、替换/延续关系和稳定去重键。同一人的新决定与旧计划续步冲突时，按明确的替换或兼容规则处理，不能双启动；纯计划游标跳转有有限步数，身体动作仍须正耗时。阶段 4 封闭本时点的启动集合后才统一求解，迟于该阶段产生的新事项进入最早允许的未来时点。

例如 A 此刻走到水源、其计划下一步是取水，B 的取水决定也在此刻准备完成，动物同刻接近饮水，三项均进入同一启动入口。持续中的取水按已发生进度结算，不能为凑齐新动作抹去真实先后。共享投入与实际效果采用[世界联合结算契约](./AI世界状态与自然演化设计.md)。

在阶段之间保留明确的提交标记；待启动项与计划游标变化一并持久化，恢复后不重复登记或执行同一阶段。刚开始的动作不能在同一零时间循环里完成、讲话和触发无穷次回应；有正耗时的动作及认知过程使后续结果进入未来时点。

同刻派生事件只能进入当前尚未提交或随后尚未执行的阶段，不能插回已经提交的阶段。当前阶段内相关物理约束须联合处理到一致后再提交；依赖后续感知和反应的事项进入最早允许的未来时点。不能以延迟事件为由先发布负库存或其他违反约束的状态。

## 7. 什么情况下调用模型

| 原因 | 如何产生 | 去重与边界 |
| --- | --- | --- |
| 个体安排的回顾时点到达 | 本人先前的决定 | 与其他理由合并 |
| 计划完成且没有可执行后续步骤 | 行动与计划执行器 | 不是每个细小动作完成都必然调用 |
| 计划前提失效且没有明确分支 | 真实行动反馈 | 只能依据本人可感知的变化或执行受阻 |
| 收到交流、注意到变化 | 已有注意条件和认知机制 | 不是任何一条消息或每次天气更新都立即调用 |
| 基础思考机会或最长间隔到达 | 初始认知模型 | 不强迫设定具体目标；睡眠或失能时按能力处理 |
| 可感知的紧急中断 | 本人既有条件或明确的基础感知机制 | 不能依据隐藏事件或程序对其人生价值的判断唤醒 |

同一时刻若一人同时遇到饥饿提醒、消息和计划结束，只得到一个合并输入包，不能因此发三次主要请求。原因、来源和被合并的事件均记录。

注意条件根据本人能够感知的信号检测，采用触发沿、事件编号与必要的冷却/合并机制，避免持续下雨导致每秒重复思考。新响应提出的注意安排在其思考完成、正式安装时才生效，不能倒过来影响更早的历史。

人可以主动安排探索、回想或较长回顾；这些安排不需要外部发生事故。执行器不会为了少调 API 自动替他作新的生活选择。

## 8. API 如何排队

C# 运行器维护一份世界时钟、每个人的任务与认知状态，以及共享的有界请求队列。游戏更新在同一模拟时段推进各人的移动和进食，相关共享资源交由统一阶段结算。网络任务负责请求和接收候选，模拟更新流程负责安装决定并修改游戏状态。

50 人短试建议以 10 个在途请求为初始配置，在账户额度允许时对照测试 20。按批次完成耗时、限流和重试情况选择实际配置。每个模拟时点形成一个封闭的必要决策批次，各请求使用该时点保存的个人观察，彼此独立。

启动请求前做组级预算预检，为全部必要请求及声明的有限修复策略预留或估计费用。若明显不足，不先发给少数人并让他们行动，而是保存并预算暂停。无法精确预估的接口保留余量并明确估计风险。

队列分批提交，返回结果逐个保存，但不逐个推进世界。所有必要成员都得到有效响应或系统选择技术暂停之前，这个时点不会结束。角色不因排在第 50 个而承受更多模拟时间消耗。

批次按动态人口建立，保存待处理顺序。优先派发尚未得到主要请求机会的成员，再处理可选追加回合。个人累计或每日调用数不作为资格条件，沿用已有的合并唤醒、最长思考间隔和身体条件。阶段预算暂停时保留全部待处理成员与有效响应，经授权续接运行额度后继续原批次。参见 [长期演进与人口扩展](./AI长期演进与人口扩展设计.md)。

请求数限制、token 限制、并发数和金额限制分别控制。限流等待与退避使用现实时间，世界时间仍保持原值。50 人同刻醒来可能产生 50 次请求，但不等于 50 个并发；平时只调用该时点真正需要思考的人。

显式回想可以在本人范围内返回额外记忆，再请求其完成本次决策；格式修复也可能增加请求。二者有独立的有限轮数和用量记录，仍属于当前个人决策，不唤醒其他人，也不取得同批他人的结果。

并发只服务同一模拟时点的必要批次，不能提前请求依赖未来观察的决定。长期错峰唤醒可能使多数批次只有一人；提高并发上限不会自动缩短这些串行等待。压测同时覆盖全员同刻、长期错峰和交流连锁唤醒，记录批次大小分布、单人批次占比、实际在途数、批次墙钟耗时、模型等待/内核计算/持久化耗时，以及每模拟日的请求量、费用和推进速度。

量级示例：若一天 1,000 次请求分别属于不同等待点，每次耗时 10 秒且无额外回合，仅模型等待约需现实 2.8 小时/模拟日，30 日约 83 小时。这不是实测或性能承诺；正式窗口依据实际轨迹测量制定。先优化不改变输入和事实的连接复用、查询与输入组装、持久化及已有结果复用；不能延迟人物反应来凑批。改变思考频率、计划能力或上下文取舍须新建实验配置，已有计划和同刻重复唤醒的合并按冻结规则执行。

## 9. 等待结束后：思考耗时怎样发生

假设个体在模拟时刻 T 获得观察，其预设本次思考耗时为 D。网络等待发生在现实中；响应齐备后，记录其决定“在 T+D 准备完成”。在 T 到 T+D 的模拟区间，其他过程照常按事件推进。

模型返回的行动和候选心理变化在等待时不成为已完成的思想或身体效果；在准备完成时校验并安装。若从观察后发生正常饥饿变化或无关世界提交，不因此把响应全部判为过期。到实际开始时重新验证行动条件。

候选心理更新按字段和所属版本合并，不覆盖整个人。身体事实与运行器已推进的状态不能被旧值倒写；允许的独立记忆追加或有明确定义的变化操作可以合并。真正冲突的字段不静默覆盖，记录拒绝并留待后续正常回顾，不因此无限追加模型请求。界面明确区分尚未准备完成的候选与已生效的打算，不能提前宣告角色已经完成决定或行动。

同一人最多有一个尚未完成的主要决定。思考期间，已有简单动作是否可以继续，由动作与注意兼容性规则声明；需要中断的精细操作在过程边界暂停。新决定要替换旧动作时，明确取消、保留或延续，不能默默并行占用同一能力。

普通新感知进入短期缓冲，不立即无限重调。若本人原有注意机制判定需要紧急重考虑，可取消尚未安装的旧决定，合并新情况并在允许的下一反应时点建立新决策。取消的输出仅留审计，不自动进入角色记忆；已有真实动作后果不回滚。

取消与再次唤醒也遵守最小认知间隔和同刻一次主要决策，不能通过零时间自我唤醒制造无限调用。真实失能或死亡会取消不再具备能力的决定与动作，不能靠延迟响应继续活动。

## 10. 多人交流与同时竞争

讲话具有模拟中的持续过程，消息只有在实际发出并满足传播与接收条件后才能送达；内容不能在说出口前就进入对方上下文。若采用分段传播，各段都必须有发生时间，未说出的余下内容不能因中断提前送出。

收到讲话只进入感知，再由注意与思考安排决定何时回应。回应需要对方自己的决策，通常发生在更晚的模拟时刻，而不是在一个 API 响应里生成双方完整对话。

同刻的采集、取水、接触、共同搬运和交接按共同状态结算。API 提交、数据库遍历、个体编号和请求返回顺序不能决定谁先获得资源；物理时间差、动作条件与声明的随机竞争规则可以产生差异。

各自决定在不同模拟时刻准备完成，可能在现实中完成请求的次序不同，但世界只依据模拟中的准备与行动时点。较慢的认知参数可以影响个人反应速度，较慢的 API 不能。

## 11. 超时、错误与技术暂停

单次请求设置现实中的超时、有限重试与整批等待边界。暂时限流可以在边界内等待；格式错误可有限修复；耗尽策略后暂停世界，不能把失败角色跳过、自动替他选生活策略或换用另一模型而不声明。

已返回的有效结果保留，未解决成员继续处于当前批次；不会先让已返回成员执行。恢复时只补齐缺失项。结果不明的外部超时可能已经计费，供应商未明确保证时不能承诺重试只收费一次；内部仍保证相同决定和动作效果不重复提交。

日志写入失败、磁盘余量不足、发现无法表达的物理作用或无法保持一致性时，在已知一致提交边界停止。不让一部分身体或资源继续运行、另一部分冻结。API 用量和运行状态可继续记录，但不伪装成角色世界事件。

本轮费用与容量边界统一引用[设计总览第 6 节](./AI部落文明模拟-设计草案.md#6-本轮运行额度与暂停)。不设置个人调用总额或日配额；并发、供应商节流、单次输出长度和技术重试边界仍是必要的运行控制。额度不足时暂停整个世界，不用规则人格继续代替本人选择。

模型网络工作不得同步阻塞游戏主线程。候选通过队列回到受控模拟入口；等待必要决定时冻结游戏中的时间、身体、天气和动作推进，但渲染、摄像头与网络任务仍可更新。需要适配原生菜单暂停和睡眠倍速，不能把旧独立模拟器的事件队列直接当作游戏已实现的调度器。

## 12. 用户暂停、继续和速度控制

暂停命令使用现实控制通道，等待模型时也能处理。收到后停止派发新请求，在可控边界保存当前状态。已有请求可能仍在供应商计算，取消不保证免单；已收到结果缓存，不必在继续时重发。

若暂停发生在未完成的决策批次，恢复仍使用相同的时点、观察包和决策序号，只补必要缺项。若没有待完成批次，则从已提交的事件阶段继续。人类在现实中离开一晚，不使世界自动过去一晚。

加速不跳过思考、行动或自然事件。为了提速改变模型、认知频率、事件粒度或自然过程近似，属于实验配置变化，需要新的规则/实验版本。首版接受 API 限制导致实际速度低于期望值，不通过补跳世界时间追赶现实。

## 13. 保存与恢复需要什么

保存：模拟时间、当前处理阶段、世界与个人版本、事件队列、动作进度、各自然过程上次更新时间、全部随机流、感知缓冲、注意订阅、个人计划、未完成决定、当前决策批次、精确输入包、请求/响应状态、已经提交的效果及预算账。

世界版本、个人版本和决策序号分开。模型请求状态的后台更新不应改变角色可感知的世界事实。恢复前判断最后一个成功提交阶段，避免重复积分、重复取水或再送一遍消息。

同样的种子不保证重新调用模型得到相同答案。回放使用保存的决定与事件；比较不同并发数的调度一致性时，也应重放同一组决定，而不是把模型采样差异当作调度错误。

随机求样绑定稳定的自然过程、接触/竞争事件或固定求样时点，不绑定本次调度循环跑了几次。因为多一次思考而额外切分计算区间时，重用原有随机驱动或按规定的条件过程推进，不能重新抽一场天气。过程内部序号与已求样结果随恢复点保存。

## 14. 具体时间线

以下为虚构示例，假设阿木、阿禾本次思考各需 5 个模拟秒；这只是演示参数。

| 模拟时刻 | 世界与人 | API 与现实等待 |
| --- | --- | --- |
| 08:00:00 | 两人需要思考，其他 48 人处于各自既有状态；保存两人的不同观察 | 两次请求进入队列；等待期间时间保持 08:00:00 |
| 08:00:00（等待完成） | 暂不执行返回的行动 | 结果保存，安排 08:00:05 准备完成 |
| 08:00:05 | 在此前 5 秒的身体和自然变化已结算后，检查并启动各自行动 | 不因开始移动或采集再调用一次模型 |
| 08:01:00 | 降雨阶段改变，所有相关地表、物品、身体和行动更新；不需要思考的人继续 | 若没有新的必要决策，不发请求 |
| 08:02:00 | 阿木的路线受阻，且没有已给定分支，需要重考虑；其他人当时状态保持一致 | 只为阿木建立请求；网络等待仍停在 08:02:00 |
| 08:02:05 | 阿木的新决定准备完成并重新检查前提；世界继续推进 | 其他人不因刚才现实中等待较久而多疲劳 |

如果 08:00 恰有 50 人都需要思考，运行器从同一个已提交世界版本生成 50 份个人输入。单次响应耗时相近且接口速率充足时，10 并发约需 5 轮请求的时间，20 并发约需 3 轮。有空位就派发下一项。若另一次有 48 人继续既有计划、2 人需要判断，只创建这 2 人的请求。

例如阿木和阿禾的拾取动作实际在同一时刻接触同一份食物。结算器同时核对双方的有效接触与可用余量，按冻结的竞争规则处理。真实先接触者可以先取得，完全同刻且条件等价时使用登记的平局规则。用固定输入、决定和随机键颠倒 API 返回顺序，两人的资源结果须保持一致。

## 15. 设计验收与剩余参数

重点场景：50 人同刻唤醒；同一人多个理由去重；慢响应不改变资源先后；限流/超时不推进年龄；思考期间出现新感知；普通身体变化不误杀有效响应；失能或死亡使未安装行动失效；连续对话不能在零时间无限发生；暂停中保留已返回决定；恢复不重复过程；慢更新不跳过早期阈值。

实现计划须把同刻阶段细节、动作兼容矩阵、注意条件表达、最小反应间隔、各类思考耗时和数值阈值求解固定下来。这些主要由构建者提出可检查的默认值，不要求用户给 50 人逐个排生活日程。真正的首版取舍是：为保持一致性，必要模型请求会阻塞世界的现实运行速度。

## 16. Windows 游戏版首轮接入方案

以下为本轮候选实现与验收边界。正式实验额度沿用[设计总览](./AI部落文明模拟-设计草案.md#6-本轮运行额度与暂停)。先用已有原生角色和固定响应验证 2–5 人的调度，再接入独立人物和真实请求。现有 `ActorModelTurn` 已验证单人冻结后提交，作为接口参考。多人批次通过 `IActorDecisionSource` 收候选响应，由全局调度统一安排提交。

### 16.1 每个模拟边界的批次

1. **结算上一子步，再收集唤醒。** 世界运行器在每个原生子步末尾接收已结算的动作反馈和送达消息，按第 6 节收集到期决定、计划续步与已启用的其他动作来源，统一检查启动后，再按第 7 节检查谁确实需要想。现有任务调度器在原生更新列表里自行开始待执行步骤，接入全局阶段时要将受管任务的启动移到这个入口。人物登记表按稳定身份维护，已有待安装决定的人只有在明确的紧急中断规则生效后才允许另起决定。继续执行现有步骤且没有新触发的人不会派发请求。
2. **封住这个时点的成员和输入。** 在同一世界阶段调用各人的认知接口，捕获本人的观察、触发理由、任务、个人版本和动作协议。为这一组分配 `batch_id`，为每人分配 `decision_id`，持久保存实际送出的输入。新消息在其实际送达的模拟时点进入下一批，不按现实时间凑批。并发只覆盖当前批次。
3. **整批预检，再有限派发。** 按候选默认值同时允许 2 个在途请求。初测用 1 与 2 对照。首轮只启用主要请求和有限传输重试，显式回想和格式修复待有独立上限及预留后启用。提供方请求速率和在途槽按现实时间计算。返回结果可乱序保存，人物只获得自己的候选决定。
4. **收齐后安排准备完成。** 先按输入快照检查结构、动作协议及引用权限，全部必要成员有效后登记 `T+D`。小场景的候选默认值为 `D = 1` 模拟秒，按第一个不早于到期时间的原生子步边界生效，记录计划时点与实际时点。安装前再次核对人物存活、决定版本和动作现场条件。同刻待开始动作沿用第 6 节统一启动规则，资源归属与 API 返回顺序无关。

认知接口需要分开“准备输入”“验证候选”“到时安装”。现有单人 `CommitTurn` 按冻结时点校验身体和任务，适合直连夹具。接入 `T+D` 时，先按个人字段版本安装仍有效的心理更新，再把行动提案加入同刻待启动集合。动作受阻不抹去独立有效的记忆或心理更新。普通身体变化可继续，游戏线程按决定版本和必要中断过滤失效部分，封闭启动集合后统一检查前提与分配资源。原生动物等未接入该阶段时，早期夹具使用互不争夺资源的场景，同刻联合结算单独验收。网络线程只提交候选、技术错误和用量记录。

### 16.2 世界暂停与恢复

暂停由世界运行器持有。游戏版在 [SubsystemUpdate](../../game/Survivalcraft/Subsystem/SubsystemUpdate.cs) 的原生子步边界设推进门，睡眠倍速一帧执行多步时也在每个子步前检查。等待期间跳过整轮世界更新及会改变世界的延迟回调，覆盖 [GameManager](../../game/Survivalcraft/Managers/GameManager.cs) 的同步队列。只把 `dt` 设为零仍会执行原生更新器，因此不足以作为冻结判定。挂起前须确认会写入模拟状态的后台工作已到安全边界，原生自动保存只能使用已确认的一致状态。

渲染、观察相机、界面控制、网络收包和账本继续处理现实事件。世界时间、角色动作和代谢、动物、天气、掉落物及消息送达停在同一时点。相机相关区块请求与模拟所需区块分开验收。恢复推进时重置帧计时起点，等待期间不累积补算时间。

等待模型、用户暂停、预算暂停、故障暂停各有自己的原因。模型结果齐备只解除等待模型这一项。用户暂停期间停止派发新请求，已返回的有效结果和用量照常入账。限流可按 `Retry-After` 在墙钟截止时间内恢复，首版每个调用至多一次明确可重试的追加尝试，须已预留费用。单次沿用适配器的 30 秒超时，首版每次连续派发窗口最多 120 现实秒。主动继续、追加额度或从检查点恢复会重开等待窗口，尝试次数和费用记录沿用原批次。发送结果不明或超时的请求先标为可能已计费，暂停等待核对或明确授权续接。有效响应保留在原批次。

### 16.3 请求账本与额度检查

请求账本独立于游戏存档回退。小规模首版用独占文件锁和同卷原子发布 JSON 文件，SQLite 留作大规模增量账本候选。人物资料和模型原始输入输出留在本机受控运行目录。每次实际派发前先记录发送意图，绑定 `experiment_id`、`batch_id`、`decision_id`、`call_id`、`attempt_id`、人物、模拟时点、模型、供应商、限额和价格表版本。响应补记供应商请求 ID、现实发送与返回时刻、状态、输入、缓存输入、输出等用量、已知费用与数据来源。每次尝试独立计费。格式校验不通过、决定后来被取消，也保留其已发生用量。

异步观察的账本快照由单个后台写入任务分批发布。游戏线程仅在确认发送意图已持久化后发请求，在确认用量结算已持久化后采用候选。重开账本时保留已知费用和未知负债，发送结果不明的尝试不自动重发。异步观察账目与冻结批次的世界检查点各有恢复入口。

按不重叠的类别汇总额度，金额使用整数最小记账单位并向上取整预留：

```text
本地可分配额度 = 本轮额度
                - 已发生费用（含已知用量估计）
                - 未发送预留
                - 在途预留
                - 结果不明的费用负债
```

一次尝试从未发送预留转为在途，收到 usage 后按同一 ID 移到已知用量，供应商对账后补记差额。超时或崩溃后处于发送不明的尝试移到未知负债，不能自动算零。同一笔预留或已知用量只计入一处。换供应商时按该端点的版本化价格和计费字段计算，当前适配器只给输入和输出总 token，按普通输入价格预留。增加细分用量后才按明确的缓存用量对账。缺少价格或无法估计的必要计费项会阻止派发。输入按系统说明、动作协议和个人上下文组成的完整请求估算。输出硬上限和风险余量也计入预留，供应商结算作为实际费用依据。启用本轮账本前核对已有真实接入测试的用量和费用归属。

预检把全批必要调用、已启用追加回合和重试全部纳入；单次派发前再次确认预留与磁盘余量可用。额度不足整批停在原时点，追加额度后沿用原批次和有效响应。暂停、重启或读旧世界不会减掉已经产生的费用。本地估算能控制新请求，外部账单硬上限需要供应商或账户提供相应保证。

### 16.4 交付顺序

| 阶段 | 可验证交付 |
| --- | --- |
| 本机调度 | 2–5 名原生测试角色共用一个推进门。覆盖只为有触发的人派发、同人多理由合并、1 与 2 并发的乱序对照，以及暂停期间仍能观察。用固定候选核对 T+D 和实际动作。 |
| 账本和恢复 | 用模拟提供方注入 429、未知用量、预算不足、暂停和进程退出。先完成并校验世界检查点，再在账本里提交检查点标识、冻结批次和预留，随后才派发。每条候选与用量持久化后才能用于解冻。重启时先核对世界检查点 ID 与账本中的批次绑定。两者匹配才复用已保存响应并补齐必要缺项，处于发送不明的尝试保留为未知负债，不自动重发。读较早世界或检查点不匹配时保留账本，走恢复核对或明确的新分支。 |
| 50 人固定响应 | 在同一进程和世界验证同刻全员请求、错峰复查、等待冻结和整批预算门槛。实测与复现见[全局认知调度夹具](../development/开发与验证.md#全局认知调度夹具)。 |
| 50 人单轮动作 | 在同一世界以 15 为请求并发上限。对照模型输出、任务终态与身体实际运动，验证等待冻结、回包安装、账本结算和动作执行。 |
| 50 人多轮动作 | 保留同一世界和角色状态，按任务结束及错峰复查开启后续批次。在动作可保存时冻结世界，并按预设的模拟时长与费用上限收尾。 |
| 50 人觅食 | 给角色不同的初始饱食度和实际可取的食物。记录模型选择、移动与拾取消费的游戏结果、资源余额和饱食度变化。 |
| 异步观察 | 世界照常推进。任务提交、任务结束与模型回包进入事件队列，由游戏线程在推进边界处理。后续任务等当前任务成功才可接上，交接和动作开始时按现场校验。在连续 60 秒的现实窗口内记录排队时间、提前派发量、每帧调度与落盘耗时，以及同一角色在自己的请求仍在途时的实际行动。 |
| 小规模真实验证 | 多人一致检查点覆盖当前启用的任务和个人状态后，才开放真实多人批次。首版多人归档要求角色处于可保存的动作间边界，决定仅使用可跨重启的动作子集。续跑从最近持久化的冻结时点恢复，之后尚未持久化的推进会从该点重新演算。在途动作及会话引用的恢复须另验。 |

首轮验收同时比较模拟时间、任务游标、库存、身体状态、消息与账本。暂停状态用这些实际量核验。调度顺序变了而固定候选一致时，核对世界结果一致。预算、重启、同时竞争及相机边界详见[验收设计](./AI测试验收与演化证据设计.md#5-时间调度和预算验收)。
