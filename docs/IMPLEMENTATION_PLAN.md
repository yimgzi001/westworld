# 实施路线与当前状态

更新于 2026-11-11。总体架构沿用 [ADR-001](design/ADR-001-SCAPI单世界多智能体架构.md)，下面新增生存目标重构的当前状态。

## 当前开发批次

- 新增地下工作站与坑内返程修正：感知摘要明确站点高差、楼层、原生可交互状态和已证明台阶；返回工作站先规划三维可达中继点，最后再核对同层交互。上阶先稳住朝向和侧向惯性，接触缺失时不丢失起跳。场景、边界与验证见[三维导航与分层感知](development/三维导航与分层感知.md)。
- 按用户本轮收尾要求完成 R93 十四项原生回归，全部通过且更新异常为零，覆盖上下层工作站、连续返程、完整采石造炉进食、封堵对照及水面回收。旧自然场正常保存，新版可见单人场按冻结源码运行；整理本轮代码与记录后提交到 `cjh`，十天与稳定供食仍待自然结果。

- 最新补充聚焦水边与猎获交接：参考 Minecraft 机器人 Mineflayer 的带代价路径和目标持续机制，实现已见水面与干地的局部寻路、连续上岸、直线水路续接、累计漂移重选路线和原生拾取确认；取肉后带回干地，危险与遮挡按实际反馈中止。另补无出口、漂移、遮挡与新威胁对照，见[水边导航与猎获回收](development/水边导航与猎获回收.md)。
- 用户再次提供岸边绕圈画面后，进一步将巡猎改为先选已见连通干地上的终点，阻断失败段自动续行；精确诊断确认原生瞬时地面接触丢失触发高频中断，增加暂停输入的短接触恢复窗口，持续缺失与实际落下仍中断。追加水湾、惯性、单帧及持续接触缺失回归，并在新的可见自然场检查实际失败频率。

- 用户重新开启可见试玩后反馈往返摆头、备料不足与策略缺少环境取舍。本轮先修已知食物打断巡猎和终点短路线高频续接，再补可选木材储备与环境资源建议；正常目标默认延续，危险与迫近生存危机优先。原生针对性验证通过后再开带画面的新版单人场。

- 普通生存由模型安排一至四步，并保留长期意图。正常补粮、工具与固定住所的发展顺序交给 AI，代码负责连续技能、原生结果核对及真正紧急的安全处理。[生存策略知识](development/生存策略知识.md) 已对应接入模型请求的情境建议。
- 本批加入原生移动鸟投猎与拾肉、平地采石和石斧、炉具熟食溯源、南瓜留种播种、二乘二固定土屋、返回本人旧工作站、着火感知和撤离。原生受控回归与自然长测分别报告，不能互相替代。
- 继续修复首炉加工链：增加由 AI 选择的有深度上限浅探，保留阶梯与耕地；处理草花挡住工作站操作、遮挡后的分段返程和低处掉落的拾取终点。旧营火增加已见火势、原生添柴与连续晾干回暖。当前以完整入包、可操作站位和真实进食验收。
- 真实场继续反馈后，增加指定已见投矛回收、制作前接近本人工作站；浅探扩到最多六格并先核对反向跳回净空、逐级返程。极低饱食的生肉只作保留原生风险的应急兜底。控制场景通过、自然供食不足和自然死亡分别记录。
- 进一步修正采集交接：库存达到目标后仍完成当前原生台阶并站稳，不在半空交给制作；掉落不可达时有限换目标，保留已有材料。旧工作台太远时可由模型选择就地做新台。自然 R57 场已实际吃到首份本场烤制的熟鸟肉，仍未证明持续供食或当前版本十天通过。
- 当前补充批次针对外出后的返程：让 AI 能选择回到较远的本人营地或工作站，每段仍重新核对实际地形与危险，只有原生进入、封门或可操作站位才完成；提供距离与耗时估计，失败、站点变化和无进展要能及时停止。先验证远站、返营、站点消失与路线受阻，再用于独立自然场。
- 已补首块石料的动作覆盖：已见但不在手边的岩石可单独取一块，落低后先带回出发地面，再由模型选择制斧或继续采八块。最终两次取样—返回—原生制斧与一次遮挡对照全部通过；发展顺序仍交给模型。
- 此前按用户“最后一轮，测完推送，就先这样”的要求完成首块石料批次并正常保存退出；其后用户重新开启可见试玩并追加导航、目标持续与备料要求，按最新补充继续开发。十天目标与稳定供食仍标为未完成。

## 目标与固定约束
- 一个持续运行的生存战争权威世界。AI无视口，经接口控制不同完整生存角色；人类视口可选。
- 模型做较低频规划，本地技能持续执行，推理不阻塞游戏线程。不能用每格调用模型或无限移动假装自然。
- 各自局部感知、性格和私有记忆；合作靠有证据的目标/任务/交付，而非聊天数量。
- 先打好地基，再逐级测10/20/50。容量常量或五角色实验不能证明50人可用。
- 朋友在main的设计保留作目标参考。实时模式优先；“等所有模型完成再推进世界”的研究锁步另行设计，不混称已兼容。
- 开发测试使用用户授权的工作区和独立测试世界。每个验证后的批次同步源码、可复用测试与简明记录，提交到 cjh。

## 接下来的完整验收步骤

### 1. 运行宿主与恢复边界
将实验中的手动装配收敛成可运行宿主：角色生命周期、ActorRegistry与原生PlayerIndex映射、活动中心接管/释放、世界与角色/技能检查点共同保存。
验收：同世界重启后身份保持；旧session拒绝新执行、已结算结果可对账；暂停/异常/移除不残留动作或区块中心，不重复物品结算。尚未做到的持久化不能靠内存票据宣称幂等。

### 2. 单角色有用生存闭环
先定义技能前提、资源占用、取消、部分完成和后置证据，再做“发现资源→接近→采集→拾取→制作/取得食物→改善真实生存值”。
验收：世界格子、背包和生存值都能对应动作账；挖掉不等于已拾取，模型说成功不算证据。加入慢/失败模型时本地技能不阻塞、动作能及时撤销。
已完成初始背包熟鱼进食；随后按[局部觅食目标契约](design/局部觅食目标执行契约.md)验证单父任务的接近→原生挖掘→自然拾取→食用完整链。南瓜属于明确人工布置夹具、提供器仍是延迟替身；不能称自然自主生存。已接授权本地Qwen3.5-4B Q4_K_M完成真实选择及修复后复测，推理/资源与新观察重验均记录；下一步先对照新增main实现规划复用，避免重复架构，再推进自然资源探索、共享推理与宿主持久化。
模型接入需明确可用授权凭据、型号和真实调用；已完成两轮本地模型真实调用，无外部API；费用为零API支出但有本机算力成本，不能由单轮外推并发规模。异步调度已具备有界并发、超时退役和结果作用域校验；提供器实现不等于真实模型可用。

### 3. 两至四角色真实合作
不同人格/私有记忆与共享任务事实分层，任务包含认领、依赖、交付与验收。队长制是可换策略，不先写死社会结构。
验收：共同目标产生可查的实体交付，而非不断互相聊天；信息只来自实际感知/收到的消息，避免全知任务账泄漏。

### 4. 逐级负载与长时恢复
完成前面闭环后再测10、20、50活跃角色，覆盖聚集与分散区块、0/1人类视口，持续运行及模型断连/重连。
记录CPU单核tick p95/p99、RSS/托管堆增长、活动区块并集、成功率/无进展时长；模型输入/缓存/输出token、真实延迟及当时价格对应费用。
云模型去掉本地推理负载，不等于GPU/内存为零；必须区分模拟、图形初始化、单一人类渲染和模型费用。

## 当前风险/决策账
- 零AI视口已经验证，但仍保留原生图形初始化和脱树GUI值控件，不能称完全无图形。
- 当前局部观察使用保守不透明体素遮挡，不是像素级视野；unknown不泄漏原因。观察只读已加载区块。
- 现有NativeActorSession是游戏线程内可信宿主接口，不是有身份验证的远程API；公开前必须加调用者角色范围。
- 票据目前有界且仅在内存，重启恢复/满额压力仍待验证。满额拒绝，不偷偷清空。
- 取消清除控制不等于冻结物理。惯性/碰撞/重力仍归游戏；以明确停止证据和超时结果结算。
- 上游依赖漏洞告警与OpenAL错误已有记录，不能隐藏为零告警。处理时应单独验证兼容性，不混进无关玩法改动。
- 凭据、运行存档、模型原始账本、依赖及构建二进制不推仓库；必要证据用安全摘要保存。源码、测试、设计决策和重现说明随步骤提交。
