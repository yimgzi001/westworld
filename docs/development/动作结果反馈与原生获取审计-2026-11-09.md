## 27留下的证据

来源：`work/food27-terra/tool-agent.jsonl`。

第一轮模型选择 MoveTo，再 PickUp 同一可见掉落引用。移动后旧引用失效，宿主拒绝旧 PickUp，反馈为 `step_stale_or_invalid`。第二轮 prompt 已包含熟肉89×1、出生鱼162×1，以及 MoveTo 的 succeeded 状态，因此不能归因于“库存没有给模型”。但近期记录仍突出 MoveTo 的 running 受理回执，缺少醒目的库存0→1变化及未执行步骤说明。模型随后转头、探索，最终4次请求耗尽，41.4591615秒失败，更新异常为0。

原掉落数量降为0、移除标记为真且角色同值库存变为1时，时间为56764.842945999。来源不确定标记早在56762.910008459就置真，当时库存0、原掉落仍1。旧审计仅记录全局存在其他同值掉落，未记录竞争源位置与吸附对象。因此27证明库存增加和旧引用失效，但不能追溯改判为“唯一指定来源获取成功”，也没有完成进食。

## 决策：反馈与审计分两条链

### 面向模型的通用状态变化反馈

从该角色前后真实观察生成有限 Delta，而非每种任务编写固定剧本：

- 原计划目标、前序工具及收据身份。
- 前后观察ID、可观察的自身库存精确值与数量变化。
- 工具受理、真实终态、尚未执行或被撤销的步骤，分开表达。
- 引用消失、超距、失视与原生失败保持不同原因，不统称“没找到”。

如果旧拾取目标不可见而同值库存增加，应报告这两个事实。只有满足明确定义、证据充分的获取后置条件时，才报告该子目标已满足；不能据此自动宣布整个“获取并进食”目标完成。来源不明仍标不明。宿主不自动添加 Eat、不切换另一目标、不默默重放失效命令，模型根据更新后的状态自主选择后续工具。

同一动作的 running 受理与终态应关联为短摘要，避免旧受理状态压过新终态。保留有界近期失败和必要 Delta，预算截断必须可见；最终菜单继续从实际展示的事实生成。完整原始回执保留审计，不以摘要代替事实。

### 仅宿主使用的原生获取因果审计

原生自动拾取可能发生在移动过程中，无需显式 PickUp 成功。应分别记录“模型调用了什么”和“原生实际发生了什么”，不能因库存增加就宣称模型显式调用了拾取接口。

为来源归因关联原掉落实例与事件、数量变化、创建时间、吸附目标、移除及角色库存变化。新增同值来源记录独立审计ID、位置/距离、数量与归属信息。全局出现同值物品不自动等于本角色有竞争来源；但单纯固定近距筛选也不能排除采样间移动、合并或其他角色交付。证据不完整时保留 uncertain，不为通过测试放宽归因。

这些隐藏来源位置、其他角色的不可见状态与夹具标记只写审计，不进入模型视觉、记忆或工具引用。模型反馈只使用其合法观察与已验证的自身事件。人工熟肉掉落正控只能证明获取与进食闭环，不能称自然采集、狩猎或烹饪。

## 下一批验收矩阵（待完成）

1. **人工正控**：原生移动/自动拾取→库存增加→原生进食，分别核验获取来源、食物数量、饱食及原生统计事件；保留出生鱼，吃鱼不能算新增食物成功。
2. **真实模型**：同一公开观察与工具接口，让模型选择步骤。记录请求预算、原生结果及失败，不用确定性正控代替模型成功。
3. **旧引用反例**：自动拾取后旧目标失效时，反馈应说明库存变化和未执行步骤；目标消失但库存未增时不得报告获取满足。
4. **竞争来源**：远处无关同值、接近/吸附到本角色的同值、合并或归属不明分别记录。未知因果不得伪造唯一来源。
5. **事实与预算**：Delta、终态和原目标在有界上下文中正确关联；来源审计不泄漏到模型；被裁剪事实不留菜单权限。
6. **停止与取消**：普通/预取共用调用预算，截止后无新派发，取消后原生动作与请求排空，实际用量未知时不计为0。

最终报告需附真实日志、来源哈希及失败分类。本设计不是上述矩阵已经通过的声明。
