# 通用模型执行与连续技能整合路线

日期：2026-11-09。状态：**planned，尚未完成整合与原生验收**。

本文件记录下一阶段最小整合，不把已有纯测试、独立实验或原生单动作成功写成自主生存完成。遵循既有架构决策的默认实时模式：世界不等待模型；模型负责方向、阶段目标与调整，本地技能负责有界连续执行。不是新增固定觅食专家，不规定采集、造武器、狩猎、烹饪顺序。

## 1. 现状与缺口

- `experiments/scapi-tool-agent/Program.cs` 已连接本地模型、动态工具菜单、严格结构化解析、每步新观察及原生动作结果。其 `Update` 在等待原生动作或等待模型时分别提前返回。世界继续更新，但同一角色仍主要按“完成动作，再等待下一次决策”串行运行；有限步骤计划也只引用本轮已有事实，不能虚构前一步未来产物。
- 本轮模型推理出现每轮约 40～80 秒的等待；这不是已建立的性能保证，也不能用放宽停止条件来掩盖。单次短移动或近战攻击之后等模型，容易表现为停顿。
- 连续导航已在 `experiments/scapi-main-integration/Program.cs` 的实验状态机中组合验证，但尚未抽取成通用工具宿主可复用的完整技能。已有组件包括 `LocalRouteCandidates`、`ObservedStepRoutes`、`LocalNavigationAlignment`、`NavigationLookPlan`、`NavigationSettling`、`LocalExploration` 和局部记忆。
- 原生 `StepTo(Vector3 Destination, float Timeout = 3f)` 已存在于 `game/Survivalcraft/Westworld/Actions/AtomicAction.cs`，由 `AtomicActions.Movement.cs` 注册并在 `AtomicActions.Step.cs` 实现。当前 `ActorTools.Catalog` 与 `NativeToolOffers` 没有 `act_StepTo` 工具。不能把“底层有台阶动作”等同“当前通用模型已能连续越阶”。
- 当前 `WorldCognitionScheduler.Observation.cs` 已有 look-ahead、预留并发槽、`PrecedingTask` 关联和任务重验证。它不是早期的纯空闲角色调度；但也尚未与本地工具宿主、完整生存角色和连续导航完成统一集成。

## 2. 五项最小整合

### 2.1 抽取连续导航技能，不重造寻路

从已有实验状态机提取每角色独立的 `LocalNavigationSkill`（拟定名称），复用上述投影、对齐、台阶、主动观察、落稳、局部探索及失败退避组件。

模型选择当前已观察目标引用，或明确有界的相对探索意图；技能内部依据新观察决定短移动、对齐、台阶和停止，不让模型逐米指挥。提取时逐项保留原实验的证据校验和终止条件，不能把未知格当作空气或可走地面，也不宣称全局寻路。

### 2.2 统一所有者与生命周期，再暴露通用技能工具

拟提供启动、查询、取消连续技能的协议，或把现有移动工具适配为同一技能入口。具体名称在实现前确定，不要求直接公开任意世界坐标的 `StepTo`。

每个角色只保留一个权威执行所有者，复用宿主已有 `AtomicActions` / `ActorTools`，避免抽取实验时再创建一套动作注册器。原子动作、复合任务、连续技能之间必须显式仲裁：被取消或替换的旧任务不再写角色控制输入；重试先查已发生结果，不能盲目重复采集、转移或制作。生命周期随角色移除、死亡、取消及宿主释放收尾，清理只能释放自身拥有的资源。

### 2.3 有界近战技能，模型决定是否交战

在模型显式选择可见实体后，可新增 `EngageVisible`（拟定名称）技能，复用 `runtime/Westworld.Scapi.Adapter/LocalAttackReadiness.cs` 与原生攻击动作，局部执行朝向、合法接近、冷却和再次攻击。

这不是自动锁敌或自动狩猎策略。技能绑定原始角色作用域和实体身份，每次动作前重查可见性、距离及原生前提；失视、目标消失、阻塞、取消或期限耗尽则停止并报告。不得借用审计快照中的真实坐标追踪不可见目标。失视后是否搜索或放弃交给模型，不能偷换成另一只同名动物。

### 2.4 复用异步预规划账本，不等模型才走路

对照 `game/Survivalcraft/Westworld/Cognition/WorldCognitionScheduler.Observation.cs` 的 look-ahead 和 `PrecedingTask` 机制，将本地模型请求与当前技能关联。只有仍有效且未超过自身预算的旧技能可在推理期间继续；没有有效技能时允许明确等待，而不是无期限漫走。

请求携带角色、会话、观察、任务身份及必要版本。模型返回后在安全阶段边界取得新观察，核对前序任务、当前库存、目标引用和能力，再决定接纳、重新规划或丢弃。不能用延长旧观察 TTL 替代重验证，也不能因晚回复恢复已取消、失视或结束的任务。共享模型队列限制在途请求，避免每角色各起一份模型或每帧重复推理。

### 2.5 事件驱动反馈，不把每次挥击变成模型回合

模型收到阶段进展、完成、受阻、危险、目标丢失等有意义结果；常规帧更新、冷却和落稳由本地完成。事件可以合并，但不能隐去失败、部分完成或材料消耗。

统一记录 `planned / running / blocked / target_lost / cancelled / achieved` 等阶段状态，以及关联任务 ID、观察证据、真实位移、动作回执、终止原因和模型调用次数。具体状态枚举是待实现协议，不代表仓库已经具备。模型仍能选择储粮、制作、交战、探索、休息或其他已支持工具，宿主只过滤真实能力与前提，不替模型规定路线优先级。

## 3. 首个完整验收场景

在 dot 云电脑的隔离实验世界中，以一名完整生存角色进行以下连续场景，保护已有世界，不使用用户电脑：

1. 模型基于真实局部观察选择接近一个可见目标；记录原始输出、引用、阶段目标和技能预算。
2. 同一技能连续通过平地、局部转角及已观察上下台阶，使用复用组件，不额外注入全图路线。模型不逐格发令。
3. 对下一轮推理人为加入 30～60 秒等待，以验证执行与规划解耦。该延迟是故障注入，须与真实 4B 推理耗时分列；旧技能只在自身预算与证据持续有效时执行。
4. 在另一次重复场景遮挡或移除目标，或者加入真实障碍：失去当前证据即安全停止／报告受阻，不穿墙、不追踪审计坐标、不换目标。
5. 在停止或取消后交付旧模型结果：必须拒绝过期任务关联，不能重新启动旧目标。新请求只能根据新观察创建新的有效任务。
6. 记录动作连续性、无进展时间、模型请求次数、CPU／内存和终止证据；保存重载若未纳入本场景，明确列为后续验收，不能借既往结果默认通过。

先完成导航、停止和晚结果这一整链，再增加连续近战验收：冷却受尊重、只攻击原绑定且仍可见的目标、失视即停，击杀和拾取分别验收。原生烹饪或狩猎夹具成功不能替代模型选择阶段目标后的整链成功。

## 4. 交付与边界

当前交付仅为代码核对和整合路线。拟新增的是通用技能所有者、宿主接入、异步任务关联及整链验收，不是重写现有导航算法或另起食物专家系统。实现阶段按完整可验证场景成批开发、复用独立测试与原生证据，成功和失败均归档；阶段测试后审查并提交 cjh。未完成之前，不宣称角色已能在长模型延迟下持续自主生存，更不外推为 10～50 角色稳定运行。

## 6. 平地原生交接与事实去重批次

独立原生导航宿主已验证平地真实移动中的早回缓冲和交接、取消晚回、障碍场景证据过期以及段末200ms期限拒绝晚回。五份原始场景记录（含旧late01与修正late02）保留；均清理和更新检查通过。这里使用确定性延迟候选，真实4B运动重叠、台阶和自然地图尚未验证；也没有把实验宿主替换为通用模型主宿主。

ToolContextMemory去除重复配方实体、无损编码空槽，保留冲突/未知字段与历史库存变化。历史真实round2提示13333→10342字符；本地4B单次回放100.35秒获得JSON（4021输入tokens、平均3.86CPU核、RSS4.34GiB），原历史轮120秒超时。但回复只是跳跃/等待，不能说明获得有效制作计划。是离线历史观察推理，无游戏动作，单样本不保证稳定性能。
