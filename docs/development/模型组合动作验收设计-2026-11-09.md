# 模型组合动作验收设计

日期：2026-11-09；基线参考 cjh `02805413`。本文是整体宿主/model loop 的设计与验收约束。通用协议、会话账本与实验宿主已实现；不宣称模型自主狩猎已完成。

## 一、统一入口，不继续堆固定食物专家

让模型使用已有 ActorTools 观察、物品、配方、动作和任务能力。宿主负责真实状态、授权边界、并发、期限和结果，不替模型固定选择“先南瓜/先木棒/必须狩猎”。制作正控与狩猎正控是执行器证据，不应直接伪装成模型策略。

底层目录曾称 31 种，增加 Step 后有 32 种；实际以 `GetCapabilities`/`DescribeToolsJson` 动态目录为准。目录存在不等于全部能力已通过原生验收。工具含查询、任务和原子动作，不能把工具数量与原子能力数量混用。

### 最小 gateway 契约（当前实现与后续边界）

当前执行封套：`sessionId, actorId, sequence, tool, arguments, readOnly, stopOnly`。会话由宿主新建，充当本轮 epoch；决策协议另外绑定 `sessionId/actorId/observationId`，执行前重验。独立可跨进程恢复的 worldEpoch/decisionId 持久账本尚未实现。

- 工具及参数 schema 来自同一 ActorTools 实例，不再生成一份手写平行工具表。
- 当前模型一次输出 0～4 个有序工具步骤，宿主逐步执行、逐步刷新验证，动作与任务必须结束才推进后续步骤。不能预先引用尚未产生的结果。原生 `submit_plan` 仍存在，但不等于本实验已将其开放给模型或完成验收。不能输出任意代码、私自构造 Entity/Inventory 句柄。
- 决策异步运行，游戏线程完成封套校验和 `InvokeJson`；模型线程不得直接读写原生对象。
- 每角色同一时间仅一个写动作/任务。后台查询可按原生约束运行，不能为了观察偷偷取消活动任务。
- 执行身份是宿主绑定的 `(sessionId, actorId, sequence)`；同序号、相同原始 JSON 返回缓存回执，不重新派发；同序号不同参数拒绝。序号被缓存淘汰后也不得再执行。重启创建新会话，旧回包不能控制新世界。当前账本仅进程内，并非崩溃持久事务。
- 语义上需区分拒绝、接收、运行和结束；当前账本记录 `returned/native_error/uncertain`，原生动作/任务状态另行读取，二者不能混为一谈。`InvokeJson` 的 `ok` 只是调用处理结果，必须继续读 `action_status`/`task_status` 与实际效果证据，不等于世界任务完成。
- 不先发所有长工具描述和全历史。按实际能力目录提供相关 schema，真实观察和未完成任务摘要有界；省 token 不应删掉失败证据或偷偷隐藏可用能力。

## 二、引用生命周期与慢模型

源码：`game/Survivalcraft/Westworld/Upper/ActorWorldMemory.cs`。

- `Capture` 用真实自身状态、眼射线、局部可见实体/拾取物生成引用。
- 每次 Capture 重建 live 引用集合；仍可见同一对象可复用引用，已不可见对象不再留在 live 集合。
- Resolve 不只是检查字典存在：`ResolveLivePosition/ObservePosition` 会重新检查眼射线、局部实体可见性、已知块重新观察及存储可见性。没有通过就遗忘并拒绝。
- 私有记忆地图最多 128 个地点，记忆位置不是当前目标实体坐标。移动到记忆地标与攻击当前可见实体的权限不同。
- 库存/自身合成空间引用属于该角色。不能从另一个 ActorTools 实例借引用。

慢模型后执行：保留原 observation 和 epoch，重新感知后尝试原引用/语义校验；失效就返回明确错误给模型重新观察，不替模型猜“附近另一个猪就是原目标”。不能把旧请求时间改成现在来伪造新授权。

观察刷新可能使先前任务的引用失效，这是正常事实，不是理由去维护全知实体位置表。面向动态追击应由局部执行器按当前真实视野更新，失去目标后只剩最后已见位置，不无限追踪。

## 三、复用现有任务与生产系统

- `ActorTools.InvokeJson` 负责字段解析和统一错误；gateway 不重复实现其参数解释。
- `ActorTools.Plan.cs` 的 `submit_plan` 接受 1～12 步，每步重试 0～2；分支指向未来步骤，恢复能力受动作类型限制。不能假设所有失败都能无损重试。
- `RecipeTaskComposer`/`plan_craft` 从真实库存、工作空间及公开配方编排转移与合成，不需另建木棒专用脚本。
- `plan_craft` 热度 0，不等于烹饪接口。熔炉应复用实际存储转移、状态查询与原生更新；只有接通后才能作为模型可执行能力。
- `MeleeAttack` 是一次真实攻击，命令成功未必造成伤害；目标死亡、原生尸体等待、掉落生成、入包需分别跟踪。
- 原生阶段失败返回事实与剩余状态，让模型选择继续、换任务或停下；不把私下重试专家逻辑藏在 gateway。

## 四、异步、取消和恢复

`ActorTaskExecutor` 自动随游戏线程调度。模型等待时当前有效任务继续；任务完成/阻塞/危险才触发下一次规划，不每格一次 LLM。已有 `WorldCognitionScheduler.Observation` 异步模式可以参考或复用，但不能和新 host 同时拥有一个角色的写控制权。main 新版推测规划等能力需要单独移植验证，不能假定当前 cjh 已具备。

取消不是回滚：已挖块、已转移物品、已伤害目标都要留在结果里。取消移动后用 `NavigationSettling` 确认实际稳定再开启下一陆地导航；空中取消不代表立即落地，失败驻留不能继续假装安全。

当前检查点代码：`ActorTaskCheckpoint.cs`、`ActorTaskExecutor.CanRestoreCheckpoint`。支持安全边界保存，原生动作正运行时不可把它当作可任意恢复状态；恢复要求加载后 GameTime==0 的允许窗口。保存世界、任务和引用环境必须一致，不能拿单任务文件恢复进不同世界。重载先对账已完成步骤/库存，避免再次发物品。完整多角色、异步模型在途快照还不是本轮已证明能力。

## 五、多场景矩阵

| 场景 | 输入与模型职责 | 验收证据 | 失败/反例 |
|---|---|---|---|
| 协议与私有引用 | 两角色不同观察，模型选工具 | 跨 actor/session/epoch 引用拒绝；无副作用 | 旧回包、重复 decisionId、错参数重用 |
| 慢模型 | 提交真实观察后延迟响应 | 执行前重验；消失目标不替换 | 动物移出视野、物品被拾走、工作台拆掉 |
| 受控制作 | 明示两原木夹具；模型自己查询配方和组合动作 | 真实采集、入包、板/台/Stick/木棒库存与工作空间守恒 | 缺材料/错误空间/满包时诚实受阻 |
| 可见动物选择 | 明示动物夹具与可用实际武器，模型选择接近/攻击/等待 | 每次真实可见目标、原生命中、反击与健康日志 | 不可见不能追踪；受伤可中断 |
| 尸体拾取 | 原生击杀后等待 | 死亡时间、掉落出现、实际库存增量/来源关联 | 未掉落不注入；别人拾走不补发 |
| 烹饪组合 | 明示原料或接续真实生肉；模型选择站点/转移/等待 | 原生燃料、输入、产出、取出、食用变化 | 燃料不足、输出满、肉腐坏、被打断 |
| 连续生产与食物 | 受控可观察环境，模型有多条可选路线 | 非固定动作序列，真实目标结果链与费用 | 只聊天/重复查询必须统计无进展 |
| 自然地图 | 预注册多种子、不放原料/动物、不清障碍 | 真发现、失败原因、行动路径、每模型调用实际效果 | 找不到食物仍失败，不替换种子挑结果 |
| 恢复和幂等 | 制作/拾取后安全边界保存重载 | 不重复消耗或生成；同任务对账后继续 | 任意中途恢复不支持则明确拒绝 |

人工与自然测试分别计数。出生库存保留并记录，材料/武器若预置必须明确；不能把夹具成果说成从自然世界自主获取。

## 六、最少日志与计量

每次模型调用：decisionId、actor/epoch、输入观察版本、工具目录版本、选定 tool/arguments、延迟、已知输入/输出 token、执行接受/拒绝原因。不得记录密钥。

每个任务：task/action ID、阶段、原生 affectedCount、实际库存/世界变化、部分完成、取消与驻留结果。生产核对所有相关工作空间而不只随身包；出生食物自然腐坏是合法变化，不误判为制作复制。

任务成功率按实际目标验收，不按模型宣称或 API ok。报告探索距离须排除夹具 setup 瞬移，区分累计真实路径、净位移和被动漂移；汇总无进展时长、工具错误、重复查询、token/成功目标。

## 七、避免本批并行重复

统一 host/model loop 由整合线程持有。此文档不实现第二个调度器/执行器，不改 ActorTools，不将制作、狩猎、烹饪 fixture 的硬编码 stage 复制成产品。

已有 FoodSituation 的环境归纳可作为摘要，但它的专家候选不应继续成为模型唯一控制入口。已有原生能力验收用于界定可靠性；新能力要接入动态工具目录并完成必要验证，而不是仅在提示词写“可以”。统一 gateway 的真正首个里程碑是：模型在真实观察下自主查询并完成一个组合目标，同时通过旧引用/取消/重复回包反例。

## 八、当前实验状态与效率门槛

首个自由工具 inventory 正控由真实本地 4B 自行选择 act_Eat，通过原生库存、FoodItemsEaten 与 Food 联合验收。它只证明现有食物的选择和执行，不证明制作、狩猎或烹饪组合。基线输入 3123 tokens，调用 70.46 秒，其中预填充 62.43 秒；已开始压缩工具签名与重复状态，严格 schema 和原生验证保留。改善幅度须用新运行证据判断，不能以提示字符减少直接宣称延迟降低。

后续受控制作、烹饪和狩猎分模式验证，失败也归档。自然模式当前明确未实现验收，不能用初始鱼、食物腐坏导致的新 value 或人工材料当自然采集成功。
