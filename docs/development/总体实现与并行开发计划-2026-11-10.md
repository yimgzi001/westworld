# 生存战争多智能体：总体实现与并行开发计划

状态：执行计划，不是完成声明。所有开发和测试在 dot 云电脑，单一仓库 `cjh` 分支；不操作用户电脑、Minecraft 或 main。按用户最新要求改为**多个模块并行开发，统一集成后集中真实测试**。模块级编译/纯测试仍保留，防止把明显错误拖到联测。

## 1. 最终产品与不变边界

一个持续运行的生存战争真实世界，由一个权威 GameHost 处理物理、区块、动物、背包、制作、生理与存档。AI 通过接口控制各自完整角色，不为每个AI创建视口或游戏进程；用户可加入一个可选人类观察/游玩视口。先做可靠单人和小组，再逐级验证10、20，最后40–50人。

模型负责目标、路线方向、资源选择、分工与交流；执行层提供简单、有明确前置/结果/中断语义的原生动作及连续技能。不能靠固定南瓜/找岸/队长脚本伪装自主，也不能因某次验证困难削掉原框架能力再补一套私有规则。

模型思考不冻结世界；角色继续有效的原行动，局部紧急自保可中断。没有有效计划时可以诚实停下，不能无限移动来隐藏延迟。人物具有独立人格、私有记忆与认知，群体信息只能经真实观察/通信获得。

## 2. 已有基础和真实缺口

- 已有统一局部观察、原生动作接口、完整生存角色/零AI视口方向、活动中心、停止与结果收据、共享模型协议、原生MoveTo预取、来源审计和可恢复批测。已有局部多角色实验仍需在最终集成版重跑，不把历史断言数量相加当规模完成率。
- 31三种子确定性正常世界采集：一场取得天然土块，两场无目标失败；32补真实自身骑乘/支撑/浸水与有界转向，仍一过两失败。均不是食物生存。
- 全新33真实 `gpt-6.1-terra / none` 在52.66秒内自行两次Dig、MoveTo后原生自动拾取1份沙砾；3请求28187 tokens。预取/运动重叠均0，不能称不停顿。其来源、库存、实际收据通过独立验收，不是投食夹具。
- 尚缺：完整自然食物链，动物/制作/烹饪转换的可靠归因，多步计划安全重叠，稳定的模型探索与长期目标，小组真实交付，多角色统一保存恢复、长期与分散区块容量证据。
- 阶段30未知调用继续单独保留，不重放，不用后来成功覆盖旧未知账目。

## 3. 总体架构与接口

### A. 世界与角色底座

复用 SCAPI 原生世界与完整 Player 生存组件，不用简化 Forager 代替完整人物。ActorId 与 PlayerData/UI slot 分离；AI零视口，区块/物理/生物活动依赖角色兴趣中心而非摄像机。一个世界权威线程负责全部状态写入，外部线程不得直接改游戏对象。

统一身份：WorldSessionId、ActorId、ObservationId、DecisionId、PlanRevision、ActionId/RunId。请求重连先查收据，不盲重放。accepted、running、succeeded、failed、cancelled、unknown明确区分；未知不是失败重试许可。

### B. 感知、知识与人格记忆

一次 observe 返回同一时点的身体、背包、视野内方块/实体/掉落与覆盖摘要。区分未加载、未观察、遮挡、截断，不提供全图真实资源坐标。自身骑乘、父身体、支撑、浸水是体感事实，未知不能当false。

观察形成不可变事实包：证据ID、角色/世界范围、时间、可见性及引用有效期。地图记忆保留 lastSeen，不当作实时地图；事件变化可触发再观察。人格参数、主观记忆、目标和客观事实分存，摘要保留来源与版本，不能覆盖原证据。模型只收到必要差量与检索记忆，不默认每次重发全部历史。

### C. 模型规划与连续执行

决策适配层与供应商解耦：结构化 goal + 有界 steps；共享模型连接/工作池，不按AI开一个模型进程。只接受当次给出的工具及参数，执行前用当前真实状态复验。网络等待在游戏线程外；不可变快照之后的投影、序列化、审计可并行。

连续技能负责转向、移动、局部避障/跨阶、挖掘、拾取等帧级工作；模型不必每格调用一次。每个技能声明：前置条件、受影响资源、时间/距离预算、中断点、部分完成与原生后置证据。

多步预取必须绑定 PlanRevision、原剩余步骤指纹和每一步实际 receipt/run；完整前序成功且新状态/新菜单仍合法才接续。失败、取消、替换、失效引用或目标已完成均作废候选；不能预支未来库存，不能把未执行的PickUp当成功，也不为提高“重叠率”在目标完成后继续花token。

### D. 资源、生存与原生能力

保留原生配方、武器、战斗、掉落、燃料、熔炉和食用，不另写虚构生存规则。工具支持获取、制作、使用、交付，模型根据真实环境自行选择植物/狩猎/烹饪路线。

验收用来源链而不是模型自述：实际观察→实际动作→原生世界/库存变化→可选制作/烹饪转换→食用与生理变化。先前仅方块同格Dig窗口的关联不能冒称多角色严格因果；需加入真正矿工/攻击/工作站操作因果ID。初始鱼可自保，但不能计作新获取食物；只拿到土/木材/生肉也不等于已完成可安全食用链。

### E. 群体协作

先共享可验证任务账，不先制造大量聊天：任务ID、版本、发布者、承接者、依赖、目标物/地点证据、状态、交付与验收。领取要防重复，交付用真实箱子/背包差，不用“我完成了”。

队长制只是可配置策略，不写死社会结构；可试1队长+3小队。角色有私有记忆与人格，同一任务可以产生不同选择。消息按相关角色投递、合并，完成/阻塞/危险再报告，避免每条广播触发N²模型调用。队长只知道收到的报告，不从审计后台偷看全世界。

### F. 持久化、可观测性和成本

世界、Actor、技能/任务游标与记忆版本一致保存；恢复先对账，不重复发物品/扣料/调用模型。模型请求有持久attempt/result及投递记录，区分“可能已发”与“已收到”，不会因空日志推断零计费。

按角色/场次记录：游戏tick p50/p95/p99、主线程CPU与总CPU核数、RSS/堆增长、活动区块并集、请求等待/执行/无进展时间、实际累计路径及净位移、动作成功/中断、模型输入/缓存/输出/推理token及费用依据。未知账目单列，不与已确认用量混算。

## 4. 优先复用的现成设计

1. SCAPI原生 Actions / ActorQueries / ActorWorldMemory / 食物与配方结算，是主执行与事实来源，不重写物理与游戏规则。
2. main的 Actions/Knowledge/Upper/Cognition/Models、前序任务绑定、候选暂存、不可变观察账本可选择性复用；参考已完成的main审查文档。不能直接合并简化Forager或照搬其任务结束即交接，完整Player仍需真实状态复验。
3. MC智能体项目的持续本地技能、寻路、模型规划解耦、私有记忆和消息收件箱模式作为源码级参照，具体适用/不适用理由放在现有《MC框架源码对照》；不把MC实测冒充SC。
4. 朋友在main的性格/种群模拟文档保留人格、记忆、社会策略接口扩展位。其“等所有模型再推进世界”的锁步模式与当前实时生存冲突：当前选择实时模式，锁步研究将来独立模式，不能声称无损混用。

## 6. 统一集成与验收阶段

### M1：一个模型驱动的真实自然食物闭环

先将P1–P3整合成一个版本，再集中跑：地面/水边/障碍等正常种子，真实观察→模型选择→持续执行→获取新来源→原生食用→生理结果；包含找不到/不够料/动作失败等合法失败。使用先前正常世界正控与人工故障夹具，但二者分开报。至少一个完整自然食物链通过才叫“单人食物闭环”；不能因模块纯测通过提前命名。

同批测慢模型/断网/取消、资源变动、动作失败后的重新观察、同角色动作期间模型在途、有效计划交接。最终要报告有多少真实模型场次覆盖重叠，不拿确定性延时替身顶替。

### M2：2–5个完整角色的小组生存与交付

每个角色独立认知与记忆、无AI视口，同世界真实采集、制作、箱子交付与任务验收；加入可选人类玩家观察。检查角色间状态串线、争抢、死亡、断线、世界+记忆保存重载。没有通过实际交付，不称“有组织”。

### M3：10→20→40/50规模与成本

逐级增加完整Player，不用简化实体/站桩替代。集中与分散区块分别测；模型并发受资源队列约束，公平调度，不一次启动50个阻塞请求。记录每角色与整体内存/CPU/区块/token斜率，才能给机器预算。不提前承诺4核4GB或“完全不吃GPU”。

### M4：长时持续世界

先1小时，再6小时生存/资源循环，故障注入模型离线、宿主计划重启、保存/恢复、旧请求晚到；验证资源与任务账不重复，人物记忆一致。每一步失败都给根因和修复回归，不用自动重启次数掩盖不稳定。

## 7. 联测流程与交付纪律

1. 各模块并行开发与必要纯测，只有接口或安全阻断才中途集成；不要每加一个小函数就单独开长游戏。
2. 收敛同一源码版本，统一编译和模块回归；冻结宿主、依赖、源码、配置和测试驱动hash。
3. 一次准备多个独立场景，单GUI顺序运行；模型与资源测试错峰，避免互扰。对比必须注明正常种子、人工夹具、替身与真实模型。
4. 批结束统一分析成功/失败/未知、原生因果、资源成本及可复现材料；失败也入库。
5. 每个完整已测试阶段中文提交并推cjh，核验远端head和树；main不动。计划/设计可先单独提交，运行代码不以未通过模块假称完成。
6. 仅推源码、测试、文档和授权脱敏证据；排除密钥、私人文件、游戏本体、依赖二进制和存档。绝对云路径脱敏，重复证据按哈希复用，减少归档与上传开销。
7. 所有长运行有上限与检查点。新环境先恢复仓库/状态，未知外部请求先对账不重放；主动续下一批，不因用户休息而停止已授权工作。
