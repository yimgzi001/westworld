# 阶段44：单世界多人闭环实施设计

日期：2026-11-10。本文是源码核查后的下一批实施计划，**不是20～50人已经跑通或性能保证**。本任务仅写设计，不修改生产代码，不运行游戏/API。

**实现选择**：优先以现有世界级 observation 调度承载角色生命周期，接入当前已验证能力菜单/回执协议。先做适配契约对照；若不能无损接入，保留 ToolAgent 角色runner，由一个薄世界调度器统一预算。两者不得同时拥有同一个角色的执行权，不复制第二个物理执行器。

## 2. 一次批量交付的四路分工

1. **角色与调度适配**：一个世界、一份角色注册表；角色各自session/记忆/目标/当前任务，退出后注销。把世界调度、动态菜单、前序回执接成一条路径。交付双角色请求乱序仍不串角色的纯测试和真实入口。
2. **动作与资源预算**：复用原生任务和局部导航；统一每帧感知/寻路预算、轮转队列及等待指标。不要每个角色都分配一整份世界预算。先记录耗时，再以可配置预算限制单帧工作，不截断动作语义。
3. **群体任务与信息来源**：先实现轻量任务记录（任务ID、发布者、承接者、目标、交付条件、期限、版本、状态、证据），通过实际收到的通信进入角色认知。完成消息只算声明，物品交付由实际库存变化/交易回执确认。人格/队长是提示词策略，不写死在执行器。
4. **矩阵与报告**：并行准备调度纯测试、双角色真实交付场、2/10/20/50规模采样和故障场。统一构建后批跑，输出开发/菜单接入/真实效果三个独立状态，而不是用目录条数当成功条数。

本批先交付双角色闭环和规模测试入口，再扩人数；无需每个工具单独长跑。接口、实现、纯回归并行，真实游戏集成按同一构建批量运行。

## 3. 快动作、慢决策与公平性

- 游戏线程唯一修改世界。模型网络异步；模型选择方向/目标/动作集，本地持续执行移动、采集、制造等原生技能。等待推理不能冻结其他角色或世界。
- 每角色至多一个执行所有者；每角色一个在途决策，允许现有绑定前序的预取，不重复派发。迟到回复重新核验session/actor/epoch/前序ID/观察有效期。
- 预算分三类：世界每帧计算预算、模型并发槽、模型费用账本。并发1/4/8/15是测试配置，不是给用户新增未批准花费上限。
- 模型队列按轮转+等待老化处理；紧急自救可以优先，但应有有界优先配额，不能持续挤占普通角色。已有轮转实现先复用，不先重写。
- 消息合并到下一次可用决策；成功/失败/阻塞/物资交付触发重规划。每条聊天不单独调用模型。不默认全员广播或固定AI01瓶颈。
- 用户接受约1秒内衔接空档：报告p50/p95/p99及超过1秒比例，按实测瓶颈优化，不追求每一刻都有动作。采样未覆盖的时间单独标未知，不能算零延迟。

## 4. 不全知共享

每条共享信息携带来源actor、观察/收到时间、内容类别、关联任务与证据收据。别人说“有食物”是报告，不是当前库存；坐标记忆可导航，不能变成活体/方块操作引用。

不能广播宿主隐藏实体列表、地下资源或全服库存。角色菜单只由自己当前可见引用、自己的库存和已收到offer生成。队长仅看到自己的感知与实际收到汇报，不因职位获得全知。

现有 Speak 是声学可听消息，带目标不等于私聊；实验若加远程任务总线，必须作为独立、显式的通信机制标注，不能伪称原生声音跨距离传到。20～50角色先使用现有听觉/物品交易，是否需要远程通信由后续设计单独决定。

## 5. 可复用纯测试与真实矩阵

纯测试优先延续现有 `DecisionHandoff.Tests`、`ContinuationScheduling.Tests`、`SocialTaskFamily.Tests` 与能力事实测试；新增项目须链接实际生产策略，不能写一个理想调度器再只测副本。

| 批次 | 输入 | 必须验证的输出 |
|---|---|---|
| 调度纯测 | 50虚拟actor、并发1/4/15、固定/乱序/超时回复 | 不超过并发；每角色无重复在途；轮转无饥饿；迟到/旧epoch不派发；网络等待不占游戏线程 |
| 信息纯测 | A观察、B转述、旧ref、重复任务版本、重复交付消息 | B不取得A的活引用；转述标来源；重复消息不重复结算；未知/缺失不变空气或空库存 |
| 双角色确定性真实场 | 明示人工物资夹具、双方独立菜单 | A取得/持有→提供→B接受→B食用；库存守恒、实际食用效果和会话ID；失败不推进后续步骤 |
| 双模型真实场 | 同一入口换模型决策源，自然出生 | 模型实际分工/选择工具、交付证据；没找到食物就记录失败，不注入资源冒充自然生存 |
| 规模与故障场 | 同世界2/10/20/50，无AI视口；密集/分散出生分别计 | 先用可控决策源隔离世界成本，再小规模真实模型；角色掉线、单请求超时不拖停全世界；保存恢复不重复执行 |

运行时须冻结构建、记录seed、人工夹具、人数/并发/模型、墙钟/游戏时间。真实场统一由中央执行；此文未执行上述新矩阵。

## 6. 资源与成本报告口径

- 整机CPU、单核峰值、进程RSS/峰值/每分钟增长、GC停顿；世界更新耗时p50/p95/p99和实时倍率。
- 每角色感知/导航耗时、队列等待、动作执行/空闲/模型等待占比；不能只报告总CPU很空。
- 活跃区块、模拟实体、生成/卸载耗时，分密集/分散两组。AI零视口不等于整个进程零GPU：保留的人类视口/引擎显示初始化要单列。
- 模型输入/输出/缓存token、请求成功/失败/未知用量、TTFT/完整回复延迟、每次实际交付和每生存小时token。不能由聊天条数推算账单。
- 资源估算先拟合 `世界基线 + 角色增量 + 区块增量`，同时给非线性拥堵误差；没有20/50实测前不承诺4核4G或某GPU足够。
