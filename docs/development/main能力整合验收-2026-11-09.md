# main 能力整合验收（2026-11-09）

## 1. 本批目的与状态

将 `main` 的既有行动、查询、任务编排及检查点能力接到 `cjh` 的完整无视口 Player，避免继续维护功能相同的两套动作执行器。本批来源版本为 **main `c6470d`**；后续 main 变化不自动属于本说明的验证范围。

最终加强版已通过受控采集、保存、第二进程恢复食用及实际库存恰好减少 1 的验收，完整数据见第 8 节。无预置食物的有限探索未找到支持的食物，明确失败退出，不把受控成功当作自然生存已完成。

这里的“自然拾取”指原生拾取机制，不意味着食物来自自然生成，也不等于已经证明自然觅食或长期自主生存。

## 2. 来源及复用范围

## 3. 保留的 cjh 宿主能力

- 使用完整 `ComponentPlayer` 及原生生命、饥饿、体力、睡眠、背包等组件，不用简化营养角色替代真实 Player。
- `PlayerData.IsExternalActor` 与无视口组件兼容保留。AI 不创建 `GameWidget`；本轮要求 AI 视口数量为零。
- 活动中心与视口分离，仍由 `ActorRegistry`、`InterestCoordinator` 和原生兴趣中心适配支持角色周围区块。
- 云环境可启动原生图形上下文，不等于游戏已实现完全无 OpenGL 依赖的无图形宿主；“零 AI 视口”和“无图形进程”必须分开表述。
- 保留有界异步决策及严格候选 JSON 映射。真实模型仅选择允许的技能和真实观测候选，不返回或执行任意代码。

## 4. 本批特定改动

### 4.1 单一动作控制权

整合场景以 `main AtomicActions / ActorTools` 为唯一动作执行方。

`NativeActorSession` 支持 `actionsEnabled:false` 的观察模式。该实例继续提供受限观测和角色登记，但其动作入口必须拒绝调用，不能与 main 任务执行器争抢移动、挖掘或食用控制权。

`AtomicActions` 构造时自行注册原生更新；`ActorTools` 构造时建立任务执行器。宿主不重复注册相同角色的执行器，也不在原生更新之外再次手动推进动作。观察适配只读角色及环境，不代表允许模型持有原生实体对象。

### 4.2 真正三维朝向

本批调整以下文件：

- `Actions/AtomicAction.cs`
- `Actions/AtomicActions.Movement.cs`
- `Upper/ActorTools.cs`
- `Upper/ActorTools.Catalog.cs`

接口扩展为：

```csharp
FaceTowards(Vector3 Point, float Timeout = 5f,
            float? PitchDegrees = null, bool HorizontalOnly = false)
```

直接向实际目标点调用时，从眼睛位置计算俯仰。执行器通过原生 `TurnOrder` / `LookOrder`、`TurnSpeed` / `LookSpeed` 逐帧转动，不直接瞬移角色旋转或写入 `LookAngles`。

工具调用支持：

```json
{"bearing":45,"pitch":-20,"timeout":4}
```

`pitch` 为绝对头部俯仰角，负数向下，范围为 -82° 到 82°。旧 bearing-only 调用保持仅水平转身语义，不主动改变当前俯仰；`destination` 与额外 `pitch` 不混用。超出原生头部角度范围的目标应明确失败，不通过夹紧角度冒称已瞄准。

### 4.3 感知与现场引用

main 的 `observe` 对方块使用前向眼睛射线，对附近实体/掉落物使用局部查询。它不是周围所有方块的全量扫描。

本轮整合也保留 cjh 的有界局部候选观测：距离、视锥、已加载状态和保守体素遮挡过滤后，只向模型提供已知可用资源候选。未知格不能带出方块值；这不是全图资源搜索。

模型选择后先重新确认当前候选，再实际转向；必须用 main 眼射线重新命中同一资源，获得 main 自己签发的现场 `reference`，才提交 main 采集计划。不得把模型生成的坐标字符串伪装成现场引用。

日志应区分规划时观测与执行前重新观测。局部范围内真实看见资源，不等于长期记忆知道全世界资源位置。

## 5. 已有接口如何组合

```csharp
var actions = new Game.Westworld.AtomicActions(player.Entity);
var tools = new Game.Westworld.ActorTools(actions, publicGuide: false);
var observationJson = tools.InvokeJson("observe", "{}");
var taskJson = tools.InvokeJson("task_status", "{}");
```

主链为：局部发现候选 → 异步模型选择 → 当前条件重验 → 三维朝向 → main 射线观测与引用 → `submit_plan` 的 `act_MoveTo` / `act_Dig` → 原生拾取及背包确认 → 有限食用计划。

`ActorTools` 已支持最多 12 步 JSON 任务、有限重试、向前跳转及特定安全失败的 fallback。`act_PickUp` 的真实回执可经 `item_from_step` 绑定后续 `act_Eat`，无需再造同类任务编排层。

当前整合 runner 采用原生自然拾取后重新核对实际槽位，再提交 `Wait → Eat` 计划；它没有据此宣称本轮已经验证所有 `item_from_step` 或失败分支组合。

如果采集成功但未拾取，不能宣称已获得食物；拾取成功但未确认原生食用效果，不能宣称饥饿已解决。每个阶段应记录世界、背包或生理结果。

## 6. 模型异步与 main 模式边界

main **同时存在**锁步/回合式路径和 `WorldCognitionScheduler.StartObservation()` 异步观察模式。后者对已有活动任务的角色跳过新请求，不能笼统描述为“main 只有等待模型时冻结世界”。

本批整合 runner 使用 cjh 的异步本地决策桥接 main 动作与任务能力；这不自动证明 main 所有认知调度模式已经接入完整无视口 Player。本轮也没有证明人格、长期记忆、社会协作或群体认知已完成整合。

等待模型时应记录世界仍在推进的证据；任务执行期间应由本地动作执行器持续工作，不按每一格移动重新请求模型。

## 7. 场景与检查点验收规则

入口：`experiments/scapi-main-integration/Program.cs`。

| 模式 | 用途 | 不能由此推出的结论 |
| --- | --- | --- |
| `fixture` | 明确布置地形及成熟资源、清空起始背包，验证组合能力与检查点发布 | 自然发现、长期生存、无人工条件优化 |
| `natural` | 不布置食物，有限扫视/探索，只使用实际观测资源；仍须披露起始背包处理 | 搜索失败不是角色或环境不存在资源的证明；搜索成功不是持续生存 |
| `reload` | 从同一检查点归档重建角色与任务，在第二进程恢复 | 强制崩溃恢复、多个活动角色的一致性恢复 |

main 检查点只在安全动作边界保存：没有正在执行的原子动作，任务处于可捕获状态，剩余步骤可由数据恢复。仍依赖现场引用的待执行步骤不能强行存成可恢复任务。

宿主使用：

```csharp
tools.SaveTaskCheckpoint("app:integration.scworld");
// 第二进程：原生导入并加载归档，绑定同一实体，尚未第一次推进世界。
bool restored = tools.RestoreTaskCheckpoint();
```

恢复必须在 `GameTime == 0`、第一次世界更新之前完成。不得等角色常规运行若干帧后才尝试恢复。记录同一实体 ID、原 TaskId、任务游标、库存、食用次数及 Food；重复 Restore 必须拒绝，不重复产生资源效果。

当前 checkpoint 时序采用 Frame 完整更新后的即时检查与保存，不在下个更新回合才检查已经可能越过的状态。这并不保证一次 Frame 内多个模拟子步出现的所有短暂边界都能被捕获；无法满足安全保存条件时应明确失败或等待合法边界，不能假称已保存。

本轮还修正了测试日志中 Vector3 的显式序列化，以便保留实际位置证据。需专门核验：checkpoint 时序、输入撤销、目标失效后的恢复、实际库存减少与 Food/食用次数增加。阶段日志和构建成功不能替代第二进程结果。

## 8. 最终结果（2026-11-09，dot 云电脑）

- 最终产物 `cloud-main-integrated5`：fixture **19.927186 秒通过**，第二进程 reload **3.0914266 秒通过**。原子任务完成接近与挖掘、原生拾取一份南瓜，食用前保存；同 TaskId 恢复后 Food **0.5453502 → 0.6953155**，FoodItemsEaten **+1**，实际库存 **1 → 0**，再次恢复拒绝。两个进程均 `updateFailures=0`、AI 视口 **0**，使用完整 Player。
- 同版 `natural` **33.8877153 秒未完成觅食**：无人工摆放食物，起始背包清空，有限 4 次探索任务。第 3 次在两次尝试后 blocked，第 4 次两次尝试后成功，最终仍未实际发现支持的成熟南瓜，明确以失败退出。没有调用模型或凭空发食物。它验证了有限重试/失败可观测，不证明自然自主生存。
- 四组回归在最终源码重新构建执行：核心契约 **70/70**、异步决策 **45/45**、本地映射/有界流 **54/54**、编译原生钩子 **7/7**。这些不是 176 个真实世界场景。

## 9. 本批完成标准与下一步

本批最小完成标准是：同一完整无视口 Player，复用 main 任务与原生动作完成受控资源链，并以同一世界检查点跨进程继续、确认不重复食用。达标后才把自然探索、失败恢复和多角色竞争依次纳入明确的新验收场景。

main 既有独立测试结果属于来源分支的回归资产，不能直接折算成 cjh 当前宿主的通过数量。32 个模块、9 项依赖与 31 个能力目录也不构成项目完成比例。
