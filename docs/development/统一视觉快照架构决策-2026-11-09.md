# ADR：统一角色视觉快照

状态：设计与实现审查中，尚未完成本阶段原生验收。基线为阶段18发布 `50e3c1`；阶段18的775项纯断言、9正4负矩阵不能作为本阶段通过证据。本文不修改既有失败记录。

## 目标与分层

让一次角色观察同时供给真实可见方块、对象、原生背包和导航证据，避免宿主、原生查询、食物投影各自扫描并得出不同事实。不是增加全知搜索，不扩大动作距离，不替模型决定采集路线。

依赖只能是 Adapter → Game。共享扫描器位于 Game/Westworld；纯几何使用该层自己的简单值类型，原生门面负责 Engine 类型转换。Game 不引用 Adapter 或 Runtime.Core DTO。ActorQueries/ActorWorldMemory 管理实体绑定与引用，扫描器不生成工具引用。

已对齐的扫描器方案：静态、无跨调用缓存；仅单次 Scan 内缓存体素读值。不可变结果附本次姿态、参数、扫描窗口。预算暂定最多1944次表面样本、4096次体素读取，耗尽后的格仍是未知。具体实现和实测性能待验收，数字不是帧耗时承诺。

## 快照与权限契约

1. 捕获与引用作用域必须绑定实际 Project、Entity、观察ID、眼睛姿态及查询参数；不能仅以 tick、玩家编号或位置作跨角色缓存键。跨世界重载必须失效。
2. 同一捕获里的 inventory 是原生自身事实。宿主 Snapshot 复用 observe.inventory，不再紧接一次 read_inventory 拼接不同时间事实。独立 read_inventory 工具仍保留，可用于主动查询、结算和不确定结果对账。
3. 模型视图删除 observation 中重复完整 inventory，改由 CompactInventory 提供非空槽和空槽索引；完整原始快照留审计。保留 visibleBlocks、coverage、sense。压缩不改变真实计数或物品值。
4. 若需裁剪，先形成唯一有界 ModelFacts，再由这份事实构造 Offers 和 Prompt。不能先给完整 refs 菜单，再在总预算裁剪中隐藏它们的事实。预算超限应明确拒绝/分页，不默默声称完整。
5. 当帧 visibleBlocks 才能授权块引用；历史地图只授予回访位置，不授予挖掘、放置、攻击或拾取的当前权限。下一动作仍须游戏线程重新观察/验证同一引用，不能自动换成邻近资源。
6. 接近角色的 pickable 若沿用 InReach 免视锥规则，应标为触觉/可达感知，不能混称视觉。对象与掉落的已加载路径防护不能因复用新扫描器而消失。

## 可见表面与原生动作必须分开

现有 ActorQueries.ReobserveKnownBlock 用格中心作视锥前置过滤；顶面可见、中心不可见时会错误淘汰刚发现的引用。新 ReobserveCell 应重读同一表面采样/遮挡规则，不用中心替代，也不能只信缓存旧值。

只读实现审查补充：当前 SharedVoxelScanner/ReobserveCell 使用身体周围 x/z ±4 的局部窗口，VoxelSurfaceGeometry 的半径是5米；它不是16米完整块扫描。旧 focus/ReobserveKnownBlock 的较远原生射线契约不能无区别换成这个局部窗口，否则远处已见引用会错误失效。最新代码已区分：ActorWorldMemory.LiveReference.SurfaceObserved 仅新批块为 true，ObservePosition 先走5米 shared reobserve 且不回退；旧 focus 保留原生分支。已只读核对该接线，兼容风险在源码层已处理，仍待原生验收。不能为兼容远 focus 把导航5米证据偷偷扩成16米。

这不意味着看见即可操作。AtomicActions.World 的 FindWorldRay、原生交互盒、InteractionReach、目标值匹配和攻击距离继续决定动作合法性。16米视觉范围不是16米挖掘/攻击。出现“可见但太远”应反馈该原因，而不是扩大原生距离或把引用改成其他目标。

ActorWorldMemory 每次 Capture 替换 live 引用表的生命周期也要一起验证：截断未返回不等于证明资源消失；可以保留带时间的历史位置，但不能保留无新证据的当前动作权限。

## 预算与截断含义

分别记录，不能用一个 complete 混淆：

- 指定局部窗口的格数、已处理/未处理格数；
- 样本与体素读取的使用量、上限、耗尽原因；
- 已证明可见但因返回上限省略的数量；
- 模型事实裁剪省略数与工具 enum 上限截断。

Complete 仅表示本次指定窗口按声明算法处理完，不是360度全视野，也不是世界全部资源。未知格不携带内容值；unknown 不等于 air。当前 NativeActorSession 的128观察容量是会话资源限制，不能以扫描复用为名共享不同角色 refs；多角色容量另作独立预算验收。

## NativeToolOffers 当前审查结论

`experiments/scapi-tool-agent/NativeToolOffers.cs` 新增 visibleBlocks 分支：只接收当前 observation 数组中合法非空气 value 和宿主引用；块引用进入 Dig/位置集合，未把块当实体；历史 recent 不回授块权限。已阅读新增纯测试：多块无 focus、空气/未知/重复、历史隔离、真实结构化 schema 接受引用。实现者报告104项通过，本文未重新运行，不把纯菜单测试当原生可见性证明。

需要保留的边界：分支 `.Take(128)` 和后续按引用字典序 `enum.Take(128)` 是独立菜单截断；coverage.truncated 不应被它们覆盖。函数信任宿主输入，不自行验证 Project/Actor、视线或引用签名，这些必须由捕获与 dispatch 门保障。若新增 sense 字段可区分未验证/历史格，宿主投影必须先过滤，不能让模型构造的 JSON 直接进入此工厂。

## 最小验收矩阵（待运行）

- 两角色同 tick 同位置不同朝向：结果/refs 不串；同 actor 换世界旧 refs 不可用。
- 顶面可见中心遮挡：发现与同规则复验一致；距离过远仍原生拒绝操作。
- 未加载、预算耗尽、返回截断：unknown 不漏值，计数守恒，不伪造完整覆盖。
- inventory 只捕获一次：模型压缩与原始槽事实一致；动作后新观察更新，不用旧值补新引用。
- ModelFacts 剪裁：菜单每一资源引用均有被展示的来源；历史位置只可导航。
- 对象/掉落保留加载、遮挡与触觉来源区分；改为共享观察后不能扩大既有权限。
- 同一原生场景记录扫描次数/样本/读取、游戏更新耗时与 prompt 大小，再比较重复扫描基线；不以纯测试时长代表真实帧耗时。

## 阶段19验收中的语义补充（尚未收尾）

`scanComplete` 只表示指定格网处理未因扫描预算耗尽而中止，不表示全部格已知。块加载状态不满足要求时，即使预算完整处理，结果仍可能全部 unknown。空 visibleBlocks 不能解释为周围资源不存在；应结合 KnownCells、LoadedRectangleChecks、LineOfSightChecks、VoxelReads 和覆盖原因说明“本次未取得视觉证据”。

当前五角色原生墙体反例发现夹具时序缺陷：ChangeCell 后区块处于 InvalidLight，建墙/拆墙帧记录 known=0、LOS=0、reads=0、loadedRectangleChecks=239。该帧的空列表不是射线被墙挡住的证据，因此先前墙断言不能算遮挡验收。夹具正在改为等待真实 Valid 且 LOS>0 再判定，原失败应保留；不得为通过测试降低扫描器加载要求或修改已冻结核心实现。

独立 surface01 的 known 数量75→4→75不是上述全unknown情形；两组证据不可混用或互相替代。当前完整纯回归为22套833项通过（协调结果，本文未重跑），不代表修正后的五角色原生矩阵已通过。最终原生结果、版本与失败日志由收尾报告补充。


## 19/20后续只读复核（等待21原生结果）

当前 Capture 在同一游戏线程调用内读取 self/focus、附近对象、共享地形扫描与 inventory，再发布引用表；这是同次同步观察，不是跨线程世界锁或跨时刻缓存。Snapshot 已直接 SplitObservation，从同一返回拆出背包，仅移除重复 inventory/inventorySummary，不裁 visibleBlocks/coverage。BuildContext 对 facts 超预算整包拒绝，因此当前批块引用不会因该层裁剪而脱离其事实来源。SharedVoxelScanner 无全局缓存，预算与 unknown 边界保持。

19/20夹具的挂载与 FullReady 区域条件仍在修正，21计划仅修夹具，不能把生产代码冻结或纯测通过写成原生验收通过。最终报告应按实际原因保留各次失败。

此前发现、现已在源码修正的宿主一致性问题：旧 Program 先用原始 recent/OfferFacts 构造菜单，再 Project 和 BuildContext 裁剪历史结果。若 read_map 页或 read_storage 结果被压缩预算剔除，菜单仍可能带该历史位置、外部工作区或槽值枚举，而最终模型事实已不含它们。该问题不意味着全知读取，也不绕过原生执行复验，但违反“菜单引用有已展示来源”的设计契约。应从最终保留的投影事实构造菜单（正确拆 projection.data），或删除缺少展示来源的枚举；learnedRecipes 可继续用独立 facts 中的真实已知配方。当时要求新增地图页/工作区记录被预算挤掉的回归；修复后的复核见下节。
