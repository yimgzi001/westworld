# 阶段39：完整能力目录与生产接线

本轮将隔离原型移入生产。**55项是52原生+3宿主导航的目录覆盖，不是55项真实执行已通过。**
完整逐项状态在同目录 `阶段39能力支持状态.json`。目录、模板、当前角色支持、同帧事实、执行菜单、实际效果分别记账；当前可执行性只由运行时判定。

## 入口与原版回归

`WESTWORLD_CAPABILITY_MENU=1` 启用新入口；未设时保留阶段38既有文件驱动回归路径。
新入口初始展示完整索引及两个发现工具。模型调用：

- `read_capabilities({offset:0,limit:8})`：分页状态，不执行动作。
- `read_capability_schema({select_family:"body_transport_equipment"})`，或 `select_tool:"act_Craft"`：明确选择下一轮菜单。选完结束本计划，下一轮重新采集；不是动作授权收据。
- 目录详情不表示能力当前可用。最多30执行槽+2发现槽；超量、未知、模板缺失明确报告。

原有同角色异步前瞻保留；新菜单在即时和前序成功后规划两个入口使用同一选择。后者是条件候选，不允许边执行旧动作边直接派发新动作。实际派发继续新鲜重验。没有新建第二个物理/任务调度器。

## 后续真实联测：合并两场，不拆成几十个小局

先冻结本轮构建、内容hash及源码，再用已有isolated staging流程准备全新工作目录。底层宿主命令为：

```sh
# 仅在已经准备好的隔离run目录；此处未执行
WESTWORLD_CAPABILITY_MENU=1 /绝对路径/dotnet ToolAgentGate.dll natural_food file capability39-a
```

此命令本身仅提供当前单角色宿主入口，必须配文件驱动。**目前没有完成两角色场景驱动，不能将它当现成55能力矩阵启动命令。** 同目录现有`batch.py`仍是旧食物/异步矩阵，不冒充新矩阵。

1. 身体/装备/库存/采集/制作/设备+有限任务中断合并一场：正例验证真实动作/库存/参数/终态；负例统一测试引用失效、配对错误、三种busy、taskId替换、取消排空。采样/响应容忍度依用户目标，重实用效果，不追求每毫秒覆盖。
2. 两完整角色社交/交付合并一场：可听见消息、定向并非私密、offer实际收到、接受前后双方库存、失败/过期、未知事实及多角色归属。

模型自主采用另记：是否实际选择工具、达成目标、token与延迟。不把确定性夹具计作模型自主生存。新真实场景未跑，接线初始可用不等于长期稳定生存。

## 明确剩余边界

- Configure仅少数设置类型有模板；其余子类型是catalog-only，不能任意object开通。
- 家具自定义options、复杂单schema进一步拆页尚未完成。
- 角色组件混合支持按每个工具判断；已修复ClimbTo不支持误屏蔽MoveTo。
- Craft数量按原生产出批次枚举，不允许不足一批的数量。
- 查询缓存已规范属性顺序，unicode/数值等值编码的完全规范化仍可后续改善。
- 旧动作与新族保留原生业务前置条件；有正确schema不代表目标一定可骑、可攀爬或可配置。
