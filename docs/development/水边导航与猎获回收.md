# 水边导航与猎获回收

更新于 2026-11-11。这里记录当前实现与验证方法，长期自然生存结果另见[单人普通生存开发记录](单人普通生存开发记录.md)。

## 解决的问题

旧导航把陆地和水面分开处理：上岸主要依靠短距离 `MoveTo`，受阻后转向再试；猎获取肉主要证明干地路线。实际运行出现岸边重复动作、击杀后报 `prey_meat_out_of_reach`、低头涉水下沉等问题。

玩家模板的 `SwimSpeed` 实际为零。正常玩家在水里使用行走、视线俯仰和跳跃输入，而不是鱼类的原生游泳速度。修复保留玩家原来的速度、体力、重力、碰撞和伤害规则。

## 路线和动作

- `PlaySurfacePath` 将当前全向观察中的水面和完整方块落脚点组成局部图，以 A* 比较路线。干地基础代价为 1，水面为 2.4，升降、转弯、出入水另外计价；这些是本项目的执行成本参数，不是 Minecraft 的固定数值。
- 只连接水平相邻、最多相差一格的已见表面。水面之间保持同一高度，上岸还排除已见的低顶。看不到高岸顶部时，寻找有证据的低岸，不把未知顶部当成可以跳上去。
- `TraverseSurface` 只执行宿主给定的两格左右短段，组合正常行走、抬头和必要跳跃。直线水面段可在同一动作中续接；转角和上岸保留独立到达核对。该动作不进入模型工具目录，也不搜索地形。
- `PlaySurfaceTravel` 保留本次目标和路标。开始新段前刷新观察，检查危险与路线许可；卡住的节点暂时排除，最多三次重选，整段最多四十秒。陆地部分仍使用原有落脚、净空与台阶证据。
- 身体刚碰到岸沿时可能暂时有原生支撑值。必须完成当前动作，脚底回到目标方块高度并稳定，才确认上岸；不会在半跳时交给制作。
- 普通陆地目标也记录没有实际进展的受阻端点，并在目标不变的前提下尝试当前已见表面的绕路，减少每帧重发失败动作。

巡猎和探索在出发前还会搜索已见干地连通图，按原方向推进、路程、升降和已访问次数选择终点。模型菜单中的可走距离来自这条实际路线；不再把直线二十格的理想坐标直接放到水面。每段失败后交回决策，不因绕行路程已累计很多就自动续下一段。受阻端点按方块格保存，防止浮点坐标微变绕过记忆。

可见自然场的精确诊断还发现：原生高频物理帧会短暂清空 `StandingOnValue`，但脚底高度不变、竖直速度仅约每秒零点零零六格。平地执行器现在允许最多 0.12 秒接触恢复窗口，此时暂停写移动输入；真正下落、入水、其他动作占用或持续缺失仍中断，原超时仍计时。没有放宽路线净空、断崖或跳跃范围。

## 击杀后的交接

狩猎技能绑定这只猎物的原生掉落来源，只从当前可见物品读取位置。击杀不是成功终点；确认本人实际库存增加才算取肉。

干地路线不可达时，可以规划水面回收，但同时必须证明存在已见干地出口。掉落物漂移时，与规划时的位置比较累计位移并重选路线；不能只比较相邻两次观察，否则缓慢漂移会被忽略。到达路标后仍以原生拾取范围核对，必要时在当前已见水面格内微调。

实际取到肉后，若仍在水里，保留该技能并走到干地再交接。新出现的猎食者、明显掉血、体力过低或超时会中止取物；遮挡后不会借助来源审计读取私有坐标追踪。审计只用于核对归属和库存结果。

提示要求击杀后优先取回掉肉，再比较烤制、补料和返程。是否捕猎、备多少物资、什么时候换长期目标仍由模型决定。

## 可复用原生场景

`experiments/scapi-step-gate` 新增以下场景，每场一个角色、隐藏静音、不调用云模型。最终场景冻结环境生成以避免随机猎食者污染动作对照，威胁专项单独加入原生灰狼；没有改变普通生存的物理、食物、伤害或库存结算。

| 场景 | 核对内容 |
| --- | --- |
| `shore-low-bank` | 水里持续接近低岸，完成原生上岸且满血 |
| `shore-high-bank` | 高岸顶部不可证明时选择已见低岸出口，不顶着高墙重试 |
| `shore-blocked-bank` | 眼前岸口有石墙时，沿水面走向另一处已见出口 |
| `shore-hunt` | 原生投矛击杀、掉肉、涉水取回，最后稳定站上干地 |
| `shore-hunt-drift` | 对同一份原生掉落施加短时横向速度，须发现累计漂移、续接水路并实际取回 |
| `shore-hunt-hidden` | 掉落后用石墙遮挡，须停止，零入水、零虚构库存 |
| `shore-no-exit` | 水坑没有可证明的出口时，零移动动作并明确失败 |
| `shore-hunt-threat` | 入水后出现可见灰狼，中止取物并释放原生动作所有权 |

漂移和中途遮挡是受控故障注入，只验证交接与信息边界；不计作自然生存成绩。完整烤肉、木材储备、陆地转向、真实台阶和岸边避险另跑回归。具体成功与失败批次保留在开发记录，不能用构建成功替代行为验收。

另有 `explore-water-bay` 检查绕过整片水湾并真实向前推进；`navigate-coast-loop`、`navigate-terrace-loop` 使用本场相同种子与日志坐标，`navigate-momentum-loop` 加入横向惯性。单独回放最初未复现自然场的全部中断，不将这些坐标场当成修改前失败证据。`contact-flicker` 在地面、高度和速度不变的情况下只清除一帧接触标记，旧执行器确实立即失败，修改后须继续原动作；`contact-persistent` 持续清除标记，仍须在恢复窗口后停止且零位移。

## 参考实现

参考的是 Minecraft 机器人项目 Mineflayer，不是把 Minecraft 原版物理移植进本游戏：

- [mineflayer-pathfinder 的 movements.js](https://github.com/PrismarineJS/mineflayer-pathfinder/blob/master/lib/movements.js)：不同移动类型的邻居、液体成本、跳跃与落差条件。
- [mineflayer-pathfinder 的 index.js](https://github.com/PrismarineJS/mineflayer-pathfinder/blob/master/index.js)：保留路线节点、原生输入持续执行、没有进展时重选路线。
- [mineflayer-collectblock 的 CollectBlock.ts](https://github.com/PrismarineJS/mineflayer-collectblock/blob/master/src/CollectBlock.ts)：采集后保留掉落物目标，跟踪到取回再移除。

本项目继续由 Survivalcraft 原生执行器结算，不照搬跨格距离、游泳速度、自动挖路或搭桥规则，也没有引入每格模型调用。
