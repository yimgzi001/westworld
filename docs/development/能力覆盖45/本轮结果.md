# 阶段45：同世界双角色协作实测

## 已核实结果

D批 `integration45-d-matrix_coop` 通过20项断言、6类效果检查；进程退出0、宿主更新异常0。独立审查原始回执、库存状态、身份和冻结指纹，不只采用汇总的passed。

- 同一个游戏Project内两个外部角色，两个不同actor/session，无角色视口。不是两世界，也不是网络联机。
- 7次当前动态菜单验证，涉及6种工具：FaceTowards（2次）、PickUp、OfferItem、RespondToOffer、Wait、Eat。7个独立capture的actor/session与后续回执对应；取食、交付、等待和食用runId没有混用。
- 每次动作前重新读取观察、库存和owner状态。Eat营养来自公开read_item，并同时进入菜单依据和提示词可见库存；并非隐含营养授权。此次没有调用模型。requestId是同步宿主的关联标识，不是原生回传的网络请求ID；OtherReference仅在当前公开entities里按人工夹具目标筛选，不代表模型自行认人。

## 并发与结束

A的Wait从游戏时间0.553628持续到8.556201，独立runId最终succeeded；B的Eat在0.553628派发并立即返回succeeded，0.610507核验时A的同一Wait仍running。证实一角色活动期间另一角色可执行并完成动作，且不会覆盖对方owner。**Eat不是跨多帧的持续任务，0.0569秒是派发至核验间隔，不是测得的食用耗时。** 尚未证明两项持续生产/移动任务长期并行。

双角色task/action状态核对为终态、无活动owner后才恢复人工地形；cleanup记录idleVerified=true，无cleanup_failure，进程正常退出。注册按一次性世界生命周期使用，本场没有验证同进程卸载再创建后注册清零或反复复用。

## 失败批次没有覆盖

- A：Vector3直接序列化触发循环/深度错误，改为标量数组日志。
- B：掉落在眼前下方约73.5°，超出60°半角视锥；不是仅凭同帧就断言感知缓存延迟。修正人工夹具几何及实际朝向，保持原生感知规则。
- C：拾取成功，但转向使用相对bearing时错误处理朝向，导致同伴不在当前可见引用里。
- D：修正转向语义后全链通过。A/B/C均仍记录失败，不计作通过场。
