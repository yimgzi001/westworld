# 环境驱动食物策略设计

日期：2026-11-09。状态：设计，尚未完成狩猎、制作武器、烹饪的原生自主闭环。

## 目标和当前边界

角色应根据真实观察、库存、身体状态和可执行能力选择食物路线，而不是固定寻找南瓜。眼前可拾取的食物、可安全采集的植物、能应对的猎物、可制作的工具以及可用炉子，都可能改变选择。优先选择有证据且当前有望实际到达并完成的路线；直线距离近不等于已验证可达。路径未知可尝试有界接近，但不得标记为“已确认可达”。

现有南瓜采集闭环是已验证路线之一，不代表其他食物自动获得了同样的执行能力。`FoodCapabilities.Catalog` 收录食物种类也不证明世界中存在这些食物，更不证明已经掌握取得它们的方法。本设计不新增未连接执行器的占位实现。

通用导航地基包括局部观察、短期记忆、对齐、平地/台阶候选、身体扫掠和失败反馈。它们为食物路线提供执行条件，不是食物策略本身；合成几何测试也不能代替真实游戏验收。

## 建议契约

以下为设计字段，不表示这些类型已实现。

### FoodSituation：一次角色私有的决策输入

- `Self`：角色身份、时间、健康、饥饿和必要身体约束。
- `InventorySnapshot`：实际槽、完整物品值、数量及库存版本；原生营养和风险评估。
- `VisibleResourceRefs`：当次真实可见植物、动物及掉落，包含证据 ID 和时间。
- `KnownRecipeRefs`：静态配方知识，与拥有材料明确分开。
- `ObservedStations`：实际观察/检查到的可使用工作台、炉子及其版本化状态。
- `CapabilitySet`：当前已连接且通过相应验证的执行器，不由模型声明。

实体引用建议为 `(session, actor, observation, entityId, observedAt, lastPosition)`。宿主用私有映射解析原生实体，执行前复核存活、世界归属、当前可见性/允许的有限记忆追踪和可达范围。会话变化、实体消失或引用过期不能重新解释成另一只动物。

### FoodStrategyCandidate：可审计的候选

建议包含：`Id`、`Kind`、所需证据、库存版本、前置条件、缺失材料、风险、期限、执行器类型。

`Kind` 可逐步支持：

- `EatInventory`：吃实际拥有且策略允许的食物。
- `CollectDrop`：接近并拾取实际观察到的食物掉落。
- `GatherPlant`：采集可处理的真实可见植物。
- `HuntVisible`：应对真实可见、当前能力可处理的猎物。
- `CraftTool`：根据实际库存和工作区制作工具。
- `CookFood`：用实际原料、燃料、设备进行烹饪。
- `Search`：在信息不足时执行有界探索，不伪造资源目标。

只有执行器已连接且当前前置条件满足的动作才进入“可立即执行”候选列表。材料不足可以成为准备计划，但不能显示为已经可执行的制作或烹饪。计划依赖、动作结果和模型陈述分开保存。

模型只选择本次候选 ID/索引，不能提供任意实体 ID、坐标或代码。沿用动态候选 schema、解析器、调度器独立校验三层；接受计划不等于成功完成。

## 本地连续技能与异步决策

高层模型决定路线，低层技能持续执行观察、接近、装备、交互和结算。不要每一步移动都重新调用模型。遇到证据失效、危险、资源竞争、超时或实际无进展，产生结构化结果，再考虑换方案。

### 狩猎路线

1. 观察到猎物，结合身体状态和实际装备选择是否尝试。
2. 有界接近并持续重新观察；不是用旧位置全知追踪。
3. 选择实际拥有的武器或明确支持的攻击方式，按原生机制攻击。
4. 目标失去可见性时，仅允许有期限的最后已知位置搜索；不能持续读取隐藏目标位置。
5. 击杀后重新观察掉落，拾取并核对库存增量。
6. 根据生肉的实际风险和烹饪条件选择下一步。

击杀不等于必定掉肉，出现掉落不等于已经捡到，捡到生肉不等于安全进食完成。

### 制作工具路线

1. 从静态配方与实际库存核算材料和工作区要求。
2. 缺少材料则形成真实资源获取子目标，不注入库存。
3. 按原生槽位操作安排配方，重新读取匹配结果。
4. 执行制作，核对原料消耗及成品进入库存或产生可见掉落。

必须处理制作过程中的库存变化、空间不足和部分完成，避免重试复制物品。

### 烹饪路线

1. 实际拥有原料和燃料，且能使用满足配方热量的炉子。
2. 转移物品并核对原生库存，不凭模型推断已经放好。
3. 等待原生炉子推进；等待期间可以继续有效计划，但不能重复提交同一投料。
4. 取得实际成品，核对库存变化；剩余燃料和残留物按原生规则处理。
5. 食用后检查真实物品消耗和身体营养变化。

没有炉子、燃料或适用执行器时，候选应该反映缺口，不把生肉改名为熟肉。

## 优先级与失败恢复

不写死“见猪就猎”或“永远南瓜”。比较当前饥饿紧迫程度、风险、已知距离、装备、所需准备和可完成性。紧急时先考虑真实已有且允许的食物；准备复杂路线时保留退出条件。任何候选排序只是策略，不是对成功率的保证。

每个动作保留会话/角色/动作 ID、输入证据、状态、期限和结算证据。阻塞或目标变化应转为局部重观察或替代路线；不要靠重复对话掩盖没有行动，也不要把旧成功回报当作当前任务成功。

## 分阶段验收

先完成通用连续导航真实验收，再选一个完整新增食物路线实施，避免同时堆砌未联通技能。

1. **候选可信度**：眼前真实猪可成为候选；墙后动物不能出现在当前可见候选。角色之间不共享未经传递的观察。
2. **工具准备**：有真实材料可完成制作；缺材料明确报告缺口。配方摆放、材料消耗、成品入袋都有原生证据。
3. **狩猎闭环**：接近、攻击、死亡、实际掉落、拾取分别记录；目标消失不全知追踪；无掉落不能报告取得肉。
4. **烹饪闭环**：缺燃料不能报告熟肉；有条件时原生炉进度和库存增量证明完成。
5. **恢复与幂等**：目标失效、库存竞争、重复提交、模型延迟及技能中断不复制物品、不无期限攻击。
6. **生存收益**：真实食物取得并食用后身体状态改变，而不是只观察模型输出或动作接受状态。

合成测试用于验证契约与失败路径；真实地图、真实角色与原生库存/生理变化才是自主生存链的验收依据。不同食物路线分别记录已验证与未验证，不能从单一路线成功外推全食物能力。
