## 延迟必须分层

首请求发布到首个原生调用约 **70.728 秒**，其中包含外部 driver 尚未启动的准备空窗，**不是 API 推理耗时**。后续已见请求到调用约 5.2–9.0 秒，接收回复到派发为毫秒级。`native_call_started` 是调用派发，不等同角色已经移动；真实动作终态另记 `native_terminal_observed`。

官方 API 的精确模型 ID、请求耗时、token 用量、reasoning 设置及成本由独立 driver 审计补充。宿主 file 模式的 `metrics/audit=null` 不表示官方请求免费或零 token。此轮为单次受控案例，不是统计性能结论；与以前版本比较要同时考虑 CompactBounded 上下文更新，不能当成只有模型变化的严格消融。

## 下一阶段：最小连续局部导航接入建议（尚未实施）

保留模型选择目标/方向，不写固定造棒流程。给宿主添加显式“沿所选方向完成一个有限局部导航段”的命名技能，而不是悄悄把所有原版 MoveTo 改语义：

1. 复用已验证的 `LocalNavigationSkill`、`LocalNavigationSkillLease` 和唯一 AtomicActions。技能执行期间统一占有动作租约；同角色其它写工具/plan_craft不能并发抢控制，真正只读查询可继续。
2. 目标来自当前真实观察或模型选择的有限方向。局部技能只用观测证据规划一段，必要时观察脚下/前方/净空；未知不视为空气，不追踪不可见实体，不扫全世界补路线。
3. 先只接单段有限执行，报告 Arrived / failed / cancelled、实际位移与失败原因。缺证据、障碍、超时后停稳并把事实交回模型，不用反复盲走掩盖失败。
4. 下一步才接 `AsyncDecisionHandoff`：真实运动且确有位移时预取一个候选；前段实际成功、租约释放、最新观察重验通过后才接下一段。快回复缓冲，慢回复时原动作按原期限自然结束。
5. Stop 必须路由技能 Cancel 并持续 Update 到停稳或隔离。原 ActorTools 的 cancel_action/action_status 不拥有该技能 run，不能代替真实技能终态。
6. 验收先沿用已有 overlap/cancel/deadline 短场景，再在真实制作目标下比较直接 MoveTo 与局部技能的有效位移/失败次数/决策等待；不因换更强模型就宣称导航能力已补齐。

本批已测的是控制器与原生工具组合，不是新的连续导航实现或完整自主生存。
