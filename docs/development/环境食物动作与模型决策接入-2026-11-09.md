# 环境食物动作与模型决策接入

本阶段从 c207d82c 继续，只改 cjh，在 dot 云电脑验证。目标不是把“找南瓜”换成固定“挖木头、造武器、杀猪”脚本，而是完善真实动作与可观察前置条件，方向性决策交给模型。

## 边界

- 单一游戏线程权威；每角色一个 AtomicActions 执行器，不因技能切换重复注册。
- NativeFoodPerception 从同一绑定角色取真实库存、5 米局部方块、16 米原生视锥/遮挡实体和掉落。语义视距不授予远处导航通行证明。动态实体引用留在宿主，不能让模型查询全图。
- FoodSituation 只描述证据、库存版本、能力、材料缺口、风险和可执行性。Search 与进食/采集并列，饱食不是禁止探索储粮的统一程序规则。
- 静态原生配方不是已有材料；发现动物不是已证明安全猎物；原生攻击返回成功不是已命中、已杀死或已收肉。
- 提示仅能选择已注册的执行候选，诊断事实单独说明“未接入”，不是宣称世界没有该资源。最多 16 个可执行候选、8 个诊断，明确遗漏数。字符预算不是 tokenizer 保证。
- 本地 Qwen3.5-4B Q4_K_M 只返回 JSON 候选选择，不生成执行代码。每实例一次请求；推理后取新观察、核对库存版本与候选语义，再调用原生动作。旧观察不会因推理慢而延长有效期。
- 当前模型主链仍注册 EatInventory / GatherPlant / Search。狩猎、掉落主动拾取、生产及烹饪的独立原生夹具通过，不自动等于这些策略已接入模型主链。扩展动态目标时必须以宿主实体身份重新观测，不能仅凭坐标相同匹配动物。

## 原生动作验收安排

1. 真实完整外部 Player：无 AI GameWidget、独立活动区、生理更新。
2. 生产：原生挖拾人工摆放原木/石材、配方转化、制作区材料守恒。
3. 狩猎：人工生成完整猎物，不改血量/速度/攻击力；真实观察、有限接近、原生攻击、死亡/尸体延迟、掉落与拾取分开核验。低血量退出如实算失败，不补血刷过。
4. 烹饪：生产所得熔炉、原生放置/交互/投入燃料与生肉、等待原生燃烧产物、取出及食用。人工生肉掉落实验只验证加工链，不能称完成狩猎。
5. 零视口周期动物刷新：修正视口依赖，但保留适生条件、数量上限和物种 RandomSpawn 设置；野猪不因本修正变为周期随机生成。真实等待游戏周期而非直接调用刷怪函数冒充周期。
6. 4B 主链：原生初始库存食用、人工转角台阶采集正控、自然种子和阻塞场景。记录实际路径/净位移、模型 CPU/RSS/输入输出统计、游戏失败与未完成，不混称自然生存通过。

## 可复现与持久化

源码、纯测试、中文设计与脱敏 JSONL 证据进仓库；隔离世界、依赖二进制、模型权重不提交。实际测量结果见同阶段验收报告，不以本设计清单代替测试完成状态。原有 ImageSharp 依赖漏洞告警另列，关闭恢复时审计不构成修复。
