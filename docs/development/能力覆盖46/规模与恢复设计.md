# 阶段46：规模与恢复设计

仅设计/源码核查，非20～50人实测结论。本批持续并发真实矩阵由中央另行运行。

## 复用成熟生命周期，不增加第二个世界时钟

继续参考 `../MC框架源码对照-2026-11-09.md` 固定版本的 Mineflayer physicsTick、pathfinder增量搜索和Mindcraft action manager：世界帧推进动作，异步模型只选择后续目标，结束/失败/取消统一回执并释放owner。不能照搬每角色40ms搜索预算，也不照搬聊天暂停自主工作的做法。

SC已有 `ActorTaskScheduler.RunPhase` 轮换首角色、`AtomicActions.Cancel/Finish` 清理控制、世界级Observation调度和有界回复队列。复用这些接口；扩人数时分别测物理、寻路、感知、网络调度，不能用总CPU余量代替单线程帧预算。单世界20/50名注册和零AI视口只是配置目标，实际区块增长、内存和公平性必须测。

## 本批持续并发验收

两个独立角色/session/request/runId，在≥1游戏秒内多个同时running样本，分别有真实水平位移；短于1秒就标未达标，不降低速度造结果。用原生菜单允许的较长路线，不绕过参数限制。

输出采样数、跨度、最大采样间隔；样本之间不宣称全覆盖。取消A后观测B保持原run继续推进并最终成功；A自然惯性先记录，settle后才开始≤.03稳定漂移检查。纯契约为 `ParallelEvidence46`，宿主还负责真实receipt来源、水平位移、settle条件和最终双owner idle。

## 长期恢复：已有实现与接线工作

核查 `WorldCognitionScheduler.Checkpoint.cs`：cohort归档保存实验/批次/时间/角色集和任务顺序游标，恢复要求账本与世界匹配；在途发送转unknown，不自动假设未发并重试。`ActorCognition.Checkpoint.cs` 保存profile/目标/记忆/承诺，但清除跨会话Source与OfferReference，避免旧ref重用。这些是可复用代码，不意味着当前ToolAgent矩阵已接入完整恢复。

下一批按四个故障窗口批量测：发送前、发送后结果未知、动作已执行但回执未持久化、保存后进程重启。恢复必须重新观察，恢复新session/epoch，旧活引用失效；对库存/交付动作先核对事实再决定是否重做。不要承诺跨游戏存档与外部模型的“恰好执行一次”事务。

先复用原生安全点快照，持久化计划与终态索引，避免中途序列化活物理动作。长期模式的周期保存和用户退出drain需单独集成。日志采用小摘要+可复查有界证据，密钥/本体/世界存档不推Git；源码、方案、脱敏结果每批提交。
