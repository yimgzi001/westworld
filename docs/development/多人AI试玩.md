# 多人 AI 试玩

在有图形桌面的 Windows 或 Linux 上，从仓库根目录运行。需要 Python 3 和 .NET 10 SDK。若仓库的 `work/dotnet/` 有独立 SDK，脚本优先使用它。

~~~powershell
python tooling/试玩西部世界.py
~~~

启动器从 `WESTWORLD_OPENAI_API_KEY` 读取 OpenAI API 密钥，未配置时才在终端提示隐藏输入。脚本启动独立生存世界，默认创建两名 AI 和一个原生玩家视口。可以用 `--actors 1` 到 `--actors 4` 调整人数，用 `--seed westworld-play` 指定种子。

每个角色用自己的观察、背包、收到的消息和上次动作结果做决定。当前菜单覆盖移动、转身、挖掘、选持物、拾取、食用、离开坐骑、等待、发言和物品交接。每轮选择一个动作，派发前用当前观察复核原参数，按原生回执反馈结果和影响数量。世界和其他角色在等待回复期间照常更新。

发言按游戏的距离和遮挡规则投递。交接需要收件人接受，并以游戏实际转移的数量结算。角色的收件箱只保留本人收到的少量近期事件，过期的交接请求会从菜单移除。

相对移动用于眼前的短程探索，最多走三格，方向在身体朝向左右各 60 度内。前往侧后方时，角色可以先转身重新观察。移动回执记录实际水平位移，超时后的部分进展也会进入下一轮决策。收件箱会优先保留仍有效的交接。

使用官方 Responses API，模型固定为 `gpt-6.1-terra`，`reasoning.effort` 固定为 `none`。全场最多同时两路请求，默认总计 12 次，可用 `--requests` 调低。达到请求上限后，已开始的动作照常收尾。关窗口或在终端按 Ctrl+C 会请求游戏停止并取消在途决策。

每次启动在 `work/play-*` 下创建新目录。角色和动作摘要在 `play.jsonl`，模型用量在 `terra-usage.jsonl`，世界存档在本场的 `doc/`。Windows 试玩预设关闭系统文件关联。驱动通过匿名管道向 HTTP 工作进程传递密钥。

## 本地短测

~~~powershell
python tooling/试玩西部世界.py --smoke
~~~

短测会创建平地世界，通过同一个多人调度和原生动作入口跑固定响应。每个角色须完成至少两轮决策并产生实际移动，受阻时先转身再走。多人场会模拟第一名角色的首次模型回复超时。在它等回复期间，第二名须完成移动并发言。第一名超时后继续参与，并从自己的原生收件箱读到该发言。游戏退出后，在 `play_result` 核对游戏更新、动作和模型队列清理。

Windows 下的单人、双人和四人短测均通过。另用原生动作核对了拾取测试物品、交接、食用，以及拒绝重复或过期的接受请求。请求预算不足的短测会等已经开始的动作结束，然后报出 `smoke_budget_exhausted`。

## 真实模型联测 2026-11-10

两场都使用 `westworld-play` 自然种子、两个角色、官方 Terra 和关闭思考，每场 8 次请求。16 次均收到有效回复，记录用量共 58,294 token，思考 token 为 0。

- 首测中，两名角色分别食用了一份原有补给。AI 1 发言，AI 2 的原生收件箱收到消息。8 个动作中 6 个成功，4 次移动里 2 次超时。两次超时前角色均已移动了一段。
- 收紧相对移动范围并补充位移反馈后，复测 8 个动作全部成功。两名角色均转身观察，唯一一次移动成功走了 2.75 格。AI 2 发出资源询问，AI 1 读到消息后发言回应。移动样本只有一次，跨地形稳定性仍需验证。

两场游戏更新异常均为 0，退出时动作与模型队列均已清理。真实模型场目前验证了开局进食、转身、移动和交流。拾取、交接和交接拒绝的结果由固定响应的原生回归单独核对。

## 普通生存长测

~~~powershell
python tooling/试玩西部世界.py --survival --seed natural34-b
~~~

默认生存新场隐藏桌面窗口并保留原生图形上下文。加上 `--watch` 打开可见窗口和只读第三人称跟拍，F8 切换跟拍画面，状态栏显示生命、饱食和精力。详细迭代见[单人普通生存开发记录](单人普通生存开发记录.md)。

长测默认只有一名 AI。本批按用户要求只做单人测试，不启动三人场；程序仍保留多人参数。采用原生「生存」难度和自然地形，启用昼夜、天气、物理、饥饿、睡眠和伤害。场内没有观察者角色，角色就绪后清除开局食物。官方 Terra 决策持续到游戏退出，默认不限总请求次数和模型驱动时长。显式添加 `--requests` 可以执行短测。缺少可执行目标时，本地等待五游戏秒后重新检查。新场声音与音乐均为零，原生声音事件仍可进入 AI 的局部听觉。

普通生存每轮从 `goalOptions` 选择一至四步，通过 `pursue_survival_goal` 依次提交编号。编号绑定本次实际食物、猎物、营地、工作站或路线，模型决定长期意图、先后与取舍。后续步骤可依赖前面的材料，前提失败则停止剩余步骤并把实际原因交回模型。转身、投矛、跳一格、挖掘和核对实际入包由连续技能完成。普通探索不会自行改为狩猎；只有模型选择 `hunt_route` 才在途中接触可食用鸟后攻击和拾肉。

日常补粮、提前储备、建家与发展不由固定生存脚本安排。只有临近饿死时的已有食物进食、已接触火焰撤离和明确的新危险交接由安全处理接手。模型会收到 [生存策略知识](生存策略知识.md) 对应的情境建议，以及原生库存、进食限制、体温、着火状态与上次结果。采石、木矛、石斧、熔炉、烤肉、南瓜留种播种、简易土屋和返回旧工作站都是可选技能；存在这些技能不代表它们已在自然世界形成稳定循环。

每 20 游戏秒记录生存指标，满两天记录一次检查。满十天时，每名角色保持存活、至少两次实际吃到与原生拾取或原生炉具出料账本相符的食物，并有主动原生睡眠，即记录时间门槛通过。游戏仍继续运行。供食是否稳定还要另看连续收支和重复场次，不能用一次十天结果替代。每个角色死亡时记录原生死因、时间和生理状态，全部死亡后结算这场长测。

每个新场在忽略目录保存 `实验版本.json`，记录本次源码、驱动和构建文件的 SHA256。修改代码后使用新版本复测；既有世界继续运行自身冻结的构建。

### 三人短测记录

两轮完成的 Terra 短测使用同一个自然种子 `natural34-b`，各 12 次有效回复，合计 89,962 token，思考 token 为 0。原始采集轮挖掉一处海胆，无入包或进食。新技能轮 AI 2 的海胆库存实际增加 1，随后由模型选择进食，原生拾取账本、食用事件和统计增量均匹配，饱食比食用前增加约 0.05。AI 1 和 AI 3 尚未完成进食。两场均无游戏更新异常，因请求额度用尽而收尾。

另用本地固定响应探测 `natural34-b`、`westworld-play`、`natural34-a`。其中 `natural34-b` 有原生拾取和进食记录。新版技能的独立离线短测覆盖了先拾取失败、走近后库存增加的路径。两种短测都保留了三人长时验收的未通过结果。
