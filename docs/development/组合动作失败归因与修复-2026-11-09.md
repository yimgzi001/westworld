## 不把所有失败归咎模型

受控制作 free04 在 576.41 秒终止，健康约 0.20，Food 约0.40，零游戏更新异常。8次模型回包，查过正确的木棒配方，挖下原生橡木，未拿到木棒。末次观察温度4.421、湿度0.797、睡眠0.156，但旧版缺少伤害原因审计，不能确定健康损失是哪种因素造成。9次发起中的最后一次被停机取消，旧审计不含该次完整资源数据，已知 token 合计只能作下界。

实际问题分层：

1. **模型规划**：已看见两块木板、一根木棍的材料与工作台要求，却多次直接调用 Craft，未建立有效中间生产链。这不是程序应偷偷补成品的理由。
2. **接口表达**：PickUp 可以输出只有 count 的 JSON 并通过旧 schema，但原生拒绝；Move/Face 也有参数分支漏约束。合法 JSON 不等于有效命令。
3. **语义缺失**：压缩时删除参数 description，使 Transfer 的 destination_value（目标槽当前值，空槽0）不明确；Craft 本身不自动填格、不负责炉内烹饪，旧短说明不足。
4. **反馈粒度**：Craft 原生返回 targetChanged 不能擅自改报“材料不足”。日志保留原码，同时提供可直接观察到的自己的库存/合成预览，帮助模型诊断。
5. **现实时间**：几十秒推理期间世界和生理继续变化。当前模型还没有同角色行动中提前规划；不暂停世界或假装持续工作来掩盖。

## 下一版修复准备，仍由模型决定方向

以下修复已通过统一8套324项纯契约测试、原生项目构建（19条警告、0错误），free05新隔离目录已启动复测；结果仍待验收，不是本页free04已运行能力。

- 真正的封闭 oneOf 参数分支，同时约束生成 schema 和独立解析器，拒绝互斥参数双传/漏传。
- 保留准确的工具前置、目标槽当前值与已有材料条件，不提供固定木棒/烹饪动作序列。
- 只给实际持有物品的原生 name/craftingId/nutrition；自己的合成格提供真实预览。外部设施仍需当前真实可见引用。
- 连续攻击前按本角色原生 HitInterval/lastHitTime 做至多4游戏秒本地等待；Ready 后重新验证目标再调用原生。mod仍可拒绝，不改冷却、不强迫攻击、不自动换目标。
- 低健康与意外视口分开停止原因；伤害源只写宿主审计，不向模型透露不可见实体。
- 失败/取消也记录进程墙钟、已采CPU/RSS与已知退出码。未读完 stderr 时 token 保持未知，绝不估成0。

所有版本采用独立运行目录与构建哈希。不能用下一版源码解释上一版运行已具备的能力。

## 验收安排

free04 制作/烹饪/狩猎作为原基线证据，完整记录实际尝试、成功副作用、失败与终止。修复后用新构建复测同类受控场景；先确认工具参数与前置反馈改善，不能因为更严格 schema 拦掉错误就算目标完成。

拾取有原生自动吸入机制。库存增加证明实际拿到物品，不自动证明模型显式调用过 PickUp 或 SelectItem。狩猎结果须结合伤害归因、原生尸体延迟、目标所有的掉落与数量守恒；动作覆盖另看回执。

自然采集/狩猎/烹饪完整生存仍未通过。模型自由工具正控暂时只有初始食物的实际食用，不能把人工牛、预置木棒、炉或肉算自然资源发现。
