## 1. 感知：查询丰富，但已加载不等于眼睛看见

[M src/agent/library/world.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/library/world.js)：

- `getNearestBlocksWhere` 直接 `bot.findBlocks` 后 `blockAt`；`getNearbyEntities` 从 `bot.entities` 按距离排序。这里没有 FOV 或遮挡检查。
- `getBlockAtPosition` 将 null 替换为 `{name:'air'}`。这对我们严格区分未知与已知空气不适用。
- `getInventoryCounts` 从实际槽累加；`getCraftableItems` 调用原生配方查询而非凭模型声明物资存在，可参考这种事实来源分层。

[F lib/plugins/blocks.js](https://github.com/PrismarineJS/mineflayer/blob/5a252e6d258882b042e60e21c37d552cdf3b3380/lib/plugins/blocks.js#L156)：

- `findBlocks` 遍历已加载 column/section，按半径匹配排序，最后截到 count；不是按角色当前视线发现。
- `blockAt` 明确 null 表示 chunk 未加载。
- `canSeeBlock` 独立做头部到目标的 raycast。这说明“附近查询”与“可见性”本来就是不同能力，不能直接把附近查询结果当视觉事实。

**对照 cjh**：`ActorQueries`、`NativeFoodPerception`、局部观察 window 和 `ActorWorldMemory` 已区分真实观察、历史位置与未知。早期 ToolAgent 只有单射线 focus；阶段23已验证一次观察返回有界可见方块、生物、掉落物与汇总，保留遮挡/未知判断。不会导入 MC 半径全块查询而默许穿墙感知。参考项：返回实际库存计数、查询分页/遗漏、可见性独立校验。待验收：同距离遮挡块不可作为资源动作目标，转头后新发现，历史只可导航。

## 2. 记忆：命名地点、对话摘要与事实记忆分开

[M src/agent/memory_bank.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/memory_bank.js)：`MemoryBank.rememberPlace(name,x,y,z)`、`recallPlace`、`getJson/loadJson` 是简单名字到坐标映射；该类没有时间、证据、失效或所有权验证。

[M src/agent/history.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/history.js)：`History.add` 超过 `max_messages` 时分块摘要；`summarizeMemories` 调模型后将记忆限制到 500 字符；`appendFullHistory` 保留被移出的原对话；`save/load` 持久化摘要、近期 turns、自主提示状态等。

**可借鉴**：短工作上下文、可回查原始日志、命名位置是不同存储，不必每轮重发全部历史。**不照搬**：500 字符截断不能取代结构化库存/配方/动作收据；模型摘要不能创造实时资源。

**对照 cjh**：`ToolContextMemory` 无损去重、`ToolResultProjection` 有界投影、`read_map` 分页与 lastSeen 是已有地基。命名地点可以成为显式工具扩展，但仍要带 actor/session/source/time；同一个地方不意味着旧树仍存在。当前仅具空间历史和有限工具事实，不宜称完整人格/人生记忆已完成。

## 3. 寻路与自然动作：目标由上层选，连续执行由本地驱动

[M src/agent/library/skills.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/library/skills.js#L1070)：`goToGoal` 选择 movements、调用 `pathfinder.goto`，并在成功或异常时清理门检查 timer。`craftRecipe`、`smeltItem`、`collectBlock`、`attackEntity` 等是技能级入口，不要求模型每个物理 tick 发动作。

注意：`goToGoal` 找不到低破坏路线时会尝试 destructive movements。不能为“成熟框架同款”直接让我们的纯导航挖方块/搭桥，这会改变动作授权与物资结算语义。

[P index.js](https://github.com/PrismarineJS/mineflayer-pathfinder/blob/b07a419a4181d242bc4b9f8648a4f624e587c18f/index.js)：`getPathFromTo` 是可增量 `yield` 的 A* 搜索，区分 partial；默认 tickTimeout 40ms。`setGoal/resetPath/stop` 管理目标、挖掘/放置中断与控制释放；`monitorMovement` 由 physicsTick 驱动。

[P lib/human.js](https://github.com/PrismarineJS/mineflayer-pathfinder/blob/b07a419a4181d242bc4b9f8648a4f624e587c18f/lib/human.js)：`planRoute` 逐片搜索并用 `setImmediate` 让出事件循环；`straightWalkable` 每 0.25m、横向三点检查地面及头脚空间，未知块不当可走；`walkTo/tickWalk` 本地持续推进，`lookAt/settled` 控制朝向与稳定判定。

特别值得复用的失败语义：该 P commit 修复 physicsTick 停止时等待头部稳定永久挂起；增加 wall cap，但 cap 到达**返回失败**而非假装已面向目标。对应 cjh 的 Settling、单调 deadline、取消 drain/quarantine 应继续保留。

**对照 cjh**：`LocalNavigationSkill`、`BoundedLocalNavigation`、`ObservedStepRoutes`、`LocalNavigationAlignment` 已处理局部连续动作；可以学习增量搜索、路径平滑与明确 partial/arrived，但不能直接搬 MC 方块碰撞尺寸、跳跃速度或路径破坏规则。50 个角色也不能各自无条件占用 40ms 搜索，要设世界共享的每帧搜索预算。

## 4. 异步：Promise 不等于同角色前瞻规划已证明

[F lib/plugins/physics.js](https://github.com/PrismarineJS/mineflayer/blob/5a252e6d258882b042e60e21c37d552cdf3b3380/lib/plugins/physics.js)：`tickPhysics` 推进物理并发出 physicsTick，`look/lookAt` 和等待 tick 独立于 LLM。可参考“动作与决策时钟分开”，SC 仍以游戏线程为唯一权威，不能新增第二个物理时钟。

[M src/agent/action_manager.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/action_manager.js)：`runAction/_executeAction` 管理一个正在执行的函数、超时、输出与 idle 事件；`stop` 反复请求 interrupt，10 秒仍不止则 cleanKill；`getBotOutputSummary` 明示截断。`_startTimeout` 参数单位是分钟，不要误抄为秒。

[M src/agent/self_prompter.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/self_prompter.js)：`startLoop` await `handleMessage`、冷却并计数连续无命令；`pause` 会停止动作。这里不能据 async 关键字宣称已具备我们要求的“同角色移动中预取、绑定前序收据、到达后重验”。

**对照 cjh**：`AsyncDecisionHandoff`、`ToolAgentScenario.Prefetch`、`PlanningPhaseContext` 提供显式前序/session/actor/epoch/revision/observation/deadline 约束。成熟框架值得借的是技能生命周期与事件驱动，而不是删除现有身份/期限校验。生成代码能力也不是搬运这些生命周期的前置条件。

## 5. 多智能体：有通信，不等于有组织交付

[M src/agent/conversation.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/conversation.js)：

- `ConversationManager.startConversation/receiveFromBot` 管理当前对话，收到另一方对话时可拒绝并结束；开始对话会暂停自主提示。
- `_scheduleProcessInMessage` 按双方忙闲调度：200ms 快延迟、5000ms 长延迟；队列合并后处理。部分忙状态另调模型判断是否响应。
- `_startMonitor` 等回应超时可生成系统催促，等待窗口翻倍；断线有结束流程。
- `sendToBot` 经 mindserver 传消息，`chat_bot_messages` 控制公开回显。公开回显与所有角色共享认知不是同一件事。

**可借鉴**：收件箱合并、忙闲感知、明确会话生命周期、断线终止、把消息处理与物理动作解耦。

**不照搬**：聊天暂停自主任务或每条消息额外推理，在 10~50 人下会放大空转与 token。以上文件不能证明有统一任务账、库存交付验收、队长制或多角色事务。

**对照 cjh 目标**：群体任务需可选的任务 ID/owner/依赖/交付证据，人物性格影响模型选择，不写死领导结构或食物路线。先提供消息来源、目标状态、完成/阻塞事件合并，再测实际工作量与通信 token，不以聊天条数作为协作成功。

## 下一批优先顺序（建议，未实现）

1. 感知与历史统一：主动扫视得到真实新证据，read_map 只负责回访导航；单角色遮挡/遗忘/回访场景。
2. 继续复用现有导航底座，增加有预算的局部路线拓展与真实失败回执；模型选目标，不固定“木棒→猎猪→烤肉”。
3. 以技能成功/失败/库存差驱动重规划，保留同角色预取的原身份、原前序与期限；停止物理 tick、迟到回复、目标消失做回归。
4. 双角色先验证一个真实交付任务，再引入人格、队长或社会结构策略；度量消息合并率、每项交付 token、无进展时间。

本报告只建立可持续的固定 commit 源码对照。下一次升级参考版本时应记录 commit 差异及新增验证，不能把这份只读研究写成“已接入 Mindcraft”。

## 阶段29落地对照（原生夹具验证，非模型自然生存）

复用现有 AsyncDecisionHandoff，把原生 MoveTo 与 host_navigate_local 统一为带 session/actor/receipt/runId 的前序执行。对应上述成熟框架的物理 tick 连续执行与目标级完成事件，不另建第二套模型调度器。早回缓冲、迟回不延长走路、取消/替换拒绝旧候选，实际停止后再观察和验证后继。

真实第二场已发现菜单准入仍只认旧 host 导航：MoveTo 成功不代表异步通过。已修复共享菜单并给同 run 的设置尝试去重，最终五场原生生命周期矩阵和旧 host 导航回归通过。保留首次菜单失败和v3失败/未知；所有场景使用固定文件驱动，不称大模型自主。
