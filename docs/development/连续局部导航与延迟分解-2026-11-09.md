# 连续局部导航与延迟分解

日期：2026-11-09。状态：**下一批设计，未实现本设计中的优化，未完成对应原生验收。**

延续实时单世界、完整生存角色、零 AI 视口与真实感知目标。不改变角色的模型目标，不预定觅食顺序，不为了覆盖推理时间硬编码更远距离或无意义动作。仅 dot 云电脑、隔离世界。

## 1. 证据与问题分离

只读核对 `work/tool-prefetch13-terra/tool-agent.jsonl`：首导航 3 段耗时 5.940 秒、路径 2.785m、终点剩余 0.215m；预取比导航开始晚约 0.860 秒。请求到宿主收到回复约 7.723 秒（模型侧约 7.59 秒）。首导航终态到下一次派发约 2.654 秒。推理在途且原生 Moving 的采样累计 1.291 秒、实际路径 2.114m。

以上不是延迟保证。Moving 区间不等于每一瞬都具有非零速度，必须与实际身体采样一起解释；路径包括物理漂移，不是指令长度。日志缺少每次查询独立耗时，不能把未行走时间全归咎于感知查询或 CPU。

两类问题必须分开：

1. **机械停顿**：每米边界、补看、对齐存在重复停稳与启动。
2. **真实决策等待**：旧目标已完成而模型仍未回包，此时等待是正确状态。

把角色走路加速，会更早完成旧目标，甚至增加终点等待；不能因此承诺无停顿。总任务耗时、移动自然性、终点等待是不同指标。

## 2. 当前定位

- `LocalNavigationSkill.Start` 每段进入 `initial_stable_dwell_required`；`Update/StopAndSettle` 每次 Move、Face、Align 成功或失败均重建停稳检测。
- `BoundedLocalNavigation.Begin/Update` 每个局部段释放再取得租约，并重复入口 dwell。前段已经连续稳定，下一段仍重复证明同一状态。
- `LocalNavigationSkill.Start/Prepare` 每段重置 `NavigationLookPlan` 和 `alignedCell`。Terra13 第三段在 Moving 前出现多次返回 Observing；需要分类记录具体补看/对齐原因，不能直接删掉。
- `Program.Update` 的终态轮询约 0.25 秒。该次首终态多出约 0.016 秒，第二段约 0.12 秒，不是 2.65 秒的主要来源。
- `CanPrefetchNavigation` 要求 Moving 且净位移至少 0.15m，带来启动延后。该门槛适合证明实验发生过位移，不必永久作为所有预取的启动政策。

## 3. 本批实现边界

### 3.1 先做连续平地，不直接重写全局导航

保持同一模型命令的目标、1–4m 距离和既有总预算。尝试在同一 lease、观察记忆和补看预算内衔接已授权平地 waypoint，不逐米重新开一个完整技能生命周期。

必须通过真实原生控制证明连续性，不是把 `Settling` 字段改名：下一段需实际已观察的支撑/头脚空间、有效包络和新鲜度。未知格仍不授权移动；动态碰撞、观察失效立即中止。若原生 `MoveTo` 的 cleanup 会清输入，应显式设计同 owner 的连续 waypoint run 或安全续接接口，不能同时创建两套控制器。

只在**平地、同目标、同 owner、已验证下一段**的内部边界研究免重复 dwell。首次进入、最终退出、取消、阻挡、危险、失视/证据过期、跨阶落地和所有权变化仍需真实停止/稳定证明。不能通过单帧低速替代连续 dwell，也不能绕过 quarantine。

### 3.2 提前准备候选，但不预知未来

可比较“前序已被原生接受且局部路线验证完成”即预取，与现行位移 0.15m 后预取。实际移动仍由采样证明，零移动的提前请求不算移动中推理成功。

保留唯一在途请求、原始 session/actor/epoch/revision/观察/前序收据身份。未来菜单仅用于规划；候选须待前序真实成功与安全交接边界，再用实际新观察、库存及菜单验证。原生取消/失败、截止、身份失配使候选退休；不得重绑目标引用、修改候选身份或延长旧动作兜底。

### 3.3 目标与每米调度分层

本批保持固定 3m 对照，不靠延长目标获得好看的异步覆盖。后续才讨论模型显式选择“到已见目标”“在有界范围搜索直到发现/预算终止”等技能目标。本地执行只能在该明确语义授权内连续推进，不能为等待模型私自增加路程或转而狩猎。

## 5. 一批完整验收

先纯测身份/所有权、包络、deadline、取消及连续状态，再开展以下原生矩阵：

1. **首准入：固定人工平地 3m**。同一出生姿态、种子、目标、预算，比对旧版与新版；证明不是绕远、多走或放宽目标。模型回复先用确定性 file driver。
2. **固定 1/3/8 秒回复**：分别覆盖早回、接近边界、晚于原目标结束。每档至少重复 3 次，不根据首个成功删失败。8秒晚回复允许终点等待，必须准确报告。
3. **Terra 实际模型对照**：仅在已有授权与预算内，同场景、同目标与菜单语义记录实际请求/回包/token，明确它不同于固定延迟控制；模型不选相同任务时不硬改回复，而记录不可直接配对。
4. **跨阶负控**：上/下台阶必须保留落地确认，不能借平地快路绕过。
5. **阻挡/遮挡负控**：途中新增障碍或下一段未知时及时停，未观察区不作为空气；失败后新观察重规划，不盲重放。
6. **取消/截止/迟到回包负控**：运行中取消，验证实际输入释放、速度下降、停稳、无新派发；旧候选不能复活。另测暂停物理 tick 的墙钟截止与 quarantine。

判通过需同时满足目标/权限/资源约束和真实执行证据；“更快”不能抵消安全回归。人工平地通过不等于任意地形、自然觅食或 50 AI 已完成。

## 6. 指标与判定

记录同一单调时钟的请求开始、实际发布、回包观察、候选接纳、每次派发、原生终态和实际停止时刻；跨进程 UTC 仅辅助，不替代宿主单调时钟。

每帧采集身体位置、速度、接地、动作/技能状态、owner/request ID；输出累计路径与净位移、速度低于阈值的区间、内部 waypoint 停顿次数、最终目标等待时间。阶段耗时拆分：原生移动、主动补看、对齐、dwell、查询与投影 CPU、线程调度/轮询、模型与文件协议。分别统计 token 输入/缓存/输出、调用次数和总墙钟。

验收期望：平地内部机械停车减少、无权限/失败语义退化；量化而不预设提升百分比。总墙钟可能受模型尾延迟主导，允许正确停下等候，**不保证无等待**。

## 7. 成熟框架对照与不照搬项

详细固定源码审查见 [MC框架源码对照](MC框架源码对照-2026-11-09.md)。本设计仅复用分层思路，尚未复制或运行这些项目：

- [Mindcraft skills.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/library/skills.js)：模型选择技能目标，`goToGoal` 等由本地持续执行。不直接采用 destructive movements。
- [mineflayer-pathfinder index.js](https://github.com/PrismarineJS/mineflayer-pathfinder/blob/b07a419a4181d242bc4b9f8648a4f624e587c18f/index.js)：物理 tick 推进、目标/路径/取消分层。不能照搬 MC 碰撞尺寸、跳跃速度或每角色40ms搜索预算。
- [mineflayer-pathfinder human.js](https://github.com/PrismarineJS/mineflayer-pathfinder/blob/b07a419a4181d242bc4b9f8648a4f624e587c18f/lib/human.js)：增量搜索、连续走路和真实失败的 wall cap。未知格不等于空气。

SC 原生 `ComponentPathfinding/ComponentPilot` 可作为底层候选，但其世界查询可能越过角色认知；必须限制在已观察授权走廊，不能以“复用成熟寻路”引入全知。人格、协作和未来种群模拟接口不在本批修改范围。
