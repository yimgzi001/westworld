# 原生狩猎与武器能力审计

日期：2026-11-09。范围：cjh 当前 Survivalcraft 原生源码及已整合 Westworld 接口的只读审计。本文不是狩猎成功报告，没有运行新的动物、武器或烹饪实测。

## 定位

食物策略不应只认成熟南瓜。应依据角色当前真实可见环境、库存、饥饿和风险，在可拾取食物、植物采集、准备武器与狩猎之间选择。原生支持很多构件，不代表模型已经能完成整个闭环。

建议最小狩猎验收链：局部观察猎物 → 准备木棒 → 有界接近与攻击 → 等待原生尸体掉落 → 实际拾取生肉 → 原生熔炉烹饪 → 食用。资源或猎物不足应返回探索/受阻，不注入库存或扫描全世界动物。

## 1. 真实可见动物

`game/Survivalcraft/Westworld/Knowledge/ActorQueries.cs`：

- `FindVisibleObjects(out Entity[] visibleEntities, float maxDistance = 8f, int limit = 24)`。
- 原生 `SubsystemBodies.FindBodiesAroundPoint` 仅作为局部粗筛，随后按眼睛距离、约 120°视锥、遮挡与数量限制过滤。
- 结果 `NearbyEntityView` 包含实体 ID、显示名、位置和距离；通过上层 `observe` 获得可用引用。
- `GameKnowledge.FindCreatures` 是物种资料，不是世界内动物实时位置，不能混用。

追击必须重新观察移动目标，不能拿到 Entity 引用后无限读取视野外的最新坐标。可保留最后见到的位置及时间，但必须标为记忆而非实时感知。

## 2. 攻击与接近能力

`game/Survivalcraft/Westworld/Actions/AtomicAction.cs` 定义 `MeleeAttack(Entity Target)`。

`Actions/AtomicActions.World.cs::StartMelee`：

1. 拒绝已有 pending 矿工动作。
2. 用 `FindWorldRay(..., RaycastMode.Interaction, 2f, ...)` 找到真实首个命中目标。
3. 检查当前持有物的等级与命中概率。
4. 调用原生 `ComponentMiner.Hit`，必要时执行原生 pending attack。
5. 返回单次攻击结果。`Succeeded` 不等于击杀，`affectedCount` 可为 0。

已有 `MoveTo`、`FaceTowards`、`SelectItem` 可以复用，但尚没有在本轮证明可稳定完成动态追击的高层技能。不要把每一帧都让模型发命令作为实现方式。应由本地有界技能持续更新接近、朝向和攻击节奏，模型选择目标及策略。

## 3. 配方与武器选择

配方来源：`game/Survivalcraft/Content/Assets/CraftingRecipes.xml`。以下为源码静态配方，不代表当前库存已有这些材料。

| 产物 | 实际材料与排列 | 热度/玩家等级 |
|---|---|---|
| 木板 ×4 | 木头 ×1 | 热度 0 |
| Stick ×4 | 木板 ×2，竖排 | 热度 0 |
| 工作台 ×1 | 木板 ×4，2×2 | 热度 0 |
| WoodenClub 木棒武器 ×1 | 木板、木板、Stick，三格竖排 | 热度 0，无显式额外玩家等级要求 |
| WoodenSpear 木矛 ×1 | 三行 `" b" / "bab" / " a"`，a=Stick，b=木板，即 Stick ×2、木板 ×3 | 热度 0，无显式额外玩家等级要求 |
| StoneClub 石棒 ×1 | 圆石或石块碎片 ×2、Stick ×1，三格竖排 | 热度 0 |
| StoneSpear 石矛 ×1 | 与木矛形状相同，b=圆石或石块碎片 | 热度 0 |
| 熔炉 ×1 | 圆石 ×8，3×3 空心 | 热度 0 |
| 熟肉 ×1 | 生肉 ×1 | 热度 1 |

木棒和木矛均需要三行配方空间，应先准备真实工作台，不假设随身格能装下。

工具数据来源：`Content/Assets/BlocksData.txt`：

| 武器 | ToolLevel | 默认近战威力 | 默认命中概率 | 耐久 |
|---|---:|---:|---:|---:|
| 木棒 | 1 | 3 | 0.7 | 30 |
| 木矛 | 1 | 2 | 0.7 | 20 |
| 石矛 | 2 | 2.5 | 0.7 | 40 |

这些是基础配置，不是每击实际伤害保证。铜武器配方明确要求玩家等级 2，铁武器等级 3，不能拿更高级工具绕过角色进度。

首个近战闭环优先木棒：材料少，基础近战威力高于木矛，避免同时引入投掷回收与弹道误差。

## 4. 制作接口能复用到哪里

`Westworld/Upper/ActorTools.Catalog.cs` 提供 `find_recipes`、`plan_craft`、`act_Craft`、物品转移及选择接口。

- `ActorTools.PlanCraft` 解析实际工作空间和配方引用，再交给 `RecipeTaskComposer` 编排。
- `RecipeTaskComposer.Compose` 拒绝热度大于 0 的配方。
- `AtomicActions.Inventory.cs::CraftAtTable` 调用真实工作台配方和玩家等级检查，并实际取出产物。

因此常温武器制作应复用这条路径；不能把 `plan_craft` 当作直接生成熟肉的接口。每步需核对材料减少、产物增加及真实槽位。

## 5. 野猪死亡、掉落与风险

来源：`Content/Assets/Database.xml` 的 `Wildboar` 模板：

- 普通掉落：`RawMeatBlock;1;2`。
- 着火掉落：`CookedMeatBlock;1;2`，但这不是推荐绕过烹饪的捷径。
- `AttackResilience=30`、`WalkSpeed=3.5`。
- 有逃跑和追击行为；同群 `AutoNearbyCreaturesHelp=True`。主动追击掩码配置为 0 不等于不会反击。

`game/Survivalcraft/Component/ComponentLoot.cs::Update`：

- 必须有 `DeathTime`，并且原生总游戏时间已到 `DeathTime + CorpseDuration`，才首次生成掉落。
- 按原生概率和数量生成拾取物，调用 `SubsystemPickables.AddPickable`，附带来源实体。
- 因而“目标死亡”“出现肉”“肉入包”是三个不同事件。不能攻击结束就立刻在库存补肉，也不能把未掉落误认为失败后再次生成。

应限制追击时间、离营距离、血量、体力和失去视野后的恢复策略。其他动物和玩家经过时，原生首个命中也可能变化，必须重新检查目标而非穿透攻击。

## 6. 熔炉与食用

`game/Survivalcraft/Component/ComponentFurnace.cs`：

- `FuelSlotIndex = SlotsCount - 3`，`ResultSlotIndex = SlotsCount - 2`，`RemainsSlotIndex = SlotsCount - 1`。
- 燃料通过 `GetFuelHeatLevel`、`GetFuelFireDuration` 参与原生消耗。
- `FindSmeltingRecipe`、`UpdateSmeltingRecipe` 与原生更新推进烹饪；可观察 `HeatLevel`、`SmeltingProgress`。

最小路径是制作/放置或实际发现熔炉，使用允许的真实库存转移填肉与燃料，等待原生输出，再取出并食用。当前没有证据表明整条熔炉操作已在本轮无视口角色上通过，应先验证存储引用解析、距离与库存转移，再做长链。

静态物品数据：生肉默认营养 .3、生病概率 .25；熟肉默认营养 .8。实际饱食变化会受原生机制影响，不能仅按静态数值断言成功。

## 7. 最小验收与明确边界

完整记录同一任务的资源观察、材料采集、物品入包、配方消耗、武器产出、持有槽、攻击结果、目标死亡、掉落出现、生肉入包、熔炉输入/输出、最终食用数量与饱食变化。库存净增不能独立证明来自某个尸体；多人情况下还需来源关联。

测试分两层：

1. 明示人工场景验证接口与失败恢复，所有预置内容记录为 fixture，不宣传自然生存。
2. 不插资源/动物、不全图查询、不注入库存的自然场景验证完整路线。无材料、未发现猎物、目标逃逸、被反击和燃料不足均如实保留失败证据。

本审计只证明源码中有这些机制。尚未实测证明：动态追击稳定、木棒制作闭环、野猪击杀后拾取闭环、熔炉烹饪闭环以及模型自主选择整条路线。
