## 第一批建议

1. 一场 `food_drop file` 人工正控：最多4请求/180秒。观察模型能否发现/选择工具、拾取或识别新获得食物并食用。人工掉落和原始库存分开记。
2. 后续可另安排一场 `natural file <新seed>`：当前宿主支持8请求/180秒，尚未stage或执行；模型自主获取一项新增资源。目标简单但真实，不把没找到食物判为所有接口失败。
3. 本次仅授权执行流程内的食用正控，最多4请求；natural后续另批；有鉴权/账单/模型拒绝/未知请求结果时停止后续模型场。无可靠usage记录null，不记0。结束保持原生drain和晚回复拒绝。
4. 初期发现/选择工具本身占模型轮次。若4轮全耗在无效发现，报告具体交互与上下文问题，再批量修复；不静默扩大轮数或替模型下决策。
