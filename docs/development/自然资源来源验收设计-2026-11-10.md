# 自然资源来源验收设计

## 决策

下一完整场景不指定南瓜或牛，不生成食物，不改地形/库存/健康，不把模型策略写成规则树。高层目标为从真实环境获取新资源，优先安全食物；模型选择路线和技能。先证明自然资源获取，再根据真实物品性质验证食用。

目前 `natural` 入口仍明确返回 pending；不能仅删除该门禁，旧的库存增长判断不是有效来源证明。

## 复用与缺口

- 复用 ActorWorldMemory / ActorQueries：角色局部方块、动物、掉落的真实观察，保留视锥、遮挡、距离和 proximity/vision 区别；执行前重新校验引用。
- 复用 NativeAcquisitionAudit：具体掉落物向具体角色的真实库存转移及数量，不用相邻位置和同值猜来源。
- 动物死亡原生 ComponentLoot 已传 OwnerEntity；待绑定模型实际攻击的可见实体与其产生的多个掉落。不得调用会生成牛/木棒/围栏的 HuntingFixture。
- 方块 DestroyCell 当前 AddPickable 无来源标签，需要在原生返回掉落实例处记录原方块坐标、完整值、掉落稳定ID；再关联实际角色挖掘调用。此钩子尚未实现。
- FoodSourceLedger 提供来源守恒范式，但自然世界多来源和部分获取需专门设计，不能直接套人工唯一食物的排他条件。

## 审计边界

宿主记录首次可见观察ID、实际工具请求、资源→原生掉落→角色转移以及可选食用事件。OwnerEntity、未观察实体健康及隐藏来源ID只用于宿主审计，不能流入模型知识。只读查询、接受命令、杀死动物、产生掉落、拾取、食用分别记录，不互相替代。

## 验收分层

1. 正常生成世界和出生，未注入资源的证据明确。
2. 从角色可感知资源选择实际动作。
3. 来源明确的新物品确实进入角色库存：自然获取通过。
4. 可食物经过原生食用，库存与生理值变化吻合：食物链通过。

木材、种子、生肉获得不能冒称完成可安全食用链。完整方块数据决定成熟度及营养，不能仅按内容ID判断南瓜可食。找不到、不可达、受伤退出、未掉落或来源未知都保留，不加资源以制造成功。

当前阶段30仍仅是人工掉落夹具，不代表此设计已实装或验收。
