# 原生局部觅食整体验收

仅在dot云电脑SCAPI1.9.5.1原生游戏中运行。参见[完整目标契约](../../docs/design/局部觅食目标执行契约.md)。

## 复现
使用.NET10构建至新的work子目录，例如：
```sh
dotnet build experiments/scapi-forage-gate/ForageGate.csproj -c Release -m:1 -nodeReuse:false -o work/forage-normal
cd work/forage-normal
dotnet ForageGate.dll --new-disposable-world
```
通过正常有图形支持的云桌面终端运行，不能将受限exec上下文无DISPLAY当作整台机器无桌面。运行器拒绝非work目录、已有doc存档或Mods目录。
取消/目标消失各用独立全新输出目录，附加参数分别为 `cancel`、`disappeared`。不要复用已有运行目录。世界与构建/依赖二进制不提交。

## 失败与修复
第一轮实际采集成功，但采集后区块正在重建、暂非Valid，原移动判断立即失败，未拾取。修正为停步等待Valid且仍受阶段预算约束，随后成功。独立审查又修复子进食票据真正预留、3D观察位移检查、父期限先于子副作用及中断时库存证据更新；以上最终源码重新实测。

## 明确边界
人工夹具只平整地面/放置原生南瓜/清空库存，不给技能凭空发食物。提供器是300ms延迟确定性替身，models=0。不能称真实LLM自主、自然找食、长期生存或复杂寻路。
原生自动拾取与进食确实发生；多人抢物归因、掉落实体证据ID及持久化尚未完成。取消终态只保证撤销输入而非瞬时速度为零。证据JSONL记录实际变化，运行世界不入库。
