# 原生狩猎正控（人工夹具）

本实验复制已验证的 production-gate 生产正控作为起点，不是产品技能实现；没有模型调用。它仅在全新隔离 work 运行目录接受 `fixture` 参数，拒绝已有 doc/Mods，避免覆盖世界。

链条：人工两原木→原生挖掘拾取→木板/工作台/木棍→原生放台制作木棒→选择真实制作的木棒→人工平地围墙内生成一只完整 Wildboar→真实视野限定的接近/转向/原生近战→原生死亡延迟掉肉→实际拾取。

不注入或清空库存；保留角色原生初始物品。不改动物健康/速度/行为/掉落，不直接造成伤害，不生成肉或熟肉。围墙限制逃逸，因此不代表自然追踪。生产阶段会改动明确的夹具地形，猎物阶段另设半径5格、3格高围墙。动物出生朝向和攻击命中依原生随机。

决策坐标仅来自 `FindVisibleObjects(10,24)` 本轮真实可见结果。保存实体标识用于识别本夹具猎物，但不可见时不读取实时位置；最多24次局部转头扫描。一次追近超时1秒，再观察。攻击前重新确认可见和距离；原生近战进一步检查射线/冷却/武器。宿主读取健康、DeathTime、lootDropped 只供验收日志，未作为模型输入。原生肉掉落/拾取与死亡分开记录。记录猎物阶段每更新采样的累计水平路径；人工摆放和生产路径不包含。

界限：最多240秒wall、猎物阶段150秒模拟时间/150米路径、自血量必须>.25；触发即取消并失败，不提高攻击力、不补血、不补物品。固定脚本不是自主策略，不是自然动物发现，不证明可持续生存。多动物环境的掉落来源归因仍需独立验证，不应把此单猎物控制场景直接当产品实现。

构建：`dotnet restore HuntingGate.csproj` 后 `dotnet build -c Release`。复制运行时输出和游戏资源到全新 `work/hunting-native-NN`，在 dot 云桌面正常图形会话执行 `dotnet HuntingGate.dll fixture`。结果在 hunting.jsonl；保存所有成功与失败证据。仅编译通过不得称狩猎通过。

## 本批实测结果（2026-11-09）

- 构建0错误/0警告。
- 01失败17.109秒：复制生产状态机的stage60误落入`stage>=20`狩猎判断，尚未生成猎物；已修为明确20..22，保留失败日志。
- 02完整原生运行29.103秒：成功采集/制作并装备木棒，人工生成完整野猪；实际8次近战尝试，其中7次造成伤害，野猪最后攻击日志健康0.3333109。玩家最后攻击时健康0.4023595，随后跌至<=0.25触发风险退出。已采样猎物阶段路径16.3609米。未击杀，未出现肉，未完成拾取。
- 02的风险退出以异常结束测试，因此UpdateFailureCount=1是测试断言触发，不可声称零异常或通过。已在最终源码额外增加风险退出现场精确健康日志，该纯日志补充重新编译，但尚未第三次原生复跑。
- 这是有价值的失败：无护甲木棒近战野猪具有真实反击风险，后续策略应考虑更低风险猎物/武器与战术，而不是提高伤害或修改动物来伪造成功。

全部过程仅dot云电脑，未动用户电脑，没有模型/API调用。当前证据只证明原生攻击/命中/反击/风险取消，不证明击杀掉落或自然自主狩猎。

## 低风险候选扩展（待原生验证）

程序可接受 `fixture Cow_Brown`，默认仍为 `fixture Wildboar`；限定这两种原生模板，不接受任意外部模板注入。Database.xml 的 Cow_Brown 继承 Cow：RawMeat2..4，AttackResilience35，AttackPower1，ChaseWhenAttackedProbability0.1、ChaseOnTouchProbability0，移动速度4。比野猪低反击倾向不代表不会反击；单动物围栏也排除了自然牛群风险。Duck虽可能较弱，但会飞，掉RawBird而非RawMeat，此批未选择。

03计划将本地轮询从固定.35秒降为.1秒，实际近战仍严格等待原生 `GameTime-m_lastHitTime>HitInterval` 并再走原生 `Hit` 冷却检查，没有更改游戏冷却。新增猎物阶段净水平位移，与累计实际路径并列。

03原生结果：38.301秒失败，但原生牛已击杀，14次攻击尝试/12次造成伤害，角色血量1；猎物阶段路径21.6703米。原生死亡时间31.6014、尸体延迟8秒，局部扫描预算在掉落出现前耗尽，错误地把死后暂不可见当成活目标丢失。保留03原始失败证据。

04修正：必须在目标仍真实可见时确认死亡标志，再进入单独30秒尸体等待阶段，只转向最后已观测的位置，不追踪不可见实体。宿主死亡审计本身不触发该阶段。另添加严格掉落归因验收：夹具开始没有生肉拾取物；每帧捕获原生Pickable对象身份和初始数量，要求OwnerEntity==此猎物；任何无关生肉出现即拒绝归因；只有目标全部掉落已被收取且库存净增等于捕获总数量时成功。全局数量检查只作隔离测试断言，不给策略坐标或资源情报。多源自然世界尚需产品级归因机制。
