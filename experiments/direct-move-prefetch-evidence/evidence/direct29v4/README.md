# 阶段29 v4：五场通过与旧host导航回归

本包五场direct_early、direct_late、direct_failure、direct_cancel、direct_replace均通过冻结独立验证器；旧host导航回归另有宿主通过记录。全部采用云端人工夹具和确定性文件控制器，没有真实模型或自然生存验证。负控通过表示原生失败/取消/身份替换后旧候选未误接管，不是失败动作变成成功。

五场各120份冻结源码相同，旧host回归同样120份并与五场一致。build04的8份宿主源码和安装宿主DLL哈希对应；保存冻结矩阵运行器与恢复工具，不读取当前生产工作树替代。首轮缺assets失败、中间27套1070项、最终27套1084项纯测日志均保留，归档过程不重跑测试。

旧失败目录direct29fail和v3目录direct29v3保持原貌，v4通过不回写历史失败或unknown。旧host分析的接续关联为temporal_only_unbound，不能与direct五场的独立身份绑定验证混为一谈。早回包正控仍约0.271秒终态至后继动作；晚回包约6.086秒，不能宣称消除所有停顿。

日志和配置的云仓库绝对路径替换为<CLOUD_REPO>，冻结源码保持原样；原始与归档SHA256各自记录。内容逐文件寻址、确定性gzip、Base64分片最大29000字节，包索引分组保存。凭据特征扫描无命中；不包含凭据、环境变量、游戏二进制、内容资产、存档或第三方依赖。

`python3 verify.py` 仅离线解码核验，不执行归档源码、游戏或API。`python3 archive.py` 只读检查；`--write` 仅重建本目录。详细结论见 `docs/development/阶段29原生直行预取验收报告-2026-11-09.md`。
