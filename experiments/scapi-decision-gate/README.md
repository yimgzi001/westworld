## 本次闭环
1. 从真实角色观察读到Food约0.549、背包里1条原生初始熟鱼。
2. 发起异步决策，同时原有有限移动技能继续运行。
3. 替身根据观察选择“满足饥饿/EatOne/背包槽1”，而非预填必定进食。
4. 游戏线程重新校验观察与完整物品值，通过原生库存处理链吃1件。

## 架构实现
- DTO移入纯核心ActorContracts，工作线程只能拿快照数据，不传游戏对象。
- IDecisionProvider可替换；AsyncDecisionScheduler以Task.Run隔离同步阻塞提供器，游戏线程轮询结果，不Wait推理。
- 默认最多2个实际在途提供器、每actor1个请求、64个邮箱。超时结果退役；不配合取消的提供器或阻塞取消回调继续占位，不用无限重启绕过容量。
- 数组容器复制，结果必须匹配session/actor/observation。调度器只调度，不执行世界动作；宿主仍校验当前原生状态。
- ApplyDecision白名单目前只有SatisfyHunger/EatOne和Observe/Wait，不接受任意脚本。
- EatOne当前**只支持已观察且完整value/count仍一致的1件原生熟鱼**。不是所有食物或通用库存事务。
- 复用原版拖放进食路径：从源格移1件→ComponentClothing.ProcessSlotItems→必要时归还原生返回物。不会再调用第二次Eat。
- 先记录Executing再进入原生处理；成功必须同时满足库存少1、Food增加、进食统计加1。异常/返回物异常保留Uncertain及实际状态，不盲目恢复物品或重试。
- 食物与移动共用session内动作ID空间、256条有界账本和单actor活动技能约束。票据仍未跨进程持久化。
